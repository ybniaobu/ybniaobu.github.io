默认构造函数 default constructor 指不需要提供任何实参就可以调用的构造函数，包括两种形式：无参构造函数以及全缺省构造函数（所有参数都有默认值），且每个类最多可以有一个默认构造函数。

如果类没有显式地定义任何构造函数，编译器就会为我们隐式地定义一个默认构造函数，又被称为合成的默认构造函数 synthesized default constructor，其效果等同于一个函数体和参数列表都为空的默认构造函数。默认构造函数在以下两种初始化场景中会被自动调用：①默认初始化 default initialization，例如 MyClass obj; 或使用 new MyClass;，此时内置类型成员（如 int、指针等）的值是未定义的，因为内置类型成员本身若默认初始化，编译器不会为它们赋一个初始值，除非作为静态存储的变量时被初始化为 0；②值初始化 value initialization，例如 MyClass obj{}; 或使用 new MyClass();，此时内置类型会被初始化为默认值 0 或 nullptr。但是，数据成员若有类内初始化器，上述两种形式都会为成员初始化为类内初始化器中的默认值。

另外，有时候编译器不能为某些类合成默认的构造函数，比如类中有未初始化的引用类型的成员变量，或者包含一个其他类类型的成员且这个成员的类型没有默认构造函数，亦或者含有未初始化的 const 成员等等。

拷贝、移动构造函数

除了定义类的对象如何初始化之外，类还需要控制拷贝、移动、赋值和销毁对象时发生的行为。一个类通过定义五种特殊的成员函数来控制这些操作，包括：拷贝构造函数 copy constructor、拷贝赋值运算符 copy assignment operator、移动构造函数 move constructor、移动赋值运算符 move assignment operator 和析构函数 destructor。析构函数在下面小节讲解，其他内容在下一章节 - 类的拷贝控制中详细说明。

析构函数

析构函数 destructor 是类的一个特殊成员函数，它在对象的生命周期结束时自动调用，主要用于释放对象占用的资源（如动态内存、文件句柄、网络连接、锁等）。它是资源获取即初始化 RAII 思想的核心支柱，RAII 在智能指针和内存管理的章节介绍。析构函数的名称与类的名称相同，只是前面多了波浪号 ~，例如 ~MyClass()，其无返回类型、无参数、不能被重载，并且每个类只能有一个析构函数。当一个类未定义自己的析构函数时，编译器会为它定义一个合成析构函数 synthesized destructor，合成析构函数的函数体为空。

在一个构造函数中，成员的初始化是在函数体执行之前完成的，且按照它们在类中出现的顺序进行初始化。在一个析构函数中，首先执行函数体，然后销毁成员，成员按初始化顺序的逆序销毁。成员的销毁是隐式的，销毁时发生什么依赖于成员的类型，销毁类类型的成员会执行成员自己的析构函数，而内置类型没有析构函数，直接释放内存，当然指针成员不会自动 delete 指向的堆内存，只会销毁指针自身。

触发场景

当对象被销毁时，析构函数自动执行，常见的销毁的场景包括：
①局部变量在离开其作用域时被销毁；
②对于动态分配的对象，当对指向它的指针应用 delete 运算符时被销毁；
③当对象作为容器元素时，容器整体销毁、显式清空或删除以及容器扩容时被销毁；
④在表达式中生成的临时对象，当创建它的完整表达式结束时被销毁；
⑤具有静态存储期的对象（全局变量、static 局部变量、static 成员变量）在程序正常终止时销毁。

静态成员

静态成员是 C++ 类中一种特殊成员，它不属于某个具体对象，而是属于类本身。所有该类的对象共享同一个静态成员，静态成员包括静态数据成员和静态成员函数。

静态数据成员

静态数据成员使用 static 关键字声明，但不能在类内初始化，必须在类外进行定义（通过范围解析运算符 :: ），除非是 constexpr 或 const，C++ 17 及之后，可以使用 inline 关键字直接在类内部初始化，无需再写类外定义。如果不存在其他的初始化语句，在创建第一个对象时，所有的静态数据都会被初始化为零。

聚合类

合成拷贝构造函数

如果我们没有为一个类定义拷贝构造函数，编译器会为我们定义一个，称为合成拷贝构造函数 synthesized copy constructor。与合成默认构造函数不同，即使定义了其他构造函数，编译器也会合成一个拷贝构造函数。合成拷贝构造函数会将其参数的成员逐个拷贝到正在创建的对象中，对于内置类型（int、指针等）直接复制字节（浅拷贝），对于类类型成员会使用该成员的拷贝构造函数。

合成拷贝构造函数因为浅拷贝的原因，存在一定的缺陷，当类有指针成员管理动态内存时，默认拷贝构造只复制指针值，即地址，导致两个对象指向同一块堆内存，析构时会发生双重释放或悬空指针问题。所以当类需要管理动态分配的内存、文件句柄等资源时，必须自定义拷贝构造函数以实现深拷贝（而非浅拷贝），否则两个对象会共享同一资源，导致重复释放或数据损坏。

Rule of Three / Five

三法则 rule of three 指如果类需要自定义 C++ 98/03 标准支持的拷贝构造函数、拷贝赋值运算符和析构函数中的任何一个函数，那么你几乎肯定需要自定义这三个中的全部。三法则的底层逻辑在于浅拷贝与深拷贝之间的矛盾，假设类管理着一个动态资源，其中析构函数负责释放资源，如果拷贝构造函数使用合成拷贝构造函数，两个对象的指针成员将指向同一块内存，如果拷贝赋值运算符使用合成拷贝赋值运算符，不仅会内存泄漏（未释放旧资源），还会导致两个指针指向同一内存。只要析构需要释放资源，就意味着资源必须独占。独占资源就必须实现拷贝构造来深拷贝复制资源，和拷贝赋值来安全释放旧资源并复制新资源。

五法则 rule of five 之所以变成五，是因为 C++11 引入右值引用和移动语义，带来了移动构造函数和移动赋值运算符，于是法则变为了如果类需要自定义上述五种函数的任何一个，那么你几乎肯定需要自定义所有函数。五法则的底层逻辑在于编译器有一个非常反直觉的规则：只要用户自定义了析构函数、拷贝构造函数或拷贝赋值运算符中的任意一个，编译器就不会隐式生成移动构造函数和移动赋值运算符。这会导致，如果你为了释放资源写了析构函数，编译器会删除移动操作。此时，试图移动该对象将会退化调用昂贵的拷贝构造函数，为了享受移动语义的高效，既然你自定义了拷贝控制，就必须同时显式定义移动控制。

五法则背后 C++ 标准的特殊成员函数自动生成规则有如下：
①析构抑制移动：这是五法则最核心的触发点，写了析构却忘记写移动，对象将失去移动能力；
②移动删除拷贝：如果你只定义了移动构造而没有定义拷贝构造，编译器会删除拷贝构造。这意味着该类变成仅移动类型；
③拷贝不抑制拷贝：定义了拷贝构造，拷贝赋值依然会生成（反之亦然），但会抑制移动。

第十章 类与继承

面向对象编程 OOP

面向对象编程 object-oriented programming (OOP) 是一个围绕在类 class 与对象 object 周围的基本概念，包含四个特征：抽象 abstraction、封装 encapsulation、继承 inheritance 和多态 polymorphism：

①抽象 abstraction：抽象或数据抽象是一种依赖于接口 interface 和实现 implementation 分离的编程技术，只向外界展示外部接口，隐藏具体实现细节。类的接口包括用户所能执行的操作，类的实现则包括类的数据成员、负责接口实现的函数体以及定义类所需的各种私有函数；

②封装 encapsulation：实现了类的接口和实现的分离，封装后的类隐藏了它的实现细节，类的用户只能使用接口而无法访问实现部分。使用私有 private 和受保护 protected 隐藏实现，使用公有 public 供外部访问；

③继承 inheritance：继承可以让一个类（子类 subclass 或派生类 derived class）获得另一个类（基类 base class 或超类 superclass）的属性和方法，实现代码复用，并建立层级关系。

④多态 polymorphism：即一个接口，多种实现，又可以被分为两种：运行时多态 run-time polymorphism 或动态多态 dynamic polymorphism 通过虚函数 virtual function 实现；编译时多态 compile-time polymorphism 或静态多态 static polymorphism 通过函数重载或模板实现。

派生类

继承 inheritance 允许一个类（派生类/子类）获得另一个类（基类/父类/超类）的属性和方法，实现代码复用并建立 is-a 关系，但基类的构造函数、析构函数、拷贝构造函数、移动构造函数、重载运算符和友元函数不会被继承。并且，派生类对象中的数据是基类对象数据的超集，即派生类通常比基类更大，因为包含了更多的数据和函数。

比如，public 继承（最为常用），外部代码可以访问派生类中的基类的 public 成员；派生类的派生类也可以访问基类的 public 和 protected 成员；protected 继承，外部代码无法访问基类的任何成员，派生类的派生类仍然可以访问基类的 public 和 protected 成员；private 继承则让外部代码和派生类的派生类都无法访问基类的成员，因为它们在派生类中变成私有的了。

继承中的类作用域

每个类都有自己的作用域，类的成员位于作用域内，当存在继承关系时，派生类的作用域嵌套在其基类的作用域之内。这意味着编译器在查找一个成员名称时，会从最内层（派生类）向最外层（基类）逐层向上搜索，直到找到第一个匹配项为止。

和其他作用域一样，派生类也能重用定义在其直接基类或间接基类中的成员，此时定义在内层作用域（即派生类）的成员将隐藏 hiding 定义在外层作用域（即基类）的成员，注意是隐藏不是重载！！！由于作用域是嵌套的，无论参数列表是否相同，派生类中的名称都会隐藏基类中同名的名称，而不是像函数重载那样在同一作用域内共存。编译器一旦在派生类作用域找到了名字，就不会再向上查找，即使派生类中的函数参数不匹配，编译器也不会去基类寻找匹配的重载版本，而是直接报错。

静态成员与继承

静态成员属于类本身，而不属于类的对象，在整个继承层级中，它只存在唯一实例。无论基类被派生多少次，无论有多少个派生类对象，基类中定义的静态成员变量在内存中只有一份，所有派生类共享这一份数据。虽然静态成员只有一份，但它的可见性完全受继承方式和访问说明符控制，规则与普通成员完全一致。

另外，静态成员函数不能声明为虚函数 virtual（虚函数见后面小节），因此无法被派生类覆写 override。如果派生类定义了一个同名静态函数，这叫做隐藏 hiding，而不是覆盖。

虚函数与多态

虚函数

基类需将它的两种成员函数区分开来：一种是基类希望其派生类进行覆盖的函数，另一种是基类希望派生类直接继承而不要改变的函数。对于前者，基类通常将其定义为虚函数 virtual，它允许程序在运行时，根据对象的实际类型（而非指针或引用的表面类型）来决定调用哪个函数，这种行为被称为动态绑定 dynamic binding。虚函数是实现运行时多态 run-time polymorphism 的核心机制，允许使用基类指针或引用来调用子类的重写方法，从而使得同一接口可以表现不同的行为。

绑定

之前提到动态绑定 dynamic binding，也称为运行时绑定 runtime binding，那么什么是绑定？绑定 binding 是指将程序中的函数调用语句与实际要执行的函数体代码（内存地址）关联起来的过程。根据这个过程发生在编译阶段还是运行阶段，我们分为静态绑定和动态绑定。

静态绑定 static binding 发生在编译阶段，编译器遇到函数调用时，根据调用对象的声明类型和函数名及参数，通过重载决议选出唯一匹配的函数。然后，编译器将该函数的修饰后名称嵌入到目标文件的调用指令中。同时，在链接期时，链接器将目标文件中的符号引用直接重定位为绝对地址或相对偏移。普通成员函数（非 virtual）、函数重载、运算符重载以及模板实例化都属于静态绑定。

动态绑定 dynamic binding 发生在运行阶段，依赖虚函数表 vtable 和虚指针 vptr，当一个类声明了虚函数，编译器会为这个类生成一张虚函数表（函数地址数组），每个对象在构造时，在内存前部都会被编译器隐式地安插一个指向该类虚函数表的指针 vptr。通过基类指针或引用调用虚函数时，程序先取出对象的 vptr，再索引虚表找到对应函数的实际地址，最后跳转执行，整个过程有轻微的内存和性能开销。

动态绑定必须是 virtual 虚函数，也必须通过基类的指针 * 或引用 & 来调用，如果直接用基类对象（而非指针/引用）赋值，会发生对象切片 object slicing，丢失派生类信息，从而退化为静态绑定。另外，用派生类指针（或对象）调用相当于普通成员函数调用。

RTTI

动态类型 dynamic type 指的是程序在运行时，指针或引用所实际指向的对象类型，可以被改变。静态类型 static Type 指变量在编译时就确定的类型，在它的声明中写明，且不会改变。如果表达式既不是引用也不是指针，则它的动态类型永远与静态类型一致。动态类型是 C++ 实现动态绑定或运行时多态的基石。

运行时类型识别 Runtime Type Identification (RTTI) 是 C++ 中的一项机制，它允许程序在运行时获取对象的动态类型（实际类型信息）。在 C++ 的静态类型系统中，变量的类型通常在编译时就已经确定。然而，当使用基类的指针或引用来操作派生类对象时（即多态场景），编译器在编译时无法确切知道这个指针或引用指向的具体是哪个派生类对象，RTTI 正是为了解决这个问题而设计的。C++ 通过两个主要的操作符来提供 RTTI 功能：

抽象类

上面提到过纯虚函数 pure virtual function，在虚函数声明的结尾加上 = 0 表示不提供具体实现，它定义了一个接口规范，让派生类覆写这个函数。含有（或者未覆盖直接继承）纯虚函数的类就是抽象类 abstract class，抽象类不能被实例化，只能作为基类被其他类继承，它的核心作用是为一组相关的类定义通用的接口和规范。派生类必须实现基类中所有的纯虚函数，否则它自身也成为一个抽象类。

模板本身只是蓝图不是具体的代码，实例化就是编译器根据具体的模板参数，从蓝图中生成真正可供编译的类或函数代码的过程。上面例子中都是隐式实例化 implicit instantiation（注意与隐式或显式指定模板实参进行区分），当代码需要一个完整的类型定义时，例如创建该类型的对象，或调用一个函数模板且编译器能推导出模板参数时，编译器自动完成隐式实例化。还有显式实例化 explicit instantiation，允许我们主动命令编译器在当前编译单元（.cpp 文件）中生成特定模板实例的代码。

模板的文件组织

C++ 模板的文件组织与传统非模板代码有根本不同，这源于其编译模型的特殊性，即编译器在实例化模板时，必须要看到其完整的定义。对于普通函数和类，头文件 .h 放声明，源文件 .cpp 放定义，然后在链接阶段将各部分组合起来。但模板不同，它本身不是可编译的代码，而是蓝图。编译器只有在遇到具体实例化时，才根据蓝图生成真正的代码。如果此时定义不可见，编译器就无法生成代码，导致链接错误。

最主流、最简单的做法，也是 C++ 标准库采用的方式，就是将模板的声明和定义都放在头文件里，缺点就是头文件会被多个 .cpp 文件包含，每个文件都要重新编译模板代码，导致编译变慢。还有种做法就是使用显式实例化，将模板的声明和定义分开，在头文件中仅包含模板声明，在源文件包含定义，并显式实例化所需类型，这种做法只适用于知道模板只会用于有限的几种类型时。

除了上述两种做法，还可以将模板定义放在专门的文件中，然后在头文件末尾包含它，以保持头文件清晰，常用的扩展名有：.tpp、.inl。

模板元编程

先解释什么是元编程 metaprogramming？简而言之，就是编写能够操作或生成其他程序（包括它自身）的程序。如果说普通编程是写代码来解决业务问题，那么元编程就是写代码来生产或修改代码。它的核心思想是将代码视为数据，让程序在编译时或运行时拥有自我认知和自我改造的能力。

根据元编程逻辑是在编译期执行还是运行时执行，可以分为两大类：①编译期元编程或静态元编程：元代码在程序编译阶段运行，生成最终的二进制代码，主要代表有 C++ 模板元编程、预处理宏等；②运行时元编程或动态元编程：元代码在程序运行期间执行，动态地修改或生成代码。灵活性极高，但会带来额外的性能开销，比如 Python 的装饰器和元类、Java / C# 的反射等。

按功能来说，也可以分为①自省 introspection：程序在运行时审视自己的结构，比如通过反射获取一个类有哪些方法和字段；②自修改 self-modification：程序在运行时修改自身结构；③代码生成 code generation：程序生成新的源代码或字节码。

模板元编程 template metaprogramming (TMP) 是 C++ 中一种在编译期（而非运行时）执行计算和逻辑处理的编程范式，让编译器在编译阶段完成数值计算或者类型操作等。一个简单的例子就是利用递归模板实例化替代循环，在编译期模拟循环：
