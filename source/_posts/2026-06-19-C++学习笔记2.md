# 第八章 类的基本概念
**类 class** 是用户自定义类型，由一组**成员 member** 组成，成员包括**数据成员 data member** 和**成员函数 member function**。一个简单的类定义如下：  

``` C++
class MyClass {       
public:                    // 访问修饰符 access specifier
    int myNum;             // 数据成员 data member 
    std::string myString;  // 数据成员 data member 
};
```

定义类之后就可以创建它的类对象了，对象可以分配在栈上也可以在堆上，对于普通对象使用 `.` 运算符访问成员，对于指针对象使用 `->` 运算符访问成员：  

``` C++
int main() {
    MyClass class1; // 栈上分配
    MyClass* class2 = new MyClass; // 堆上分配
    
    class1.myNum = 5;
    class2->myNum = 5;
    std::cout << class1.myNum << std::endl; // 输出 5
    std::cout << class2->myNum << std::endl; // 输出 5
    delete class2;
}
```

## 类内初始化器
C++ 11 引入了**类内初始化器 in-class initializer**，或称为**默认成员初始化器 default member initializer**，它允许你在声明成员变量时直接为其指定默认值，例如：  

``` C++
class MyClass {
    int a = 10;          // 使用 = 
    double b{3.14};      // 使用 {}
    std::string s = "hello";
    // int c(5);         // 错误！不能使用圆括号，会被解析为函数声明
};
```

注意，类内初始化器的实际初始化顺序遵循声明顺序。

## 类访问修饰符
**访问修饰符 access specifier** 主要是用于实现数据**封装 encapsulation**，C++ 提供了三种访问修饰符：  
①公有 public：成员可以从类外部访问；  
②私有 private：成员不能从类外部访问；  
③受保护 protected：成员不能从类外部访问，但其派生类可以访问。

默认情况下，如果不显式指定访问修饰符，类的成员都是 private，例如：  

``` C++
class A { int x; };  // x 是 private，外部不能访问
```

## 成员函数
一般来说，类的定义分为两个部分：类声明和类成员函数定义。类成员函数定义可以在类内部，也可以在类外部。但是通常情况下，建议将类声明放在头文件 <kbd>.h</kbd> 文件当中，类成员函数定义放在 <kbd>.cpp</kbd> 文件当中。

### 类内部定义

``` C++
class MyClass {
public:
    void myMethod() {
        std::cout << "Hello World!" << std::endl;
    }
};
```

在类内部定义的成员函数是隐式内联 inline 的。在上一章函数章节有提过 inline 的作用是把代码复制粘贴到调用处，让程序跑得更快，但是对于现在的编译器来说，是否内联优化几乎完全取决于编译器。而这里的内联，主要是解决一个函数被定义在多个 <kbd>.cpp</kbd> 文件当中从而导致链接时重复定义的问题。比如，如果成员函数定义在头文件 <kbd>.h</kbd> 里，且被多个 <kbd>.cpp</kbd> 文件包含，必须让它隐式内联（写在类内部）或显式加 inline（写在类外部），否则链接器会报错说函数重定义。

### 类外部定义
成员函数若定义在类外部，则需要作用域解析运算符 `::` 来标识函数所属的类：  

``` C++
class MyClass { // 建议放在 .h 文件当中
public:
    void myMethod();
};

void MyClass::myMethod() { // 建议放在 .cpp 文件当中，若放在 .h 文件中建议加 inline
    std::cout << "Hello World!" << std::endl;
}
```

### this 指针
当一个对象的成员函数被调用时，即 `obj.func()`，编译器会隐式地将该对象的地址作为参数传递给 func，这个参数就是 **this 指针**。在成员函数内部，所有对非静态成员的访问，其实都是通过 `this->成员名` 来完成的，this 前缀是编译器自动添加的。简单的示例如下：  

``` C++
class Button {
private: 
    string name;
public:
    void setName(string name) {
        this->name = name; // 左边的 name 是成员变量，右边的 name 是参数
    }

    void onClick() {
        EventSystem::register(*this); // 将当前对象传入事件系统
    }
};
```

this 指针是一个指针常量，即指针本身不可修改以及不能指向别的对象，实际类型为 `ClassName* const`。

### const 成员函数
**常量成员函数 const member function** 指不能修改对象成员变量的成员函数，通过将 const 关键字放在成员函数的参数列表之后来实现，这个 const 实际上修饰的是 this 指针，表示 this 是一个指向常量的指针，类型为 `const ClassName* const`，例如：  

``` C++
class Counter {
private:
    int value = 0;
public:
    int getValue() const {
        // value++; // 报错
        return value; // 只读访问
    }
};
```

### mutable 成员
被 `mutable` 修饰的成员变量，即**可变数据成员 mutable data member**，即使在 const 成员函数中，依然可以被修改，例如：  

``` C++
class Counter {
private:
    mutable int value = 0;
public:
    int getValue() const {
        value++; // 允许
        return value;
    }
};
```

## 构造函数
**构造函数 constructor** 是一种特殊的成员函数，常用于初始化类对象的数据成员，同样可以在类内部或外部定义。构造函数名称与类的名称完全相同，且没有返回类型。一个类可以有多个构造函数，即**构造函数重载 constructor overloading**，只要参数列表不同。我们可以<u>显式</u>地调用构造函数，也可以<u>隐式</u>地调用构造函数，例如：  

``` C++
class Car {
public:
    std::string brand;
    int year;
    Car(std::string x, int y); // 带参数构造函数
};

Car::Car(std::string x, int y) {
    brand = x;
    year = y;
}

int main() {
    Car car1 = Car("Honda", 2019); // 显式调用构造函数
    Car car2("Toyota", 2020); // 隐式调用构造函数
    Car* car3 = new Car("Ford", 2018); // 显式调用构造函数

    Car car4{"Nissan", 2026}; // 直接列表初始化，C++ 17 后只调用一次构造函数
    Car car5 = Car{"Tesla", 2021}; // 列表初始化 + 复制初始化，C++ 17 后只调用一次构造函数
    Car car6 = {"Mercedes", 2024}; // 复制列表初始化，C++ 17 后只调用一次构造函数
}
```

### 默认构造函数
**默认构造函数 default constructor** 指不需要提供任何实参就可以调用的构造函数，包括两种形式：无参构造函数以及全缺省构造函数（所有参数都有默认值），且每个类最多可以有一个默认构造函数。

``` C++
class Example {
public:
    Example() { /* ... */ } // 1. 无参构造函数
    Example(int a = 0, double b = 1.0) { /* ... */ } // 2. 全缺省构造函数（所有参数都有默认值）
};
```

如果类没有显式地定义任何构造函数，编译器就会为我们隐式地定义一个默认构造函数，又被称为**合成的默认构造函数 synthesized default constructor**，其效果等同于一个函数体和参数列表都为空的默认构造函数。默认构造函数在以下两种初始化场景中会被自动调用：①**默认初始化 default initialization**，例如 `MyClass obj;` 或使用 `new MyClass;`，此时内置类型成员（如 int、指针等）的值是未定义的，因为内置类型成员本身若默认初始化，编译器不会为它们赋一个初始值，除非作为静态存储的变量时被初始化为 0；②**值初始化 value initialization**，例如 `MyClass obj{};` 或使用 `new MyClass();`，此时内置类型会被初始化为默认值 0 或 nullptr。但是，数据成员若有类内初始化器，上述两种形式都会为成员初始化为类内初始化器中的默认值。

另外，有时候编译器不能为某些类合成默认的构造函数，比如类中有未初始化的引用类型的成员变量，或者包含一个其他类类型的成员且这个成员的类型没有默认构造函数，亦或者含有未初始化的 const 成员等等。

### 构造函数初始化列表
推荐使用**构造函数初始化列表 constructor initialize list** 来初始化数据成员，它也称为**成员初始化列表 member initializer list**。初始化列表位于构造函数的参数列表之后，函数体之前，以冒号 `:` 开头，多个成员用逗号分隔，例如：  

``` C++
class Entity {
private:
    int& a;
    const int b;
    std::string name;
public:
    Entity(int& x, int y, const std::string& n) : a(x), b(y), name(n) {
        // 构造函数函数体
    }
};
```

有些成员变量必须放在初始化列表中初始化，否则编译报错，比如：  
①引用类型 `T&`：引用必须在定义时绑定对象，且不可修改；  
②const 成员：常量在声明后不能赋值，只能在初始化阶段设值；  
③没有默认构造函数的类对象：如果成员是一个类，且该类没有提供无参构造函数，你必须在初始化列表里传入构造参数。  

``` C++
class Inner {
public:
    Inner(int val) {} // 有参构造函数，无默认构造函数
};

class MyClass {
private:
    const int c;
    int& ref;
    Inner in;
public:
    // 错误！执行到构造函数体 {} 时，这些成员已经尝试使用默认构造，但 const / 引用未绑定，Inner 无默认构造
    MyClass(int val, int& r) {
        c = val;    // 错误
        ref = r;    // 错误
        in = Inner(10); // 错误（虽然看起来像，但 in 已经构造完了）
    }

    // 正确
    MyClass(int val, int& r) : c(val), ref(r), in(10) {}
};
```

在构造函数体内赋值跟使用初始化列表具有本质区别：<u>在构造函数体内赋值，编译器会先调用成员的默认构造函数创建临时对象，然后再调用赋值运算符覆盖值</u>，这产生了两次函数调用。而使用初始化列表，编译器直接初始化成员对象，只发生一次构造。

``` C++
class Student {
private:
    std::string name;
public:
    Student(const std::string& s) { // 方式一：低效 (先默认构造空string，再赋值)
        name = s;
    }
    
    Student(const std::string& s) : name(s) { } // 方式二：高效 (直接拷贝构造)
};
```

另外，初始化列表的执行顺序，完全取决于成员变量在类中的声明顺序，而不是初始化列表中的书写顺序。<u>建议书写时，永远让初始化列表的顺序与类中声明的顺序严格一致</u>，并且绝对不要用尚未初始化的成员去初始化另一个成员。

### 委托构造函数
C++ 11 引入了**委托构造函数 delegating constructor**，它允许一个构造函数在初始化列表中调用同一个类的另一个构造函数，例如：  

``` C++
class Date {
    int d, m, y;
public:
    Date(int day, int month, int year) : d(day), m(month), y(year) {}
    Date() : Date(1, 1, 1970) {} // 委托构造函数
    Date(int day) : Date(day, 1, 1970) {} // 委托构造函数
};
```

在委托构造函数的初始化列表中只能有这一个委托调用，不能同时有其他成员初始化器。当一个构造函数委托给另一个构造函数时，受委托的构造函数的初始化列表和函数体被依次执行，然后再执行当前构造函数自身的函数体。

### 转换构造函数
如果构造函数可用单个实参调用（只有一个参数，或者有多个参数但除第一个外均有默认值），则它实际上定义了转换为当前类类型的隐式转换机制，称为**转换构造函数 converting constructor**，例如：  

``` C++
class MyString {
private:
    std::string data;
public:
    // 转换构造函数：允许从 const char* 隐式转换为 MyString
    MyString(const char* str) : data(str) { 
        std::cout << "Converting constructor called" << std::endl; 
    }
};

void print(MyString s) {
    // ...
}

int main() {
    print("Hello World"); // 隐式转换，自动调用 MyString(const char*) 进行转换
    MyString s = "C++"; // 隐式转换，等价于 MyString s("C++");
}
```

由于，所有单参数构造函数都是转换构造函数，会导致意外转换，C++ 提供了 `explicit` 关键字，强制要求必须使用直接初始化或显式转换：  

``` C++
class SafeString {
private:
    std::string data;
public:
    explicit SafeString(const char* str) : data(str) { }
};

void log(SafeString s) { /*...*/ }

int main() {
    log("error"); // 错误：无法隐式转换
    SafeString s1("OK"); // 正确：直接初始化
    SafeString s2 = "OK"; // 错误：explicit 禁止复制初始化
    SafeString s3 = SafeString("OK"); // 正确：显式构造后拷贝
    log(SafeString("error")); // 正确：显式构造临时对象
    SafeString s4 = static_cast<SafeString>("OK"); // 正确：static_cast 显式转换
    SafeString s5 = (SafeString) "OK"; // 正确：C 风格强制转换
}
```

### 拷贝、移动构造函数
除了定义类的对象如何初始化之外，类还需要控制拷贝、移动、赋值和销毁对象时发生的行为。一个类通过定义五种特殊的成员函数来控制这些操作，包括：**拷贝构造函数 copy constructor**、**拷贝赋值运算符 copy assignment operator**、**移动构造函数 move constructor**、**移动赋值运算符 move assignment operator** 和**析构函数 destructor**。析构函数在下面小节讲解，其他内容在下一章节 - 类的拷贝控制中详细说明。

## 析构函数
**析构函数 destructor** 是类的一个特殊成员函数，它在对象的生命周期结束时自动调用，主要用于释放对象占用的资源（如动态内存、文件句柄、网络连接、锁等）。它是**资源获取即初始化 RAII** 思想的核心支柱，RAII 在智能指针和内存管理的章节介绍。析构函数的名称与类的名称相同，只是前面多了波浪号 `~`，例如 `~MyClass()`，其无返回类型、无参数、不能被重载，并且每个类只能有一个析构函数。当一个类未定义自己的析构函数时，编译器会为它定义一个**合成析构函数 synthesized destructor**，合成析构函数的函数体为空。

在一个构造函数中，成员的初始化是在函数体执行之前完成的，且按照它们在类中出现的顺序进行初始化。在一个析构函数中，首先执行函数体，然后销毁成员，成员按初始化顺序的逆序销毁。成员的销毁是隐式的，销毁时发生什么依赖于成员的类型，销毁类类型的成员会执行成员自己的析构函数，而内置类型没有析构函数，直接释放内存，当然指针成员不会自动 delete 指向的堆内存，只会销毁指针自身。

``` C++
class Resource {
    int* data;
public:
    Resource() { data = new int[100]; }
    ~Resource() { delete[] data; } // 必须释放
};
```
### 触发场景
当对象被销毁时，析构函数自动执行，常见的销毁的场景包括：  
①局部变量在离开其作用域时被销毁；  
②对于动态分配的对象，当对指向它的指针应用 delete 运算符时被销毁；  
③当对象作为容器元素时，容器整体销毁、显式清空或删除以及容器扩容时被销毁；  
④在表达式中生成的临时对象，当创建它的完整表达式结束时被销毁；  
⑤具有静态存储期的对象（全局变量、static 局部变量、static 成员变量）在程序正常终止时销毁。  

## 静态成员
静态成员是 C++ 类中一种特殊成员，它不属于某个具体对象，而是属于类本身。所有该类的对象共享同一个静态成员，静态成员包括静态数据成员和静态成员函数。

### 静态数据成员
静态数据成员使用 `static` 关键字声明，但不能在类内初始化，必须在类外进行定义（通过范围解析运算符 `::` ），除非是 constexpr 或 const，C++ 17 及之后，可以使用 inline 关键字直接在类内部初始化，无需再写类外定义。如果不存在其他的初始化语句，在创建第一个对象时，所有的静态数据都会被初始化为零。

``` C++
class MyClass {
public:
    static int count; // 声明
};
int MyClass::count = 10; // 定义并初始化（必须在类外）
```

### 静态成员函数
如果把函数成员声明为静态的，就可以把函数与类的任何特定对象独立开来。静态成员函数即使在类对象不存在的情况下也能被调用，静态函数只要使用类名加范围解析运算符 `::` 就可以访问，但只能访问静态成员数据、其他静态成员函数和类外部的其他函数，不能访问类的 this 指针。静态成员函数可以在类内实现（隐式内联），也可以在类外定义：  

``` C++
class Utility {
public:
    static void show(); // 声明
};
void Utility::show() { // 类外定义，不加 static
    // ...
}
```

## 成员指针
**成员指针 pointer to member** 是指可以指向类的非静态成员（数据成员或成员函数）的指针。与普通指针存储内存地址不同，成员指针存储的是成员相对于类对象起始地址的偏移量（对于数据成员）或函数入口地址（对于成员函数）。这种设计使得成员指针可以独立于具体对象存在，当初始化一个这样的指针时，我们令其指向类的某个成员，但是不指定该成员所属的对象，直到使用成员指针时，才需要提供成员所属的对象。静态成员属于类本身而非具体对象，有固定的内存地址，因此使用普通指针即可，无需成员指针语法。

### 数据成员的指针
和其他指针一样，在声明成员指针时我们也使用 `*` 来表示当前声明的名字是一个指针。与普通指针不同的是，成员指针还必须包含成员所属的类，需在 `*` 之前添加 `classname::` 以表示当前定义的指针可以指向 classname 的成员。例如：

``` C++
class Point {
public:
    int x;
    double y;
};

// 声明并初始化指向数据成员的指针
int Point::*pX = &Point::x;
double Point::*pY = &Point::y;
```

当我们初始化一个成员指针或为成员指针赋值时，该指针并没有指向任何数据。成员指针指定了成员而非该成员所属的对象，只有当解引用成员指针时我们才提供对象的信息。也就是说，成员指针必须与具体的对象结合才能访问成员数据，通过 `.*` 和 `->*` 两个操作符完成，例如：  

``` C++
Point pt;
Point* pPt = &pt;

// 通过对象使用 .* 操作符
pt.*pX = 10;
int val1 = pt.*pX;

// 通过对象指针使用 ->* 操作符
pPt->*pX = 20;
int val2 = pPt->*pX;
```

### 成员函数的指针
和指向数据成员的指针一样，我们使用 `classname::*` 的形式声明一个指向成员函数的指针。类似于任何其他函数指针，指向成员函数的指针也需要指定目标函数的返回类型和形参列表。如果成员函数是 const 成员或者引用成员，则我们必须将 const 限定符或引用限定符包含进来，例如：  

``` C++
class Calculator {
public:
    int add(int a, int b) { return a + b; }
    void show() const { /* ... */ }
};

// 指向成员函数 add
int (Calculator::*pAdd)(int, int) = &Calculator::add;

// 指向 const 成员函数（必须匹配 const 限定符）
void (Calculator::*pShow)() const = &Calculator::show;
```

使用方式与数据成员指针类似，通过 `.*` 和 `->*` 调用：  

``` C++
Calculator calc;
Calculator* pCalc = &calc;

// 通过对象调用
int result = (calc.*pAdd)(3, 5);

// 通过对象指针调用
int result2 = (pCalc->*pAdd)(3, 5);
```

注意：`(calc.*pAdd)(3, 5)` 的前一个括号是必须的。因为函数调用 `()` 的优先级高于 `.*`，若写成 `calc.*pAdd(3, 5)`，编译器会理解为 `calc.*(pAdd(3, 5))`，导致错误。

### 使用成员指针的类型别名
使用类型别名 `using` 或 typedef 可以简化成员函数指针的声明：  

``` C++
class Screen {
public:
    void home();
    void forward();
};

typedef void (Screen::*Action)(); // 使用 typedef
Action pAction = &Screen::home;

using Action = void (Screen::*)(); // 使用 using (C++11)
Action pAction2 = &Screen::forward;
```

## 友元
**友元 friend** 允许外部函数或外部类访问当前类的 private 和 protected 成员，但因为会破坏封装性，建议少用为妙。友元的声明只能出现在类的内部，且不受 public / private 访问修饰符的影响。

### 友元函数
友元可以让全局函数能够访问类的私有成员：  

``` C++
class Box {
private:
    double width;
public:
    Box(double w) : width(w) {}
    
    friend void printWidth(Box& b); // 声明全局函数 printWidth 为友元
};

void printWidth(Box& b) { // 注意没有作用域限定符 ::
    std::cout << "Width = " << b.width << std::endl; // 可以访问 private 成员 width
}

int main() {
    Box box(10.5);
    printWidth(box);
}
```

### 友元类
整个类作友元，让友元类可以访问当前类的私有成员：  

``` C++
class A {
private:
    int secret = 42;
public:
    friend class B; // 声明 B 类是 A 的友元
};

class B {
public:
    void show(A& a) {
        std::cout << a.secret << std::endl; // B 可以访问 A 的私有成员
    }
};

int main() {
    A a;
    B b;
    b.show(a); // 输出 42
}
```

### 成员函数作为友元
仅让某个类的某个特定成员函数成为另一个类的友元，这种方式可能需要注意是否满足声明和定义的彼此依赖关系，可能需要类的**前向声明 forward declaration**，即仅声明类而暂时不定义它，例如：  

``` C++
class A; // 前向声明

class B {
public:
    void func(A& a); // 将成为友元
};

class A {
private:
    int data = 10;
public:
    friend void B::func(A& a); // 仅声明 B 的 func 为友元
};

void B::func(A& a) {
    std::cout << a.data << std::endl; //必须等 A 完全定义后才能实现 func，因为要用到 A::data
}
```

## 聚合类
**聚合类 aggregate class** 是一种特殊的类或结构体，它允许使用**聚合初始化 aggregate initialization** 来直接初始化其成员。聚合初始化是唯一一种绕过构造函数的初始化方式，直接在对象的内存上，按声明顺序把值“填充”给成员变量。聚合初始化也是使用 `{}` 或 `()`（C++ 20 起支持）形式初始化的，但对非聚合类使用 `{}` 或 `()` 都会调用构造函数。一个类或结构体被视为聚合类，当且仅当它满足以下所有条件：  
①没有用户提供的构造函数（`=default` / `=delete` 除外）；  
②所有非静态数据成员的访问权限必须是 public，静态数据成员和成员函数不受此限制；  
③不能有基类（C++ 17 后允许）或虚函数。

聚合初始化按成员在类中声明的顺序依次赋值，未提供值的成员将执行值初始化（内置类型归零，类类型调用默认构造函数），例如：  

``` C++
class Point {
public:
    int x;
    int y;
};

Point p1{1, 2};  // 聚合初始化 p1.x = 1, p1.y = 2
Point p2{3};     // 聚合初始化 p2.x = 3, p2.y = 0（值初始化）
Point p3{};      // 聚合初始化 p3.x = 0, p3.y = 0
Point p4(1, 2);  // 聚合初始化（C++20 起支持）
Point p5 = {1, 2}; // 聚合初始化
```

注意，只要显式写了构造函数，聚合性立刻失效，`{}` 就会去匹配构造函数。另外，聚合类通常代表简单的数据容器，天生适合结构体，`struct` 默认所有成员刚好是 public。

## 字面值常量类
上篇文章第五章 - 表达式与运算符 - 常量表达式 - 字面值类型提过**字面值常量类 literal constant class**，但那里讲的比较简单。字面值常量类是**字面值类型 literal type** 的一种，指满足特定条件、可以在编译期作为常量表达式使用的类类型，必须同时满足：  
①类必须使用析构函数的默认定义；  
②至少有一个 constexpr 构造函数（非拷贝/移动构造函数），或者该类是一个聚合类；  
③所有非静态数据成员和所有基类都必须是字面值类型；  
④如果一个数据成员含有类内初始值，则内置类型成员的初始值必须是一条常量表达式，或者如果成员属于某种类类型，则初始值必须使用成员自己的 constexpr 构造函数。

``` C++
// 字面值常量类
struct Point {
    int x, y;
    constexpr Point(int a, int b) : x(a), y(b) {} // constexpr 构造函数
    constexpr int sum() const { return x + y; } // constexpr 成员函数
};

// 聚合类，自动成为字面值类型（因为成员是 int，析构平凡）
struct Color {
    unsigned char r, g, b;
};

int main() {
    constexpr Point p(3, 4); // 编译期构造
    constexpr int sum = p.sum(); // 编译期计算
    constexpr Color c{255, 0, 0};
    constexpr int red = c.r; // 可以作为编译期常量
    std::cout << sum << '\n';  // 输出 7
}
```

另外，C++ 20 之前要求 constexpr 构造函数必须初始化所有非静态数据成员，但自 C++ 20 起不再强制要求，未初始化的成员将成为未初始化的状态。C++ 20 之前，如果 constexpr 构造函数没有在初始化列表中覆盖某个成员，编译器会自动检查该类内初始值，如果有，则认为该成员已被初始化，编译通过；如果没有类内初始值，且构造函数没写，则会报错。

# 第九章 类的拷贝控制和运算符重载
**拷贝控制 copy control** 是 C++ 类设计中的核心概念，它定义了当对象被拷贝、移动、赋值或销毁时发生的行为。一个类通过定义五种特殊的成员函数来控制这些操作，包括：**拷贝构造函数 copy constructor**、**拷贝赋值运算符 copy assignment operator**、**移动构造函数 move constructor**、**移动赋值运算符 move assignment operator** 和**析构函数 destructor**。

## 拷贝构造函数
**拷贝构造函数 copy constructor** 是一种特殊的构造函数，第一个参数是自身类类型的 const 左值引用（可以是非 const 引用，但不推荐），如果有额外参数则必须有默认值，例如：  

``` C++
class MyClass {
public:
    MyClass(const MyClass& other);  // 拷贝构造函数
};
```

### 触发场景
拷贝构造函数在以下场景中会被调用：  

| 场景 | 代码示例 |
| :---- | :---- |
| 对象定义时使用同类型对象的初始化（直接初始化） | `MyClass a; MyClass b(a);` |
| 对象定义时同类型对象的等号初始化（拷贝初始化） | `MyClass b = a;` （此处不是赋值，赋值是 `MyClass a, b; b = a;`，调用拷贝赋值运算符） |
| 函数实参按值传递 | `void func(MyClass x); func(a);` |
| 函数按值返回对象 | `MyClass func() { return a; }` |

但编译器在某些场景中允许进行**拷贝省略 copy elision**，消除不必要的拷贝，将两个独立的对象合并到同一个内存地址上，直接在最终目标位置构造对象，从而跳过中间临时对象的诞生与销毁。如函数返回一个纯右值临时对象：`return A();`；以及用临时对象初始化新对象：`A a = A();`，此时等价于 `A a();`。这两种纯右值初始化，在 C++ 17 后拷贝省略是标准强制的，不再是可选的优化。对于函数返回一个局部具名变量：`A a; return a;`，仍然是允许但非强制的优化。

另外，如果拷贝构造函数被声明为 `explicit`，要求显式调用，则拷贝初始化 `MyClass b = a;` 会编译失败，而可以使用直接初始化 `MyClass b(a);`。

### 合成拷贝构造函数
如果我们没有为一个类定义拷贝构造函数，编译器会为我们定义一个，称为**合成拷贝构造函数 synthesized copy constructor**。与合成默认构造函数不同，即使定义了其他构造函数，编译器也会合成一个拷贝构造函数。合成拷贝构造函数会将其参数的成员逐个拷贝到正在创建的对象中，对于内置类型（int、指针等）直接复制字节（浅拷贝），对于类类型成员会使用该成员的拷贝构造函数。

合成拷贝构造函数因为<u>浅拷贝</u>的原因，存在一定的缺陷，当类有指针成员管理动态内存时，默认拷贝构造只复制指针值，即地址，导致两个对象指向同一块堆内存，析构时会发生双重释放或悬空指针问题。所以当类需要管理动态分配的内存、文件句柄等资源时，必须自定义拷贝构造函数以实现<u>深拷贝</u>（而非浅拷贝），否则两个对象会共享同一资源，导致重复释放或数据损坏。

### 自定义拷贝构造函数
自定义拷贝构造函数的一个示例如下，适用于类中持有动态内存数组：  

``` C++
#include <algorithm>

class Buffer {
private:
    size_t size;
    int* data; // 管理动态内存数组
public:
    Buffer(size_t n) : size(n), data(new int[n]) {}
    
    // 自定义拷贝构造（深拷贝）
    Buffer(const Buffer& other) : size(other.size), data(new int[other.size]) {
        std::copy(other.data, other.data + size, data); // 复制数据
    }
    
    ~Buffer() { delete[] data; }
};
```

`std::copy` 是 C++ 标准库 `<algorithm>` 头文件中提供的通用元素复制算法，不在这里详细介绍了。性能更高的写法会使用 `std::uninitialized_copy`，有兴趣可以额外去了解。

## 拷贝赋值运算符
**拷贝赋值运算符 copy assignment operator** 是一个名为 `operator=` 的成员函数，是**重载运算符 overloaded operator** 的一种（可以先看本章运算符重载小节），其参数通常为 const 左值引用，返回类型通常为自身类型的左值引用（通常为 `*this`），例如：  

``` C++
class MyClass {
public:
    MyClass& operator=(const MyClass& other);
};
```

当已有对象被赋予另一个同类型已有对象时，拷贝赋值运算符被调用，但要注意拷贝赋值作用于已存在的对象，拷贝构造作用于新创建的对象，例如：  

``` C++
MyClass a;
MyClass b = a;  // 调用 拷贝构造函数 (b 还未被构造)
MyClass c;      // 调用 默认构造函数
c = a;          // 调用 拷贝赋值运算符 (c 已经存在)
```

与拷贝构造函数一样，如果一个类未定义自己的拷贝赋值运算符，编译器会为它生成一个**合成拷贝赋值运算符 synthesized copy assignment operator**。合成拷贝赋值运算符也是逐个成员拷贝，对于内置类型直接复制字节（浅拷贝），对于类类型成员调用该成员的拷贝赋值运算符，跟合成拷贝构造函数存在相同的风险。

### 自定义拷贝赋值运算符
当类管理动态内存、文件句柄或锁等资源时，必须自定义拷贝赋值运算符，下面使用自定义拷贝构造函数中的示例为示例，手动实现拷贝赋值：  

``` C++
#include <algorithm>

class Buffer {
    // 数据成员、构造函数、拷贝构造函数、析构函数见自定义拷贝构造函数

    Buffer& operator=(const Buffer& other) {
        // 自赋值检测（防止释放自身资源后，再去拷贝自身已释放的内存）
        if (this == &other) {
            return *this;
        }

        // 释放当前旧资源
        delete[] data;

        // 深拷贝
        size = other.size;
        data = new int[size];
        std::copy(other.data, other.data + size, data);

        return *this;
    }
};
```

手动实现拷贝赋值需要注意自我赋值检测以及异常处理，可以改用常见经典写法，即采用<u>拷贝并交换 copy-and-swap</u>的方式，自动处理自我赋值，并提供强异常安全保证，例如：  

``` C++
#include <algorithm>
#include <utility> // for std::swap

class Buffer {
    // 数据成员、构造函数、拷贝构造函数、析构函数见自定义拷贝构造函数

    // 交换函数
    void swap(Buffer& other) noexcept {
        std::swap(this->data, other.data);
        std::swap(this->size, other.size);
    }

    // 拷贝赋值运算符，利用局部拷贝 + 交换 (自动处理自赋值和异常)
    Buffer& operator=(const Buffer& other) {
        Buffer temp(other); // 调用拷贝构造，若抛异常，原对象保持不变
        temp.swap(*this); // 交换资源，temp 析构时带走旧资源
        return *this;
    }

    // 或者可以利用传值的拷贝构造创建副本，但这个函数同时处理了拷贝和移动，不是很建议使用
    Buffer& operator=(Buffer other) {
        other.swap(*this);
        return *this;
    }
};
```

`std::swap` 是 C++ 标准库中用来交换两个变量或对象的值的函数模板，内部实现利用了移动语义加快了交换效率，不在这里详细介绍，有兴趣可以额外了解。

## 移动构造函数
在 C++ 11 之前，没有直接的方法移动对象。因此，即使不必拷贝对象的情况下，也不得不拷贝。如果对象较大，或者是对象本身要求分配内存空间，进行不必要的拷贝代价非常高。为了支持移动语义，C++ 11 引入了右值引用，右值引用在第三章 - 引用部分详细探讨过，这里就不重复说明了。为了让我们自己的类型支持移动操作，需要为其定义移动构造函数和移动赋值运算符。这两个成员类似对应的拷贝操作，但它们从给定对象“窃取”资源而不是拷贝资源，使用的正是右值引用。

类似拷贝构造函数，**移动构造函数 move constructor** 的第一个参数是该类类型的一个引用，只不过是右值引用 `T&&`，若有其他参数则必须有默认值。声明时，推荐添加 `noexcept`，它表示该函数不会抛出异常，因为移动操作不分配资源，通常不会抛出异常，这么做可以防止为了处理可能发生的异常而进行一些额外的工作，同时有助于标准库（如 `std::vector`）在重新分配内存时优先使用移动构造。实例如下：  

``` C++
class MyClass {
public:
    MyClass(MyClass&& other) noexcept; // 移动构造函数
};
```

移动构造函数通常在用右值初始化同类型对象时被调用，例如：  

``` C++
// 用 std::move 转换后初始化
std::vector<int> v1{1,2,3};
std::vector<int> v2(std::move(v1));

// 函数返回局部对象（当不触发拷贝省略和编译器选择移动时）
std::string createString() {
    std::string s = "hello";
    return s; // C++11 起优先移动，实际常被 NRVO 优化掉
}

// 使用临时对象初始化
std::string s = std::string("temp"); // 临时对象是右值，移动构造
```

编译器也会隐式声明移动构造函数，称为**合成移动构造函数 synthesized move constructor**，但条件比合成拷贝构造函数复杂很多。如果类没有用户声明的拷贝构造函数、拷贝赋值运算符、移动赋值运算符或析构函数时，编译器才会合成一个按成员移动的移动构造函数，对内置类型移动即拷贝（浅拷贝，复制值），对类类型调用其移动构造函数。

### 自定义移动构造函数
除了转移资源所有权，移动构造函数还必须确保将源对象置于有效但未指定的状态（通常是将指针置空）。这主要是为了防止源对象在离开作用域析构时，因重复释放已转移的资源而导致程序崩溃。还是使用之前拷贝时的示例：  

``` C++
class Buffer {
    // 数据成员、构造函数、析构函数、拷贝构造函数、拷贝赋值运算符

    Buffer(Buffer&& other) noexcept : size(other.size), data(other.data) {
        // 将源对象置于“空”状态，防止其析构时释放我们窃取的资源
        other.size = 0;
        other.data = nullptr;
    }
};
```

## 移动赋值运算符
与拷贝赋值运算符一样，**移动赋值运算符 move assignment operator** 也是一个名为 `operator=` 的成员函数，其参数为右值引用`T&&`，返回值通常为 `T&`（`*this`）。同样建议声明为 noexcept，因为移动操作不应抛出异常，这有助于标准库在重新分配内存时选择移动而非拷贝，以获得强异常安全保证。

``` C++
class MyClass {
public:
    MyClass& operator=(MyClass&& other) noexcept; // 移动赋值运算符
};
```

移动赋值只会在对已有对象赋值的语境中被调用，注意与移动构造（初始化新对象）进行区分，例如：  

``` C++
std::vector<int> a = {1, 2, 3};
std::vector<int> b; // 初始化为空 vector
b = std::move(a); // 移动赋值：b 接管 a 的资源，a 变为空
```

编译器隐式声明移动赋值运算符（即**合成移动赋值运算符 synthesized move assignment operator**）的条件跟合成移动构造函数一样，需要类没有用户声明的拷贝构造函数、拷贝赋值运算符、移动构造函数、析构函数。也同样要注意浅拷贝的问题。

### 自定义移动赋值运算符
移动赋值运算符需要将源对象的资源转移给已有对象，同时释放目标对象的旧资源。示例还是以之前为基础：  

``` C++
class Buffer {
    // 数据成员、构造函数、析构函数、拷贝构造函数、拷贝赋值运算符、移动构造函数

    Buffer& operator=(Buffer&& other) noexcept {
        // 自赋值检测
        if (this == &other) {
            return *this;
        }

        // 释放当前旧资源
        delete[] data;

        // 窃取源对象的资源（浅拷贝指针），并将源对象置于“空”状态
        data = other.data;
        size = other.size;
        other.data = nullptr;
        other.size = 0;

        return *this;
    }
};
```

也可以直接使用交换的形式，或者使用 copy-and-swap 的移动版本：  

``` C++
class Buffer {
    // 数据成员、构造函数、析构函数、拷贝构造函数、拷贝赋值运算符、移动构造函数

    // 直接交换当前对象与源对象，源对象 other 随后析构时再释放旧资源
    Buffer& operator=(Buffer&& other) noexcept {
        swap(other);
        return *this;
    }

    // 或者使用移动构造临时对象，再与当前对象交换
    Buffer& operator=(Buffer&& other) noexcept {
        Buffer temp(std::move(other));
        swap(temp);
        return *this;
    }
};
```

## Rule of Three / Five
**三法则 rule of three** 指如果类需要自定义 C++ 98/03 标准支持的拷贝构造函数、拷贝赋值运算符和析构函数中的任何一个函数，那么你几乎肯定需要自定义这三个中的全部。三法则的底层逻辑在于浅拷贝与深拷贝之间的矛盾，假设类管理着一个动态资源，其中析构函数负责释放资源，如果拷贝构造函数使用合成拷贝构造函数，两个对象的指针成员将指向同一块内存，如果拷贝赋值运算符使用合成拷贝赋值运算符，不仅会内存泄漏（未释放旧资源），还会导致两个指针指向同一内存。只要析构需要释放资源，就意味着资源必须独占。独占资源就必须实现拷贝构造来深拷贝复制资源，和拷贝赋值来安全释放旧资源并复制新资源。

**五法则 rule of five** 之所以变成五，是因为 C++11 引入右值引用和移动语义，带来了移动构造函数和移动赋值运算符，于是法则变为了如果类需要自定义上述五种函数的任何一个，那么你几乎肯定需要自定义所有函数。五法则的底层逻辑在于编译器有一个非常反直觉的规则：<u>只要用户自定义了析构函数、拷贝构造函数或拷贝赋值运算符中的任意一个，编译器就不会隐式生成移动构造函数和移动赋值运算符</u>。这会导致，如果你为了释放资源写了析构函数，编译器会删除移动操作。此时，试图移动该对象将会退化调用昂贵的拷贝构造函数，为了享受移动语义的高效，既然你自定义了拷贝控制，就必须同时显式定义移动控制。

五法则背后 C++ 标准的特殊成员函数自动生成规则有如下：  
①析构抑制移动：这是五法则最核心的触发点，写了析构却忘记写移动，对象将失去移动能力；  
②移动删除拷贝：如果你只定义了移动构造而没有定义拷贝构造，编译器会删除拷贝构造。这意味着该类变成仅移动类型；  
③拷贝不抑制拷贝：定义了拷贝构造，拷贝赋值依然会生成（反之亦然），但会抑制移动。

| 用户显式声明 | 拷贝构造函数 | 拷贝赋值运算符 | 移动构造函数 | 移动赋值运算符 | 析构函数 |
| :---- | :---- | :---- | :---- | :---- | :---- |
| 无任何声明 | 自动生成 | 自动生成 | 自动生成 | 自动生成 | 自动生成 |
| 仅析构函数 | 自动生成 (deprecated) | 自动生成 (deprecated) | 不生成 | 不生成 | 用户定义 |
| 仅拷贝构造 | 用户定义 | 自动生成 | 不生成 | 不生成 | 自动生成 |
| 仅拷贝赋值 | 自动生成 | 用户定义 | 不生成 | 不生成 | 自动生成 |
| 仅移动构造 | 被删除 | 被删除 | 用户定义 | 自动生成 | 自动生成 |
| 仅移动赋值 | 被删除 | 被删除 | 自动生成 | 用户定义 | 自动生成 |

**零法则 rule of zero** 指理想情况下，任何自定义类都不应该自定义析构、拷贝或移动函数，而应该使用 RAII 类（如 std::vector、std::string、std::unique_ptr）作为成员，让编译器自动生成完美的拷贝/移动控制。

## default / delete
### default
我们可以通过将特殊成员函数定义为 `=default` 来显式地要求编译器生成合成的版本，例如：  

``` C++
class Widget {
public:
    Widget() = default; // 默认构造函数
    ~Widget() = default; // 析构函数
    Widget(const Widget&) = default; // 拷贝构造
    Widget& operator=(const Widget&) = default; // 拷贝赋值
    Widget(Widget&&) = default; // 移动构造
    Widget& operator=(Widget&&) = default; // 移动赋值
};
```

`=default` 常用于恢复被抑制的默认函数。

### delete
我们也可以在函数声明后加上 `=delete`，将函数定义为删除的函数，任何试图调用它的代码都会产生编译错误，例如：  

``` C++
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;            // 禁止拷贝构造
    NonCopyable& operator=(const NonCopyable&) = delete; // 禁止拷贝赋值
};
```

`delete` 可以作用于任意函数，不仅是特殊成员。另外，可通过删除析构函数强制对象只能在堆上构造，需配合 new 和自定义释放函数，但通常不推荐。

### 合成特殊成员函数被删除
C++ 标准规定：合成的特殊成员函数在无法生成有意义的实现时，会被隐式定义为删除 deleted。这种删除是递归性的，编译器会检查类中的所有非静态数据成员和直接基类，只要其中任何一个成员的对应特殊操作不可用（不存在、被 delete 或不可访问），编译器就会将合成的特殊成员函数标记为 deleted。具体如下表：  

| 特殊成员函数 | 被删除的情况 |
| :---- | :---- |
| 默认构造 | ①成员/基类无默认构造；②有 const 或引用成员且未初始化 |
| 析构函数 | ①成员/基类的析构函数被删除或不可访问（private）|
| 拷贝构造 | ①成员/基类不可拷贝构造；②成员/基类析构函数不可用；③用户自定义了移动操作 | 
| 拷贝赋值 | ①成员/基类不可拷贝赋值；②成员/基类析构函数不可用；③有 const 或引用成员 |
| 移动构造 | ①成员/基类不可移动构造；②成员/基类析构函数不可用；③用户自定义了拷贝操作 |
| 移动赋值 | ①成员/基类不可移动赋值；②成员/基类析构函数不可用；③用户自定义了拷贝操作；④有 const 或引用成员 |

## 成员函数的引用限定符
成员函数的**引用限定符 reference qualifier**，在成员函数声明的参数列表之后加 `&` 或 `&&`（const 之后，override / final 之前），用来限定 `*this` 的左值/右值属性。`&` 表示该函数只能被左值对象调用（`*this` 是左值），`&&` 表示该函数只能被右值对象调用（`*this` 是右值，通常是临时对象），例如：  

``` C++
class Widget {
public:
    void doWork() &  { std::cout << "调用于左值对象\n"; }
    void doWork() && { std::cout << "调用于右值对象\n"; }
};

int main() {
    Widget w;
    w.doWork();        // 调用 &  版本（w 是左值）
    Widget().doWork(); // 调用 && 版本（临时对象是右值）
}
```

因为不管对象是一个左值还是一个右值，都可以在对象上调用成员函数。引用限定符存在的最大价值就是防止右值对象调用成员函数所引发的问题，比如：  

``` C++
class Buffer {
    std::vector<int> data_;
public:
    // 没有限定符，左值右值都能调用
    const std::vector<int>& data() const { return data_; } 
};

void test() {
    // 危险！临时对象销毁后，返回的引用悬垂。ref 此时指向已销毁的内存，未定义行为
    const std::vector<int>& ref = Buffer().data(); 
}
```

建议写为：  

``` C++
class Buffer {
    std::vector<int> data_;
public:
    // 对左值对象：返回可修改的引用（允许修改原对象）
    std::vector<int>& data() & { return data_; }
    
    // 对 const 左值对象：返回 const 引用（只读）
    const std::vector<int>& data() const & { return data_; }

    // 对右值对象：将数据移出（省去拷贝，且避免悬垂）
    std::vector<int> data() && { return std::move(data_); }
};
```

这也是常见的 getter 写法。

## 运算符重载
重载声明是指一个与之前已经在该作用域内声明过的函数或方法具有相同名称的声明，但是它们的参数列表不相同。而运算符是具有特殊名字的函数，它们的名字由关键字 `operator` 和其后要定义的运算符号共同组成。**运算符重载 operator overloading** 可以通过<u>定义特殊成员函数或非成员函数</u>来实现，与其他函数一样，重载的运算符有返回类型、参数列表和函数体，例如：  

``` C++
class Complex {
    double real, imag;
public:
    Complex operator+(const Complex& other) const; // 成员函数
};

Complex operator+(const Complex& lhs, const Complex& rhs); // 或者作为非成员函数
```

如上所示，重载运算符函数的参数数量与该运算符作用的运算对象数量一样多。一元运算符有一个参数，二元运算符有两个。对于二元运算符来说，左侧运算对象传递给第一个参数，而右侧运算对象传递给第二个参数。如果一个运算符函数是成员函数，则它的左侧运算对象绑定到隐式的 `this` 指针上。

重载不能改变优先级、结合性、操作数个数。运算符至少一个操作数是用户定义类型，所以当运算符作用于内置类型的运算对象时，我们无法重载，比如不能重载 `int + int`。运算符作为成员函数时，左操作数必须是当前类的对象（因为 `this` 指针），所以需要支持左操作数为内置类型或其他类型时，例如 `2 + Complex`，必须将 `+` 重载为非成员，使得第一个参数可以是 int。流插入和提取运算符 `<<` 和 `>>` 必须是非成员，因为左操作数是 `std::ostream` 或 `std::istream`。另外，`=`、`[]`、`()`、`->` 和类型转换运算符（后面会提到）要求左操作数是该类对象，必须是成员运算符函数。

我们可以重载大多数运算符，下面是可重载的运算符列表：  

|  |  |  |  |  |  |
| :---- | :---- | :---- | :---- | :---- | :---- |
| + | - | * | / | % | ^ |
| & | &#124; | ~ | ! | , | = |
| &lt; | &gt; | &lt;= | &gt;= | ++ | -- |
| &lt;&lt; | &gt;&gt; | == | != | && | &#124;&#124; |
| += | -= | &lt;&lt;= | &gt;&gt;= | \[ \] | \( \) |
| -&gt; | -&gt;* | new | new\[ \] | delete | delete\[ \] |

不能被重载的运算符有：

|  |  |  |  |  |  |  |
| :---- | :---- | :---- | :---- | :---- | :---- | :---- |
| :: | .* | . | ?: | sizeof | alignof | typeid |

运算符除了普通的调用形式外，还可以像调用普通函数一样直接调用运算符函数，如下：  

``` C++
data1 + data2; // 普通的表达式
operator+(data1, data2); // 等价的非成员运算符函数调用
data1.operator+=(data2); // 等价的成员运算符函数调用
```

### 流插入和提取运算符
流插入运算符 `<<` 和流提取运算符 `>>` 的第一个形参分别是非常量的 ostream 对象引用和 istream 对象引用，所以必须是非成员函数，第二个形参是要打印或者写入的类类型。又因为 IO 运算符常常需要读取类的私有成员，故一般会声明为友元以便访问私有成员，如下：  

``` C++
class Complex {
    double real, imag;
public:
    friend std::ostream& operator<<(std::ostream& os, const Complex& c);
    friend std::istream& operator>>(std::istream& is, Complex& c);
};
std::ostream& operator<<(std::ostream& os, const Complex& c) {
    os << c.real << " + " << c.imag << "i";
    return os;
}
std::istream& operator>>(std::istream& is, Complex& c) {
    is >> c.real >> c.imag;
    return is;
}
```

### 算术运算符
`+`、`-`、`*`、`/`、`%`，通常返回一个新对象，不修改操作数，建议声明为 const，例如：  

``` C++
class Complex {
    double real, imag;
public:
    Complex operator+(const Complex& other) const {
        return Complex(real + other.real, imag + other.imag);
    }

    friend Complex operator+(const Complex& c, double d); // 支持 Complex + double
    friend Complex operator+(double d, const Complex& c); // 支持 double + Complex
};

Complex operator+(const Complex& c, double d) {
    return Complex(c.real + d, c.imag);
}
Complex operator+(double d, const Complex& c) {
    return Complex(d + c.real, c.imag);
}
```

### 赋值运算符
`=`、`*=`、`/=`、`%=`、`+=`、`-=`、`&=`、`^=`，除了 `=` 必须定义为成员函数外，其他复合赋值运算符不非得是类的成员，不过我们还是倾向于把包括复合赋值在内的所有赋值运算都定义在类的内部。赋值运算符通常修改左操作数，返回左操作数的引用 `*this`，以支持链式赋值，例如：  

``` C++
class Complex {
public:
    Complex& operator+=(const Complex& other) {
        real += other.real;
        imag += other.imag;
        return *this;
    }
};
```

### 关系运算符
`<`、`>`、`<=`、`>=`、`==`、`!=`，返回 bool，通常不修改对象，建议声明为 const 成员函数，例如：  

``` C++
class Complex {
public:
    bool operator==(const Complex& other) const {
        return real == other.real && imag == other.imag;
    }
    bool operator!=(const Complex& other) const { 
        return !(*this == other); 
    }
};
```

### 下标运算符
表示容器的类通常可以通过元素在容器中的位置访问元素，这些类一般会定义下标运算符 `operator[]`，下标运算符必须是成员函数。通常提供 const 和非常量两个版本，当作用于一个常量对象时，下标运算符返回常量引用以确保我们不会给返回的对象赋值，例如：  

``` C++
class Vector {
    int* data;
    size_t size;
public:
    int& operator[](size_t index) { return data[index]; }
    const int& operator[](size_t index) const { return data[index]; }
};
```

### 递增和递减运算符
C++ 语言并不要求递增和递减运算符必须是类的成员，但是因为它们改变的正好是所操作对象的状态，所以建议将其设定为成员函数。同时，要注意区分前置和后置运算符，后置版本接受一个额外的（不被使用）int 类型的形参。这个形参的唯一作用就是区分前置版本和后置版本的函数，而不是真的要在实现后置版本时参与运算。另外，为了与内置版本保持一致，后置运算符应该返回对象的原值（递增或递减之前的值），返回的形式是一个值而非引用。

``` C++
class Counter {
    int count;
public:
    Counter& operator++() { // 前缀 ++
        ++count;
        return *this;
    }
    Counter operator++(int) { // 后缀 ++，int 参数仅作区分
        Counter old = *this; // 记录当前的值
        ++(*this); // 复用前缀
        return old;
    }
};
```

### 成员访问运算符
在迭代器类及智能指针类中常常用到解引用运算符 `*` 和箭头运算符 `->`，箭头运算符必须是类的成员，解引用运算符通常也是类的成员，尽管并非必须如此。示例如下：  

``` C++
class StringWrapper {
    std::string s;
public:
    StringWrapper(const std::string& str) : s(str) {}

    std::string& operator*() { // operator* ：返回引用用于整体操作（比如整体赋值）
        return s;
    }
    std::string* operator->() { // operator-> ：返回指针用于访问成员（比如调用成员函数）
        return &s;
        // return & this->operator*(); // 也可以使用解引用运算符并取地址
    }
};
```

### 函数调用运算符
如果类重载了函数调用运算符 `()`，则我们可以像使用函数一样使用该类的对象，且函数调用运算符必须是成员函数，例如：  

``` C++
struct absInt {
    int operator()(int val) const {
        return val < 0 ? -val: val;
    }
};

int i = -42;
absInt absObj;
int ui = absObj(i);
```

如果类定义了调用运算符，则该类的对象称作**函数对象 function object**，因为可以调用这种对象，所以我们说这些对象的行为像函数一样。lambda 表达式本质就是函数对象，当我们编写了一个 lambda 后，编译器将该表达式翻译成一个未命名类的未命名对象，在 lambda 表达式产生的类中含有一个重载的函数调用运算符。默认情况下 lambda 不能改变它捕获的变量。因此在默认情况下，由 lambda 产生的类当中的函数调用运算符是一个 const 成员函数。如果 lambda 被声明为可变的 mutable，则调用运算符就不是 const 的了。lambda 表达式产生的类不含默认构造函数、赋值运算符及默认析构函数，它是否含有默认的拷贝/移动构造函数则通常要视捕获的数据成员类型而定。

另外，标准库定义了一组表示算术运算符、关系运算符和逻辑运算符的类，每个类分别定义了一个调用运算符，下表所列的类型定义在 functional 头文件中：

### 类型转换运算符
**类型转换运算符 conversion operator** 是类的一种特殊成员函数，它允许类隐式或显式转换为其他类型。类型转换函数必须是类的成员函数，它不能声明返回类型，形参列表也必须为空，通常不应该改变待转换对象的内容，故一般为 const 成员函数，其一般形式为：`operator type() const;`。其中 type 表示要转换成为的类型，但不允许转换成数组或者函数类型，可以是指针和引用类型。示例如下：  

``` C++
class Rational {
    int num, den;
public:
    operator double() const { return static_cast<double>(num) / den; }
};
Rational r(1, 2);
double d = r; // 隐式转换为 0.5
```

为了防止隐式转换产生意外，C++ 11 引入了**显式的类型转换运算符 explicit conversion operator**，即加上 `explicit` 要求必须通过显式的强制类型转换执行类型转换：`explicit operator type() const`。

# 第十章 类与继承
## 面向对象编程 OOP
**面向对象编程 object-oriented programming (OOP)** 是一个围绕在**类 class** 与**对象 object** 周围的基本概念，包含四个特征：**抽象 abstraction**、**封装 encapsulation**、**继承 inheritance** 和**多态 polymorphism**：  

**①抽象 abstraction**：抽象或数据抽象是一种依赖于**接口 interface** 和**实现 implementation** 分离的编程技术，只向外界展示外部接口，隐藏具体实现细节。类的接口包括用户所能执行的操作，类的实现则包括类的数据成员、负责接口实现的函数体以及定义类所需的各种私有函数；  

**②封装 encapsulation**：实现了类的接口和实现的分离，封装后的类隐藏了它的实现细节，类的用户只能使用接口而无法访问实现部分。使用**私有 private** 和**受保护 protected** 隐藏实现，使用**公有 public** 供外部访问；  

**③继承 inheritance**：继承可以让一个类（**子类 subclass** 或**派生类 derived class**）获得另一个类（**基类 base class** 或**超类 superclass**）的属性和方法，实现代码复用，并建立层级关系。

**④多态 polymorphism**：即一个接口，多种实现，又可以被分为两种：**运行时多态 run-time polymorphism** 或**动态多态 dynamic polymorphism** 通过**虚函数 virtual function** 实现；**编译时多态 compile-time polymorphism** 或**静态多态 static polymorphism** 通过函数重载或模板实现。

## 派生类
**继承 inheritance** 允许一个类（派生类/子类）获得另一个类（基类/父类/超类）的属性和方法，实现代码复用并建立 is-a 关系，但基类的构造函数、析构函数、拷贝构造函数、移动构造函数、重载运算符和友元函数不会被继承。并且，派生类对象中的数据是基类对象数据的超集，即派生类通常比基类更大，因为包含了更多的数据和函数。

派生类必须通过使用**类派生列表 class derivation list** 明确指出它是从哪个或哪些基类继承而来的。类派生列表的形式是：首先是一个冒号，后面紧跟以逗号分隔的基类列表，其中每个基类前面可以有以下三种访问说明符中的一个：public、protected 或者 private（如果未使用访问修饰符，则默认为 private，结构体默认 public 继承），例如：  

``` C++
class Animal { };
class Dog : public Animal { };
```

### 访问控制
第八章 - [类的基本概念](#类访问修饰符)中介绍过一个类的成员可以是**私有的 private**、**受保护的 protected** 或者**公有的 public**：  
①如果成员是私有的，仅可被声明它的类的成员函数和友元函数使用；  
②如果成员是受保护的，可被声明它的类的成员函数和友元函数使用，也可以被继承自该类的派生类中的成员函数和友元函数使用；  
③如果成员是公有的，可被任何函数使用。

<u>派生类对其继承而来的成员的访问权限受到两个因素影响：一是在基类中该成员的访问说明符，二是在派生类的派生列表中的访问说明符。</u>类派生列表中的访问说明符决定了基类中的成员在派生类中变成什么访问级别，最终权限为基类该成员原有的权限与继承方式取交集（看谁更严格）。所以本质上来说，类派生列表中的访问说明符对派生类成员（或友元函数）是否能访问基类成员没有影响，对基类成员的访问权限只与基类中的访问说明符有关。类派生列表中的访问说明符的目的是控制派生类的派生类对于基类成员的访问权限。

比如，**public 继承**（最为常用），外部代码可以访问派生类中的基类的 public 成员；派生类的派生类也可以访问基类的 public 和 protected 成员；**protected 继承**，外部代码无法访问基类的任何成员，派生类的派生类仍然可以访问基类的 public 和 protected 成员；**private 继承**则让外部代码和派生类的派生类都无法访问基类的成员，因为它们在派生类中变成私有的了。

### 继承中的类作用域
每个类都有自己的作用域，类的成员位于作用域内，当存在继承关系时，<u>派生类的作用域嵌套在其基类的作用域之内</u>。这意味着编译器在查找一个成员名称时，会从最内层（派生类）向最外层（基类）逐层向上搜索，直到找到第一个匹配项为止。

和其他作用域一样，派生类也能重用定义在其直接基类或间接基类中的成员，此时定义在内层作用域（即派生类）的成员将**隐藏 hiding** 定义在外层作用域（即基类）的成员，注意是隐藏不是重载！！！由于作用域是嵌套的，无论参数列表是否相同，派生类中的名称都会隐藏基类中同名的名称，而不是像函数重载那样在同一作用域内共存。编译器一旦在派生类作用域找到了名字，就不会再向上查找，即使派生类中的函数参数不匹配，编译器也不会去基类寻找匹配的重载版本，而是直接报错。

``` C++
class Base {
public:
    void func(int x) { std::cout << "Base int"; }
    void func(double x) { std::cout << "Base double"; }
};

class Derived : public Base {
public:
    void func(const std::string& s) { std::cout << "Derived string"; }
};

int main() {
    Derived d;
    d.func(10); // 编译错误！不是重载而是隐藏，编译器发现无法用 int 匹配 string，于是报错。
    d.Base::func(10); // 正确：使用作用域限定符强制查找基类
}
```

### using 基类成员
有时需要改变派生类从基类继承来的<u>非私有</u>成员的访问权限，可以通过 `using` 声明来实现。using 声明语句中成员的访问权限由该 using 声明语句之前的访问说明符来决定。也就是说，如果一条 using 声明语句出现在类的 private 部分，则该名字只能被类的成员和友元函数访问；如果 using 声明语句位于 public 部分，则类的所有用户都能访问它；如果 using 声明语句位于 protected 部分，则该名字对于成员、友元函数和派生类是可访问的。示例如下：  

``` C++
class Base {
protected:
    int m_value = 10;
public:
    void func1() {}
    void func2() {}
};

class Derived : private Base { // private 继承
public:
    using Base::m_value; // 将 m_value 提升为 public
    using Base::func1; // 将 func1 恢复为 public
protected:
    using Base::func2; // 将 func2 恢复为 protected
};
```

### 友元类与继承
基类的友元类在访问派生类新定义的成员时不具有特殊性，但可以访问从基类继承来的成员。因为基类的友元类本质上拥有访问基类所有成员（包括 private 和 protected）的权限。当派生类继承这些成员时，无论通过派生类对象还是基类对象访问，这些成员依然属于基类的作用域。因此，基类的友元类完全可以通过派生类对象，访问到派生类从基类继承下来的 protected 或 private 成员，例如：  

``` C++
class Base {
protected:
    int base_protected = 1; // 基类的保护成员
private:
    int base_private = 2; // 基类的私有成员
public:
    friend class FriendOfBase;
};

class Derived : public Base {
private:
    int derived_private = 3; // 派生类新增的私有成员
};

class FriendOfBase { // 声明一个类作为 Base 的友元
public:
    void test(Base& b, Derived& d);
};

void FriendOfBase::test(Base& b, Derived& d) {
    // 1. 访问基类自己的成员：可以（因为是基类的友元）
    int a1 = b.base_protected; // 正确
    int a2 = b.base_private;   // 正确

    // 2. 访问派生类对象中“继承自基类”的成员：可以！
    int a3 = d.base_protected; // 正确（该成员属于 Base 的作用域）
    int a4 = d.base_private;   // 正确（该成员属于 Base 的作用域）

    // 3. 访问派生类“自己新增”的成员：不可以！
    // int a5 = d.derived_private; // 错误！FriendOfBase 不是 Derived 的友元
}
```

类似的，派生类的友元类也不能随意访问基类的成员，因为友元关系是不可继承的，这个的示例我就不放出来了。  

### 静态成员与继承
静态成员属于类本身，而不属于类的对象，在整个继承层级中，它只存在唯一实例。无论基类被派生多少次，无论有多少个派生类对象，基类中定义的静态成员变量在内存中只有一份，所有派生类共享这一份数据。虽然静态成员只有一份，但它的可见性完全受继承方式和访问说明符控制，规则与普通成员完全一致。

``` C++
class Base {
public:
    static int s_count;
};
int Base::s_count = 10; // 静态成员必须在类外单独定义并初始化
class Derived1 : public Base {};
class Derived2 : public Base {};

int main() {
    Derived1::s_count = 20;
    std::cout << Derived2::s_count << std::endl; // 输出 20（同一份）
}
```

另外，静态成员函数不能声明为虚函数 virtual（虚函数见后面小节），因此无法被派生类覆写 override。如果派生类定义了一个同名静态函数，这叫做隐藏 hiding，而不是覆盖。

## 虚函数与多态
### 虚函数
基类需将它的两种成员函数区分开来：一种是基类希望其派生类进行覆盖的函数，另一种是基类希望派生类直接继承而不要改变的函数。对于前者，基类通常将其定义为**虚函数 virtual**，它允许程序在运行时，根据对象的实际类型（而非指针或引用的表面类型）来决定调用哪个函数，这种行为被称为**动态绑定 dynamic binding**。虚函数是实现**运行时多态 run-time polymorphism** 的核心机制，允许使用基类指针或引用来调用子类的重写方法，从而使得同一接口可以表现不同的行为。

虚函数声明时需在类成员函数的返回类型之前使用 `virtual` 关键字。virtual 只能出现在类内部的声明语句之前而不能用于类外部的函数定义。如果基类把一个函数声明成虚函数，则该函数在派生类中隐式地也是虚函数。如果想要声明**纯虚函数 pure virtual function**，在声明末尾加上 `= 0`，例如：  

``` C++
class Base {
public:
    virtual void func1(); // 1. 普通虚函数
    virtual void func2() = 0; // 2. 纯虚函数
    virtual ~Base() {} // 3. 虚析构函数（即使函数体为空，也要声明，后面构造函数与拷贝控制小节也会提及）
};

void Base::func1() { // 类外定义实现（注意：此处不能加 virtual）
    std::cout << "Base::func1" << std::endl;
}
```

派生类可以在它覆盖的函数前使用 `virtual` 关键字，但不是非得这么做。派生类想要**覆写 override** 基类的虚函数，必须同时满足以下条件，缺一不可，否则就是**隐藏 hiding** 而非覆写：函数名相同、参数列表相同、返回类型相同（除非是<u>协变返回类型</u>）、const 或引用限定符相同。为了解决手写覆写容易出错的问题，C++ 11 引入了 `override` 关键字，显式告诉编译器要覆写基类虚函数，如果签名不符合要求，编译直接报错，而不是静默地变成隐藏。override 需放在形参列表后面，若有 const 和引用限定符，则在 const 和引用限定符后面。

``` C++
class Base {
    virtual void foo(int x);
};

class Derived : public Base {
    void foo(int x) override;
};
```

**协变返回类型 covariant return type** 是唯一允许返回类型不同的特例。如果基类虚函数返回 `Base*` 或 `Base&`，派生类覆写时可以返回 `Derived*` 或 `Derived&`，例如：  

``` C++
class Base {
    virtual Base* clone() const { return new Base(*this); }
};

class Derived : public Base {
    // 返回类型由 Base* 变为 Derived*，这是合法的覆写
    virtual Derived* clone() const override { return new Derived(*this); }
};
```

我们也可以在派生类覆盖的虚函数中调用基类的虚函数，因为基类的版本通常需要完成继承层次中所有类型都要做的共同任务：  

``` C++
class Base {
public:
    virtual void show() {
        std::cout << "Base::show()" << std::endl;
    }
};

class Derived : public Base {
public:
    void show() override {
        Base::show(); // 使用作用域限定符显式调用基类的 show() 版本
        std::cout << "Derived::show()" << std::endl;
    }
};
```

### 绑定
之前提到**动态绑定 dynamic binding**，也称为**运行时绑定 runtime binding**，那么什么是绑定？**绑定 binding** 是指将程序中的函数调用语句与实际要执行的函数体代码（内存地址）关联起来的过程。根据这个过程发生在编译阶段还是运行阶段，我们分为静态绑定和动态绑定。

**静态绑定 static binding** 发生在编译阶段，编译器遇到函数调用时，根据调用对象的声明类型和函数名及参数，通过重载决议选出唯一匹配的函数。然后，编译器将该函数的修饰后名称嵌入到目标文件的调用指令中。同时，在链接期时，链接器将目标文件中的符号引用直接重定位为绝对地址或相对偏移。普通成员函数（非 virtual）、函数重载、运算符重载以及模板实例化都属于静态绑定。

**动态绑定 dynamic binding** 发生在运行阶段，依赖**虚函数表 vtable** 和**虚指针 vptr**，当一个类声明了虚函数，编译器会为这个类生成一张虚函数表（函数地址数组），每个对象在构造时，在内存前部都会被编译器隐式地安插一个指向该类虚函数表的指针 vptr。通过基类指针或引用调用虚函数时，程序先取出对象的 vptr，再索引虚表找到对应函数的实际地址，最后跳转执行，整个过程有轻微的内存和性能开销。

动态绑定必须是 virtual 虚函数，也必须通过<u>基类</u>的指针 `*` 或引用 `&` 来调用，如果直接用基类对象（而非指针/引用）赋值，会发生**对象切片 object slicing**，丢失派生类信息，从而退化为静态绑定。另外，用派生类指针（或对象）调用相当于普通成员函数调用。

``` C++
class Base {
public:
    virtual void func() { std::cout << "Base" << std::endl; }
};

class Derived : public Base {
public:
    void func() override { std::cout << "Derived" << std::endl; }
};

int main() {
    Derived d;
    Base* p = &d; // 派生类到基类的类型转换，详见下面类型转换与继承小节
    Base q = d; // 对象切片
    p->func(); // 动态绑定，输出 "Derived"
    d.func(); // 静态绑定，输出 "Derived"
    q.func(); // 静态绑定，输出 "Base"
}
```

还有一点要注意的是，调用虚函数时，函数体是动态绑定的，但函数的默认参数值却是静态绑定：  

``` C++
class Base {
public:
    virtual void test(int num = 10) { std::cout << "Base: " << num << std::endl; }
};

class Derived : public Base {
public:
    void test(int num = 20) override { std::cout << "Derived: " << num << std::endl; }
};

int main() {
    Base* p = new Derived();
    p->test(); // 输出：Derived: 10，函数体调用了 Derived 的（动态绑定），但 num 参数取自 Base 类定义的默认值 10（静态绑定）
    delete p;
}
```

底层原因是，默认参数值在编译期根据指针的声明类型被压入函数调用栈，不受运行时动态类型影响。所以最佳实践是绝对不要在虚函数中使用默认参数。

### RTTI
**动态类型 dynamic type** 指的是程序在运行时，指针或引用所实际指向的对象类型，可以被改变。**静态类型 static Type** 指变量在编译时就确定的类型，在它的声明中写明，且不会改变。如果表达式既不是引用也不是指针，则它的动态类型永远与静态类型一致。动态类型是 C++ 实现动态绑定或运行时多态的基石。

**运行时类型识别 Runtime Type Identification (RTTI)** 是 C++ 中的一项机制，它允许程序在运行时获取对象的动态类型（实际类型信息）。在 C++ 的静态类型系统中，变量的类型通常在编译时就已经确定。然而，当使用基类的指针或引用来操作派生类对象时（即多态场景），编译器在编译时无法确切知道这个指针或引用指向的具体是哪个派生类对象，RTTI 正是为了解决这个问题而设计的。C++ 通过两个主要的操作符来提供 RTTI 功能：  

①`typeid` 运算符，它用于获取一个对象或类型的类型信息。它返回一个 `std::type_info` 对象的常量引用，其中包含了该类型的相关信息，对于多态类型 typeid 会返回其实际派生类的类型信息，对于非多态类型，typeid 返回的是其静态类型（即编译时声明的类型）的信息，例如：  

``` C++
class Base { public: virtual ~Base() {} };
class Derived : public Base {};

int main() {
    Base* ptr = new Derived();
    std::cout << typeid(*ptr).name() << std::endl; // 对多态类型，typeid 返回实际类型 Derived
    std::cout << typeid(ptr).name() << std::endl; // 对非多态类型，typeid 返回静态类型 Base
    delete ptr;
}
```

②`dynamic_cast` 运算符，主要用于在继承层次结构中进行安全的**向下转型 downcast**，即将基类指针或引用转换为派生类指针或引用。对于指针，如果转换成功，返回目标类型的指针，如果失败，返回 nullptr；对于引用，如果转换成功，返回目标类型的引用，如果失败，会抛出 `std::bad_cast` 异常。注意，dynamic_cast 只能用于多态类型（即类至少有一个虚函数），例如：  

``` C++
class Base { public: virtual ~Base() {} };
class Derived : public Base {};

int main() {
    Base* basePtr = new Derived();
    Derived* derivedPtr = dynamic_cast<Derived*>(basePtr); // 安全向下转型
}
```

RTTI 的实现与虚函数表机制紧密相连，RTTI 信息通常存储在类的虚表中。当对多态对象使用 typeid 时，编译器通过对象的 vptr 找到虚表，进而访问到存储的 RTTI 数据，从而得知对象的真实类型。实现 dynamic_cast 需要检查目标类型是否在对象的继承体系中，这涉及遍历 RTTI 数据中存储的继承关系信息（如单继承、多继承、虚继承等），以确定转换是否合法。

RTTI 有一定的性能开销，一些编译器提供了选项来禁用 RTTI，禁用后，dynamic_cast 和 typeid 将不可用或行为未定义。

### 抽象类
上面提到过**纯虚函数 pure virtual function**，在虚函数声明的结尾加上 `= 0` 表示不提供具体实现，它定义了一个接口规范，让派生类覆写这个函数。含有（或者未覆盖直接继承）纯虚函数的类就是**抽象类 abstract class**，抽象类不能被实例化，只能作为基类被其他类继承，它的核心作用是为一组相关的类定义通用的接口和规范。派生类必须实现基类中所有的纯虚函数，否则它自身也成为一个抽象类。

C++ 没有专门的 interface 关键字。通常，一个所有成员函数都是纯虚函数、且没有任何成员变量的抽象类，就被当作接口 interface 使用。而更宽泛的抽象类则可以包含已实现的成员函数和成员变量，提供部分通用功能。

``` C++
class Shape { // 抽象类（里面有纯虚函数）
public:
    virtual void draw() = 0; // 纯虚函数，这里不写具体代码
};

class Circle : public Shape {
public:
    void draw() override {
        std::cout << "Circle draw" << std::endl;
    }
};
```

### final
C++ 11 提供了 `final` 关键字，防止继承的发生，可以作用于类或虚函数：  

**①禁止类被继承**，当 final 放在类名后面时，表示该类不允许被作为基类，即不能有派生类：  

``` C++
class Base final { }; // 若试图继承 final 类，编译错误
```

**②禁止虚函数被覆写**，当 final 放在虚函数的参数列表和函数体（或 `=0`）之间时，表示该虚函数在后续的任何派生类中都不允许被重写：  

``` C++
class Derived: public Base {
public:
    void foo() override final { std::cout << "foo"; } // 禁止后续重写
};
```

final 重要的底层价值在于**去虚拟化 de-virtualization**，虚函数通过虚函数表间接调用，存在性能开销，并且会阻止内联。当编译器看到类或函数标记为 final 时，它知道没有派生类会重写该函数，因此在编译时，如果对象类型明确（非基类指针/引用），编译器可以进行静态绑定直接调用地址，甚至内联 inline 展开代码，显著提升高频调用场景下的性能。

### 虚函数指针
在第八章 - 类的基本概念提过[成员指针](#成员指针)，指向虚成员函数的指针同样有效，调用时会触发动态绑定，例如：  

``` C++
class Base {
public:
    virtual void foo() { std::cout << "Base\n"; }
};
class Derived : public Base {
public:
    void foo() override { std::cout << "Derived\n"; }
};

void (Base::*pFoo)() = &Base::foo;
Derived d;
Base* pBase = &d;
(pBase->*pFoo)(); // 输出 "Derived"（多态生效）
```

但有一点要注意，指向基类成员的指针可以隐式转换为指向派生类同名成员的指针，指向派生类成员的指针不能隐式转换为指向基类成员的指针（这个规则看似与派生类指针可以隐式转换为基类指针相反，但逻辑是一样的，详见下面[类型转换与继承](#类型转换与继承)），例如：  

``` C++
void (Base::*pbFoo)() = &Base::foo;
void (Derived::*pdFoo)() = pbFoo; // 正确：基类 -> 派生类

// void (Base::*pbFoo2)() = pdFoo; // 错误：派生类 -> 基类
```

## 构造函数、拷贝控制与继承
### 构造函数
当创建一个派生类对象时，<u>基类的构造函数一定会先于派生类的构造函数体执行</u>，因为派生类对象在内存布局上包含了基类的子对象。如果基类有默认构造函数（无参或全缺省参数），派生类构造函数可以不显式调用，编译器会自动插入对基类默认构造函数的调用。如果基类只有带参数的构造函数，即没有默认构造函数，派生类必须在成员初始化列表中显式调用基类的某个构造函数，例如：  

``` C++
class Base {
public:
    Base(int x) { cout << "Base(int)" << endl; } // 无默认构造
};

class Derived : public Base {
public:
    Derived(int a) : Base(a) { cout << "Derived(int)" << endl; }
};
```

还有一点需要注意：<u>不要在构造函数中调用虚函数</u>，因为在构造函数内部，运行时绑定是失效的。当构造 Derived 对象时，先构造基类 Base。此时 Derived 部分尚未构建完成，为了安全，编译器将当前对象的 vptr 指向 Base 的 vtable，因此 Base 构造函数中绑定的永远是 Base 的虚函数。

C++ 11 引入了**继承构造函数 inheriting constructor**，即通过 `using Base::Base;` 让派生类继承基类构造函数：  

``` C++
class Base {
public:
    Base(int a) {}
    Base(double b) {}
    Base(int a, double b) {}
};

class Derived : public Base {
public:
    using Base::Base; // 自动生成 Derived(int), Derived(double), Derived(int, double)
};
```

和普通成员的 using 声明不一样，一个构造函数的 using 声明不会改变该构造函数的访问级别。例如，不管 using 声明出现在哪儿，基类的私有构造函数在派生类中还是一个私有构造函数，受保护的构造函数和公有构造函数也是同样的规则。

`using Base::Base;` 并不会继承基类的所有构造函数，默认构造函数、拷贝构造函数、移动构造函数都不会被继承。同时，派生类可以继承一部分构造函数，而为其他构造函数定义自己的版本。如果派生类定义的构造函数与基类的构造函数具有相同的参数列表，则该构造函数将不会被继承，定义在派生类中的构造函数将替换继承而来的构造函数。

当一个基类构造函数含有默认实参时，这些实参也不会被继承。相反，派生类将获得多个继承的构造函数，其中每个构造函数分别省略掉一个含有默认实参的形参。例如，如果基类有一个接受两个形参的构造函数，其中第二个形参含有默认实参，则派生类将获得两个构造函数：一个构造函数接受两个形参（没有默认实参），另一个构造函数只接受一个形参，它对应于基类中最左侧的没有默认值的那个形参。

### 析构函数
当派生类对象销毁时，<u>析构函数的调用顺序是构造函数调用顺序的逆过程</u>，先派生类析构函数体执行，再派生类的成员对象析构（按声明顺序的逆序销毁），然后再执行基类析构函数体，如果有多继承，按继承声明顺序的逆序销毁。

<u>基类通常都应该定义一个虚析构函数，即使该函数不执行任何实际操作也是如此</u>。这是因为，若基类指针指向派生类对象，当指针销毁执行析构函数时，有可能出现指针的静态类型与被删除对象的动态类型不符的情况。比如，用 `Base*` 指针去 `delete` 一个 `Derived` 对象，如果 `Base` 的析构函数不是 `virtual`，编译器只会调用 `Base::~Base()`，而不会调用 `Derived::~Derived()`。所以我们需要在基类中将析构函数定义成虚函数以确保执行正确的析构函数版本：  

``` C++
class Base {
public:
    ~Base() { std::cout << "Base destructor\n"; } // 非虚
    // virtual ~Base() { std::cout << "Base destructor\n"; } // 虚析构函数
};

class Derived : public Base {
    int* arr;
public:
    Derived() : arr(new int[100]) {}
    ~Derived() { delete[] arr; std::cout << "Derived destructor\n"; }
};

int main() {
    Base* p = new Derived();
    delete p; // 输出仅：Base destructor，arr 数组内存泄漏（未调用 ~Derived）
}
```

还有几点需要注意：①<u>基类最好不要有纯虚析构函数 `virtual ~Base() = 0;`，如果有，也必须为纯虚析构函数提供函数体（通过在类外定义）</u>。因为派生类析构时，无论如何都会隐式调用基类的析构函数，如果基类析构函数是纯虚的且没有实现，链接器会报错 undefined reference。②跟构造函数一样，<u>不要在析构函数中调用虚函数</u>，原因类似，运行时绑定失效，在构造时，vptr 会随着构造函数层级逐层向下覆盖（Base 设成 Base 表，Derived 设成 Derived 表）。析构时，vptr 会逆向往回重置：当 Derived 析构函数体执行完毕，进入成员变量析构阶段后，编译器会将 vptr 重新指向 Base 的 vtable。

另外，基类需要一个虚析构函数这一事实还会对基类和派生类的定义产生另外一个间接的影响：只要用户自定义了析构函数，编译器就不会隐式生成移动构造函数和移动赋值运算符。

### 拷贝构造函数
对于拷贝构造函数，建议<u>派生类的拷贝构造函数必须显式调用基类的拷贝构造函数</u>，否则，基类子对象会被默认构造，导致部分拷贝或数据丢失，例如（代码中 Derived 的拷贝构造函数调用基类拷贝构造函数 `Base(d)`，会将 Derived 对象 d 的基类部分切片后传入 Base 的拷贝构造，这正是向上转型的合法用法）：  

``` C++
class Base {
    int data;
public:
    Base(int d = 0) : data(d) {} // 有默认构造，若没有默认构造，下面错误写法会编译失败
    Base(const Base& other) : data(other.data) { 
        std::cout << "Base Copy\n"; 
    }
};

class Derived : public Base {
    double extra;
public:
    // 错误写法：没有在初始化列表调用 Base 拷贝，编译器隐式调用 Base()，data 被设为 0，而非拷贝 d 中的 data
    Derived(const Derived& d) : extra(d.extra) { 
        std::cout << "Derived Copy (WRONG)\n";
    }

    // 正确写法：显式传递
    Derived(const Derived& d) : Base(d), extra(d.extra) { 
        std::cout << "Derived Copy (RIGHT)\n";
    }
};
```

### 移动构造函数
也建议<u>派生类的移动构造函数必须显式调用基类的移动构造函数，并且需要将派生类对象用 `std::move` 转型为右值，才能匹配到基类的移动构造版本</u>。如果调用时写成 `Base(d)`，会调用基类的拷贝构造，失去移动语义，浪费性能。如果写成 `Base()`，会调用基类的默认构造，导致数据丢失。建议写为 `Base(std::move(d))`，例如：  

``` C++
class Base {
    std::vector<int> data;
public:
    Base() = default;
    Base(Base&& other) noexcept : data(std::move(other.data)) {
        std::cout << "Base Move\n";
    }
};

class Derived : public Base {
    std::string name;
public:
    // 正确写法：显式传递右值给基类
    Derived(Derived&& d) noexcept : Base(std::move(d)), name(std::move(d.name)) {
        std::cout << "Derived Move\n";
    }

    // 错误写法：调用了 Base 的拷贝构造
    // Derived(Derived&& d) : Base(d), name(std::move(d.name)) {}
};
```

### 拷贝和移动赋值运算符
还是和上面一样，<u>派生类的赋值运算符必须显式调用基类的赋值运算符</u>。与构造函数使用初始化列表不同，赋值运算符的调用必须写成函数调用，且要在函数体内完成。拷贝赋值调用 `Base::operator=(other);` 传递派生类对象切片后赋值基类部分；移动赋值调用 `Base::operator=(std::move(other));`：  

``` C++
class Base {
    std::vector<int> data;
public:
    Base& operator=(const Base& other) {
        if (this != &other) { data = other.data; }
        return *this;
    }
    Base& operator=(Base&& other) noexcept {
        if (this != &other) { data = std::move(other.data); }
        return *this;
    }
};

class Derived : public Base {
    std::string name;
public:
    Derived& operator=(const Derived& other) { // 拷贝赋值
        if (this != &other) {
            Base::operator=(other); // 调用基类拷贝赋值运算符
            name = other.name;
        }
        return *this;
    }
    Derived& operator=(Derived&& other) noexcept { // 移动赋值
        if (this != &other) {
            Base::operator=(std::move(other)); // 调用基类移动赋值运算符
            name = std::move(other.name);
        }
        return *this;
    }
};
```

编译器隐式生成的赋值运算符会自动先调用基类的赋值运算符，再调用成员变量的赋值运算符（按声明顺序），最后执行函数体。故自己显式自定义时，强烈建议先调用基类赋值，再处理派生类成员。

## 类型转换与继承
### 派生类到基类的类型转换
一个派生类对象包含多个组成部分：一个含有派生类自己定义的（非静态）成员的子对象，以及一个与该派生类继承的基类对应的子对象。因为在派生类对象中含有与其基类对应的组成部分，所以我们能把派生类的对象当成基类对象来使用，而且我们也能将基类的指针或引用绑定到派生类对象中的基类部分上，例如：  

``` C++
Animal animal; // 基类对象
Dog dog; // 派生类对象
Animal* p = &animal; // p 指向 Animal 对象
p = &dog; // p 指向 dog 的 Animal 部分
Animal& r = dog; // r 绑定到 dog 的 Animal 部分
```

这种转换通常称为**派生类到基类 derived-to-base** 的类型转换。和其他类型转换一样，编译器会隐式地执行派生类到基类的转换。意味着我们可以把派生类对象或者派生类对象的引用或指针用在需要基类引用或指针的地方，比如函数参数。

但是要注意**对象切片 object slicing** 问题，上面提到过，这里再说一次，即将派生类对象<u>按值</u>赋值给基类变量时（实际上是调用基类的赋值运算符，只能处理基类自己的成员），编译器只会拷贝基类的那部分内存，派生类的特性会被**切掉 sliced down**，例如：  

``` C++
Dog dog;
Animal animal = dog; // 切片发生！animal 丢失了 Dog 的信息
animal.speak(); // 调用的是 Animal::speak，不是 Dog::speak（失去了多态）
```

另外，不存在从基类向派生类的隐式类型转换，若想要转换，同时基类中含有一个或多个虚函数，我们可以使用 `dynamic_cast` 请求一个类型转换，该转换的安全检查将在运行时执行。如果我们已知某个基类向派生类的转换是安全的，则我们可以使用 `static_cast` 来强制覆盖掉编译器的检查工作。

### 派生类向基类转换的可访问性
派生类向基类转换的可访问性由继承方式和代码位置来决定：  
①在类外部使用派生类向基类转换，Derived 必须使用 public 继承 Base。如果是 protected 或 private 继承，在类外部无法将派生类转换为基类，即禁止向上转型；  
②在 Derived 类内部的成员函数或友元函数，无论 Derived 是以 public、protected 还是 private 方式继承 Base，永远允许向上转型；  
③在 Derived 的派生类，即孙子类的成员或友元，如果 Derived 是 public 或 protected 继承 Base，则允许转型。如果 Derived 是 private 继承 Base，则禁止转型。

## 多重继承
**多重继承 multiple inheritance** 允许一个类同时从多个基类继承属性和方法，在派生类的派生列表中可以包含多个基类，每个基类包含一个可选的访问说明符，基类之间用逗号分隔：  

``` C++
class Base1 { public: void func(); };
class Base2 { public: void func(); };
class Derived : public Base1, public Base2 { }; // 多重继承：Derived 同时继承 Base1 和 Base2
```

当派生类对象被构造时，基类按照声明顺序依次构造，派生类自身最后构造；析构时顺序相反。C++ 11 允许派生类从它的一个或几个基类中继承构造函数（通过 using），但是如果从多个基类中继承了相同的构造函数（即形参列表完全相同），则程序将产生错误。

在只有一个基类的情况下，派生类的作用域嵌套在基类作用域中，查找过程沿着继承体系自底向上进行，直到找到所需的名称，派生类的名称将隐藏基类的同名成员。在多重继承的情况下，相同的查找过程在所有直接基类中同时进行，如果名称在多个基类中都被找到，则对该名称的使用将具有**二义性 ambiguity**，会导致程序出错。对于一个派生类来说，从它的几个基类中分别继承名称相同的成员是完全合法的，只不过在使用这个名称时必须使用作用域限定符 `::` 来显式指定要调用哪个基类的成员：  

``` C++
Derived d;
// d.func(); // 错误！二义性
d.Base1::func(); // 正确，使用作用域限定符指定
d.Base2::func();
```

### 菱形继承
**菱形继承 diamond inheritance** 是多继承中最典型的问题场景：当两个基类共同继承自同一个祖先类，而另一个类又同时继承这两个基类时，继承关系图呈现菱形结构（图就不展示了）：  

``` C++
class A { public: int x; };
class B : public A {};
class C : public A {};
class D : public B, public C {};
```

在普通继承（非虚继承，后面讲）下，菱形继承会导致两个严重问题：  
①**数据冗余 data redundancy**：最终派生类 D 的对象中包含了两份 A 的实例，一份来自 B，一份来自 C。  
②**访问二义性 ambiguity**：当通过 D 的对象访问 A 的成员时，编译器无法确定应该访问 `B::A` 还是 `C::A` 中的成员，导致编译错误，还是需要使用作用域限定符 `::` 来显式指定要调用哪个基类的成员：  

``` C++
D d;
// d.x = 10;  // 编译错误：对 'x' 的访问不明确
d.B::x = 10;  // 必须显式指定路径
d.C::x = 20;  // 两个 x 是独立的
```

### 虚继承
在 C++ 中通过**虚继承 virtual inheritance** 的机制解决上述问题。通过在继承时使用 virtual 关键字，确保公共基类在最终派生类中只存在一份实例，共享的基类子对象称为**虚基类 virtual base class**：  

``` C++
class A { public: int x; }; // 虚基类
class B : public virtual A {};  // B 虚继承 A
class C : virtual public A {};  // C 虚继承 A
class D : public B, public C {}; // D 继承 B 和 C，此时 A 只有一份

D d;
d.x = 10; // 合法，只有一个 x
```

使用虚继承后，构建 D 类对象时，A 的构造函数只会被调用一次。构建 B 子对象时，调用一次 A 的构造函数。构建 C 子对象时，发现 A 已经被构造，不再重复构造，最终 D 对象中只包含一份 A 的子对象。

在虚继承中，虚基类的构造函数最先被调用，然后按照继承声明顺序调用非虚基类的构造函数，最后调用派生类自身的构造函数。最终派生类（即最底层的类）负责直接调用虚基类的构造函数。这意味着即使 B 和 C 的构造函数的初始化列表中包含对 A 的构造调用，这些调用也会被忽略，转而由 D 直接构造 A。

# 第十一章 模板与泛型编程
**模板 template** 是 C++ 中<u>泛型编程</u>的基础，模板就是创建类或函数的<u>蓝图</u>，用占位符（模板参数）代表数据类型。编译器在编译时，会根据你实际使用的具体类型，自动生成对应的、类型特定的代码。

> 模板这一块内容比较多，下面会尽可能多地提及到各个方面，但主要以基础为主。对于高级内容点到为止，不会深入探讨，了解存在这些内容，便于以后实践中深入学习。

## 函数模板
### 定义函数模板
模板定义以关键字 `template` 开始，后跟一个**模板参数列表 template parameter list**，这是一个逗号分隔的一个或多个**模板参数 template parameter** 的列表。模板参数遵循普通的作用域规则，一个模板参数名的可用范围是在其声明之后，至模板声明或定义结束之前。模板定义的一般形式如下：  

``` C++
template <typename T> 
// 或 template <class T>，两者在模板参数声明中完全等价，typename 和 class 没有什么不同
// typename 更清楚地指出随后的名字是一个类型名，更加直观

template <typename T, class U> // 多个类型参数
```

我们可以定义**函数模板 function template** 用于创建可以处理不同类型数据的通用函数：  

``` C++
template<typename T>
T max(T a, T b) {
    return (a > b) ? a : b;
}
```

当使用模板时，我们可以隐式地或显式地指定**模板实参 template argument**，编译器使用实参的类型来确定绑定到模板参数 T 的类型，编译器用推导出的模板参数类型来为我们**实例化 instantiate** 一个特定版本的函数，生成的版本通常被称为模板的实例：

``` C++
int i = max(3, 5); // 隐式指定模板实参，实例化为 max<int>
double d = max<double>(4.5, 2.3); // 显式指定模板实参，实例化为 max<double>
```

另外，函数模板可以声明为 inline 或 constexpr，放在模板参数列表之后，返回类型之前：  

``` C++
template <typename T>
inline T max(T a, T b) { return (a > b) ? a : b; }

template <typename T>
constexpr T max(T a, T b) { return (a > b) ? a : b; }
```

### 函数模板重载
可以声明多个同名的函数模板，函数模板跟普通函数也可以同名。与普通函数重载类似，函数模板重载要求参数列表不同，返回值类型不同不能构成重载：  

``` C++
template <typename T>
void display(T a, T b) {
    std::cout << "Template (T, T)" << std::endl;
}

template <typename T>
void display(T a, T b, T c) { // 重载模板：参数数量不同
    std::cout << "Template (T, T, T)" << std::endl;
}

template <typename T1, typename T2>
void display(T1 a, T2 b) { // 重载模板：参数类型不同
    std::cout << "Template (T1, T2)" << std::endl;
}

template <typename T>
void display(T* a, T* b) { // 重载模板：参数类型不同
    std::cout << "Template (T*, T*)" << std::endl;
}
```

重载解析规则优先选择最匹配的版本，大致遵循以下优先级：  
①如果存在一个普通函数，且其参数与调用实参精确匹配，无需任何类型转换，则编译器会优先选择它；  
②如果没有精确匹配的普通函数，编译器会尝试从函数模板生成一个可以精确匹配调用实参的函数；  
③如果上述两者都不存在，编译器会考虑那些需要隐式类型转换才能匹配的普通函数；  
④编译器最后才考虑需要类型转换才能匹配的函数模板。

``` C++
void f(int, int) {
    std::cout << "Ordinary function" << std::endl;
}

template <class T1, class T2>
void f(T1, T2) {
    std::cout << "Function template" << std::endl;
}

f(1, 1); // 输出 Ordinary function
f(1l, 1); // 输出 Function template
f<int, int>(2, 2); // 显式指定了模板参数，强制使用函数模板，输出: Function template
```

### 万能引用与完美转发
如果一个函数参数是指向模板参数类型的右值引用 `T&&`，则可以传递给它任意类型的实参，既可以绑定到左值，也可以绑定到右值，即**万能引用/转发引用 universal reference / forwarding reference**：  

``` C++
template<typename T>
void func(T&& param) {  // 这是万能引用，不是右值引用
    // ...
}

int x = 10;
func(x); // T 推导为 int&，param 是左值引用
func(10); // T 推导为 int，param 是右值引用
```

如上所示，当我们将一个左值传递给函数的右值引用参数，且此右值引用指向模板类型参数时，编译器会推断模板类型参数为实参的左值引用类型，对应上述例子中为 `int&`。此时，func() 的函数参数变为了一个 int& 的右值引用，当类型推导涉及引用的引用时，会触发引用折叠规则，最终函数参数将被实例化为一个左值引用参数：  

| 原始类型 | 折叠后 |
| :---- | :---- |
| T& & | T& |
| T& && | T& |
| T&& & | T& |
| T&& && | T&& |

有时，某些函数需要将其一个或多个实参连同类型不变地转发给其他函数，通过将一个函数参数定义为一个指向模板类型参数的右值引用，我们可以保持其对应实参的所有类型信息。但这样没有解决全部问题，因为右值引用函数参数，是具名变量，与其他任何变量一样，都是左值表达式：  

``` C++
void Fun(int& x)  { std::cout << "左值引用" << std::endl; }
void Fun(int&& x) { std::cout << "右值引用" << std::endl; }

template<typename T>
void PerfectForward(T&& t) {
    Fun(t);  // 无论传入什么，t 在这里都是左值！
}

PerfectForward(10); // 传入右值，但 Fun(t) 调用的却是左值版本
```

此时就需要使用 `std::forward` 保持类型信息来进行**完美转发 perfect forwarding**，它是一个条件性转换函数，如果传入的是左值，则保持为左值，如果传入的是右值，则转换为右值：  

``` C++
template<typename T>
void PerfectForward(T&& t) {
    Fun(std::forward<T>(t)); // 保持 t 的原始类型属性
}
```

## 类模板
### 定义类模板
**类模板 class template** 是用来生成类的蓝图的。类似函数模板，类模板的定义以关键字 `template` 开头，后跟尖括号 `<>` 中的模板参数列表：  

``` C++
template <typename T>
class Box {
private:
    T item;
public:
    Box(T value) : item(value) {}
    
    void displayItem() {
        std::cout << "Box contains: " << item << std::endl;
    }
};
```

但与函数模板的不同之处是，类模板实例化时不支持自动类型推导，必须显式指定模板实参，即：  

``` C++
Box<int> intBox(123);
intBox.displayItem(); // 输出: Box contains: 123

Box<std::string> strBox("Hello");
strBox.displayItem(); // 输出: Box contains: Hello
```

### 类模板的成员函数
与其他任何类相同，我们既可以在类模板内部，也可以在类模板外部为其定义成员函数，且定义在类模板内的成员函数被隐式声明为内联函数。类模板的每个实例都有其自己版本的成员函数，因此当我们在类外定义一个成员函数时，必须再次声明模板参数：  

``` C++
template <typename T>
class MyClass {
public:
    void display();
};

// 类外定义成员函数
template <typename T>
void MyClass<T>::display() {
    // ...
}
```

另外，对于一个实例化了的类模板，其成员只有在使用时才被实例化。

### 类模板的静态成员
与普通类的静态成员不同，类模板的静态成员不是所有实例化类型共享的，而是每个具体的模板实例化类型拥有自己独立的一份静态成员副本。静态数据成员必须在类模板的作用域外单独定义，并且需要指定模板参数。定义时通常给出初始值，若未显式初始化，则进行零初始化。而静态成员函数，可以在类内直接定义（隐式内联），也可以在类外定义，同样需要指定模板参数：  

``` C++
template<typename T>
class MyClass {
public:
    static int count;
    static T value;
    static void func() { }
};

template<typename T>
int MyClass<T>::count = 0;

template<typename T>
T MyClass<T>::value = T();

template<typename T>
void MyClass<T>::func() { }
```

### 成员模板
无论是普通类还是类模板都可以包含本身是模板的成员函数，这种成员被称为**成员模板 member template**。成员模板不能是虚函数，这是因为虚函数表 vtable 的大小在编译时必须是固定的，而模板的实例化数量是不确定的，无法为每个实例化版本分配一个 vtable 条目。

``` C++
template<typename T> // 类模板参数
class Wrapper {
public:
    template<typename U> // 成员模板参数
    void assign(const U& val);
};

template<typename T> // 类模板参数
template<typename U> // 成员模板参数
void Wrapper<T>::assign(const U& val) {
    // ...
}
```

为了实例化一个类模板的成员模板，我们必须同时提供类和函数模板的实参。与往常一样，我们在哪个对象上调用成员模板，编译器就根据该对象的类型来推断类模板参数的实参。与普通函数模板相同，编译器通常根据传递给成员模板的函数实参来推断它的模板实参。

### 类模板的类型别名
C++ 11 允许为类模板定义一个类型别名：  

``` C++
template<typename T>
using Vec = std::vector<T>;

Vec<int> numbers; // Vec<int> 等价于 std::vector<int>
```

`typedef` 无法直接定义模板别名，只能定义具体类型的别名，无法包含模板参数，比如 `typedef std::vector<int> IntVector;`

### 类模板的类型成员
类模板的类型成员是指在类模板内部定义的类型别名 `typedef` 或 `using` 或嵌套类型（嵌套类、嵌套枚举等）。类模板的成员类型别名以一种更容易从类外部访问的方式定义了类内的相关类型，常用于暴露与模板参数相关的类型信息，例如：  

``` C++
template<typename T>
class MyContainer {
public:
    // 类型别名（C++11 前用 typedef）
    using value_type = T; // 值类型
    using reference = T&; // 引用类型

    // 嵌套类（也是类型成员）
    class iterator { /* ... */ };

    // 嵌套枚举
    enum class SortOrder { Asc, Desc };
};

// 使用时，通过实例化后的类作用域访问
MyContainer<int>::value_type a = 42; // int a
MyContainer<int>::iterator it; // 嵌套类对象
MyContainer<int>::SortOrder order = MyContainer<int>::SortOrder::Asc;
```

当类型成员依赖于模板参数 T 时，比如 `T::value_type` 这样的代码，编译器在解析阶段无法确定它究竟是类型还是静态成员变量，因此必须显式加上 `typename` 关键字（这里不能使用 `class`）告诉编译器该名字是一个类型：  

``` C++
template<typename T>
void foo() {
    // MyContainer<T>::value_type x; // 错误：编译器不知道 MyContainer<T>::value_type 是类型还是变量

    typename MyContainer<T>::value_type x; // 正确：用 typename 告诉编译器这是一个类型
}
```

### 类模板与友元
如果一个类模板包含一个非模板友元，则友元被授权可以访问所有模板实例。如果友元自身是模板，类可以授权给所有友元模板实例，也可以只授权给特定实例。

①将普通的非模板类或非模板函数声明为类模板的友元。此时，这个普通的类或函数可以访问该类模板任意实例的私有成员：  

``` C++
template <typename T>
class Bar {
    friend class FooBar; // 普通非模板类作为友元
    friend void fun(); // 普通非模板函数作为友元
};
```

②将整个函数模板或类模板声明为友元，这意味着该函数模板或类模板的所有实例化版本都能访问当前类模板的所有实例的私有成员：  

``` C++
template <class T>
class Bar {
    T data;

    template <class U>
    friend class FooBar; // 所有 FooBar 的实例都是 Bar 所有实例的友元

    template <class U>
    friend void fun(Bar<U>&); // 所有 fun 的实例都是 Bar 所有实例的友元
};

template <class T>
class FooBar { // 任意 FooBar<T> 都可以访问任意 Bar<U> 的私有成员
public:
    template <class U>
    void print(Bar<U>& bar) {
        std::cout << bar.data << std::endl;  // 可访问
    }
};

template <class T>
void fun(Bar<T>& bar) { // 任意 fun<T> 都可以访问任意 Bar<U> 的私有成员
    std::cout << bar.data << std::endl;
}
```

③只将函数模板或类模板的某个特定实例（如 `FooBar<int>`）声明为友元。此时，只有该特定实例能访问当前类模板的私有成员：  

``` C++
// 必须提前声明
template <class T> class Bar;
template <class T> class FooBar;
template <class T> void fun(Bar<T>&);

template <class T>
class Bar {
    friend class FooBar<int>; // 只有 FooBar<int> 是友元
    friend void fun<int>(Bar<int>&); // 只有 fun<int> 是友元
};
```

## 模板参数
前面的例子中使用的模板参数都是类型模板实参，实际上模板参数分为三大类：**类型模板参数 type template parameter**、**非类型模板参数 non-type template parameter**、**模板模板参数 template template parameter**。

### 非类型模板参数
非类型模板参数接受编译期常量作为参数，例如整数、枚举、指针、引用等，从 C++ 20 起，支持浮点数、字面量类类型等，表示一个值而非一个类型。我们通过一个特定的类型名而非关键字 class 或 typename 来指定非类型参数。当一个模板被实例化时，非类型参数被一个用户提供的或编译器推断出的值所代替，这些值必须是<u>常量表达式</u>，从而允许编译器在编译时实例化模板。

``` C++
template <int N>
class Array {
    int data[N];
};

template <int N, int M>
int add() { return N + M; }

Array<10> arr; // N = 10
int result = add<3, 5>(); // 结果 8
```

绑定到指针或引用非类型参数的实参必须具有静态的生存期，我们不能用一个普通（非 static）局部变量或动态对象作为指针或引用非类型模板参数的实参。指针参数也可以用 nullptr 或一个值为 0 的常量表达式来实例化。

### 模板模板参数
模板模板参数表示一个模板本身，作为参数传递给另一个模板，这里给个简单的示例：  

``` C++
template <typename T, template<typename> class C>
class Stack {
    C<T> data;
};

template <typename T>
using Vector = std::vector<T>;

Stack<int, Vector> s;
```

在 C++ 17 之前，模板模板参数的声明中只能用 class（不能用 typename），但 C++ 17 开始两者均可。模板模板参数这一块内容比较“高级”，主要服务于库的作者和框架的设计者，这里就简单介绍一下，以后有需求的话，建议更深层次的学习与工程实践一起进行。

### 默认模板参数
就像能为函数参数提供默认实参一样，我们也可以提供**默认模板实参 default template argument**。从 C++ 11 开始，支持函数和类模板的默认模板实参，之前只允许为类模板提供默认模板实参。

``` C++
// 类模板的默认模板实参
template <typename T = int, typename C = std::vector<T>>
class MyContainer {
    C data;
};

MyContainer<> defaultContainer; // 尖括号不能省略，但可以为空，表示使用默认类型

// 函数模板的默认模板实参
template <typename T, typename F = std::less<T>>
int compare(const T &v1, const T &v2, F f = F())
{
    if (f(v1, v2)) return 1; 
    if (f(v2, v1)) return -1;
    return 0;
}

compare(1, 3); // 1
compare(1, 3, std::greater<int>()); // -1
compare(10, 5, [](int a, int b) { return a > b; }); // 1
```

### 可变参数模板
C++ 11 引入了**可变参数模板 variadic template**，允许函数模板和类模板接受可变数目的参数，称为**参数包 parameter packet**，通过省略号 `...` 来声明。存在两种参数包：**模板参数包 template parameter packet**，表示零个或多个模板参数；**函数参数包 function parameter packet**，表示零个或多个函数参数。

①模板参数包：在 `typename` 或 `class` 后面加上 `...`：  

``` C++
template<typename... Args> // Args 是一个模板参数包
class MyClass;
```

②函数参数包：在函数参数列表中，类型后面加上 `...`：  

``` C++
template<typename... Args>
void myFunction(Args... args) { } // args 是一个函数参数包
```

参数包不能直接使用，必须通过某种方式**展开 expand** 才能访问其中的每个参数，最经典的可变参数模板展开方式通过<u>递归</u>调用逐步处理每个参数，例如：  

``` C++
// 终止函数：处理最后一个参数
template<typename T>
void print(T value) {
    std::cout << value << std::endl;
}

// 递归函数：每次调用处理 Args 中第一个参数，然后递归处理剩余参数
template<typename T, typename... Args>
void print(T first, Args... rest) {
    std::cout << first << " ";
    print(rest...);  // 展开剩余参数包，递归调用
}

// 使用
print(1, 3.14, "hello", 'c'); // 输出: 1 3.14 hello c
```

关于更多展开参数包的方式，这里就不再详细说明了，这部分其实可探讨的内容也挺多的，比如 C++ 17 引入的折叠表达式，以及转发参数包等等，日后真有需求再了解也不迟。

## 特化
**模板特化 template specialization** 为模板的特定参数类型提供定制化实现的机制，当编译器遇到使用特定类型的模板实例时，会优先使用特化版本而非通用模板。模板特化分为两种：①**全特化 full specialization**，为模板的所有参数提供具体类型；②**偏特化 partial specialization**，仅为模板的部分参数提供具体类型或对参数类型做限制。

### 全特化
全特化将模板参数列表中所有的参数都确定化，template 关键字后面跟一对空的尖括号 `<>`，例如：  

``` C++
// 主模板
template<typename T>
class MyClass {
public:
    void show() {
        std::cout << "General template" << std::endl;
    }
};

// 全特化：专门为 int 类型定制
template<>
class MyClass<int> {
public:
    void show() {
        std::cout << "This is the int specialization" << std::endl;
    }
};

MyClass<double> obj1; // 使用普通模板
MyClass<int> obj2; // 使用全特化版本
obj1.show(); // 输出：General template
obj2.show(); // 输出：This is the int specialization
```

### 偏特化
偏特化是指仅对模板参数列表中的一部分参数进行特化，或对模板参数类型进行限制，函数模板不支持偏特化，因为函数模板有重载。

``` C++
// 主模板
template<typename T>
class MyClass {
public:
    void show() { std::cout << "General template" << std::endl; }
};

// 偏特化：专门处理指针类型
template<typename T>
class MyClass<T*> {
public:
    void show() { std::cout << "This is the specialization for pointer types" << std::endl; }
};

MyClass<int> obj1; // 普通模板
MyClass<int*> obj2; // 偏特化版本
obj1.show(); // 输出：General template
obj2.show(); // 输出：This is the specialization for pointer types
```

## 模板实例化
模板本身只是蓝图不是具体的代码，实例化就是编译器根据具体的模板参数，从蓝图中生成真正可供编译的类或函数代码的过程。上面例子中都是**隐式实例化 implicit instantiation**（注意与隐式或显式指定模板实参进行区分），当代码需要一个完整的类型定义时，例如创建该类型的对象，或调用一个函数模板且编译器能推导出模板参数时，编译器自动完成隐式实例化。还有**显式实例化 explicit instantiation**，允许我们主动命令编译器在当前编译单元（`.cpp` 文件）中生成特定模板实例的代码。

### 显式实例化
显式实例化与隐式实例化不同，编译器会实例化类模板的所有成员，即使我们不使用某个成员，它也会被实例化。通常将显式实例化定义放在一个 `.cpp` 文件中，示例如下：  

``` C++
#include "Stack.h" // template<typename T> class Stack { /* ... */ };

// 显式实例化定义，为 int 和 std::string 生成所有成员代码
template class Stack<int>;
template class Stack<std::string>;
```

上面的示例准确地说只是显式实例化定义，C++ 11 还引入了显式实例化声明，使用 `extern` 关键字，用于抑制当前编译单元中的隐式实例化，从而显著缩短编译时间并减小目标文件大小，例如：  

``` C++
// 文件: Stack.h
template<typename T> class Stack { /* ... */ };
extern template class Stack<int>; // 显式实例化声明：告诉所有包含此头文件的 .cpp，不要实例化 int 版本

// 文件: Stack_impl.cpp
#include "Stack.h"
template class Stack<int>;
```

## 模板的文件组织
C++ 模板的文件组织与传统非模板代码有根本不同，这源于其编译模型的特殊性，即编译器在实例化模板时，必须要看到其完整的定义。对于普通函数和类，头文件 `.h` 放声明，源文件 `.cpp` 放定义，然后在链接阶段将各部分组合起来。但模板不同，它本身不是可编译的代码，而是蓝图。编译器只有在遇到具体实例化时，才根据蓝图生成真正的代码。如果此时定义不可见，编译器就无法生成代码，导致链接错误。

最主流、最简单的做法，也是 C++ 标准库采用的方式，就是将模板的声明和定义都放在头文件里，缺点就是头文件会被多个 `.cpp` 文件包含，每个文件都要重新编译模板代码，导致编译变慢。还有种做法就是使用显式实例化，将模板的声明和定义分开，在头文件中仅包含模板声明，在源文件包含定义，并显式实例化所需类型，这种做法只适用于知道模板只会用于有限的几种类型时。

除了上述两种做法，还可以将模板定义放在专门的文件中，然后在头文件末尾包含它，以保持头文件清晰，常用的扩展名有：<kbd>.tpp</kbd>、<kbd>.inl</kbd>。

## 变量模板
**变量模板 variable template** 是 C++ 14 引入的，最常见的用途是定义数学常量（如 π、e），让它们在不同的精度下自动匹配类型，例如：  

``` C++
template<typename T>
constexpr T pi = T(3.1415926535897932385L);

int pi_int = pi<int>; // 使用 int 版本，精度被截断，变为 3
```

## 概念
**概念 concept** 是 C++ 20 引入的，简单来说它是对模板参数的一组要求，它允许程序员以清晰、直观的方式指定模板参数必须满足的条件。你可以将概念理解为一个编译期的谓词 predicate，对类型进行求值，如果类型满足所有要求则返回 true，否则返回 false，如果不满足所有要求，编译直接报错。这里就简单介绍一下。

### 定义概念
定义概念使用 `concept` 关键字，基本语法如下：  

    template <typename T>
    concept 概念名 = 约束表达式;

这里的约束表达式就是一个返回 true 或 false 的条件，通常使用 `requires` 表达式，下面给出一个简单的例子，定义一个 Addable 可相加概念：  

``` C++
#include <concepts> // 使用内置概念需要这个头文件

template <typename T>
concept Addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>; // 要求 a + b 的結果必须能转换成 T 类型
};
```

### 使用概念
定义好概念后，有三种主要方式把它用在模板上：  

①模板参数中直接使用：  

``` C++
template <Addable T> // 直接把概念名放在模板参数里
T add(T a, T b) { return a + b; }
```

②使用 requires 子句，最明确的方式：  

``` C++
template <typename T>
requires Addable<T> // 使用 requires 子句明确指出约束
T add(T a, T b) { return a + b; }
```

③使用 Addable 概念修饰 auto：  

``` C++
Addable auto add(Addable auto a, Addable auto b) {
    return a + b;
}
```

C++20 在 `<concepts>` 头文件中提供了很多常用的概念，可直接使用，部分如下表：  

| 概念 | 作用 |
| :---- | :---- |
| `std::integral<T>` | 检查类型是否为整数类型（如 int, long）|
| `std::floating_point<T>` | 检查类型是否为浮点类型（如 float, double）|
| `std::same_as<T, U>` | 检查两个类型是否完全相同 |
| `std::convertible_to<T, U>` | 检查类型 T 是否能隐式转换为类型 U |
| `std::derived_from<Derived, Base>` | 检查 Derived 是否公开继承自 Base |
| `std::movable<T>` | 检查类型是否可移动 |
| `std::copyable<T>` | 检查类型是否可复制 |

## 模板元编程
先解释什么是**元编程 metaprogramming**？简而言之，就是编写能够操作或生成其他程序（包括它自身）的程序。如果说普通编程是写代码来解决业务问题，那么元编程就是写代码来生产或修改代码。它的核心思想是将代码视为数据，让程序在编译时或运行时拥有自我认知和自我改造的能力。

根据元编程逻辑是在编译期执行还是运行时执行，可以分为两大类：①**编译期元编程或静态元编程**：元代码在程序编译阶段运行，生成最终的二进制代码，主要代表有 C++ 模板元编程、预处理宏等；②**运行时元编程或动态元编程**：元代码在程序运行期间执行，动态地修改或生成代码。灵活性极高，但会带来额外的性能开销，比如 Python 的装饰器和元类、Java / C# 的反射等。

按功能来说，也可以分为①**自省 introspection**：程序在运行时审视自己的结构，比如通过反射获取一个类有哪些方法和字段；②**自修改 self-modification**：程序在运行时修改自身结构；③**代码生成 code generation**：程序生成新的源代码或字节码。

**模板元编程 template metaprogramming (TMP)** 是 C++ 中一种在编译期（而非运行时）执行计算和逻辑处理的编程范式，让编译器在编译阶段完成数值计算或者类型操作等。一个简单的例子就是利用递归模板实例化替代循环，在编译期模拟循环：  

``` C++
// 主模板：递归定义
template <int N>
struct Factorial {
    static const int value = N * Factorial<N - 1>::value;
};

// 全特化：递归终止条件
template <>
struct Factorial<0> {
    static const int value = 1;
};

// 使用：在编译期计算 5!
int result = Factorial<5>::value; // result 在编译时就被赋值为 120
```

模板元编程就简单介绍到这里，它主要是个黑科技，在编写高性能、高泛用性的基础库时用到得比较多。
