# 第十七章 智能指针与内存管理
之前的例子中，对动态内存的管理都是通过 `new` 和 `delete` 来手动管理的。然而，手动管理动态内存很容易出问题，因为确保在正确的时间释放内存是相对困难的：如果忘记调用 `delete`，被分配的内存就无法归还给系统，从而产生**内存泄漏 memory leak**；如果释放得过早，指针就会变成指向已销毁对象的**悬空指针 dangling pointer**；如果对同一块内存释放两次，还会发生**二次释放 double free**。而悬空指针与二次释放都属于**未定义行为 undefined behavior**，轻则导致程序崩溃，重则破坏数据、引发难以排查的安全漏洞。此外，若在 `new` 之后、对应的 `delete` 之前抛出异常，释放内存的语句将永远无法执行，同样会造成内存泄漏。可见，仅仅依靠 `new`/`delete` 来手动管理内存，既不安全，也不省心。  

为此，C++ 11 标准库引入了**智能指针 smart pointer**。智能指针在行为上类似内置指针，但它的核心价值在于可以自动管理所指向对象的生命周期：借助后面将要介绍的 **RAII** 思想，当智能指针对象被销毁时，它会自动释放所管理的内存，使程序员无需（也不应）再手动调用 `delete`。C++ 11 一共提供了三种智能指针（位于头文件 `<memory>` 中）：独占对象所有权的 `unique_ptr`、可共享对象所有权的 `shared_ptr`，以及配合 `shared_ptr` 使用、不增加引用计数的 `weak_ptr`，它们分别适用于不同的所有权模型。

## RAII 思想
**资源获取即初始化 resource acquisition is initialization (RAII)** 是一种借助对象的生命周期来管理资源的编程思想，简单来说就是一句话：<u>在构造函数中获取资源，在析构函数中释放资源</u>。只要把某份资源的生命周期绑定到一个局部对象的生命周期上，那么无论该对象是正常离开作用域，还是因异常触发栈展开而被销毁，其析构函数都一定会被执行，资源也就一定能得到释放，程序员无需手动触发。其中的**资源 resource** 是一个相当宽泛的概念，包括：动态内存、文件句柄、互斥锁、数据库连接、网络套接字等。下面用一个简单的例子来演示 RAII 的工作方式：  

``` C++
class IntArray {
private:
    int* data; // 原始资源（动态数组）
    size_t size;

public:
    // 构造函数：获取资源（分配内存）
    IntArray(size_t sz) : size(sz), data(new int[sz]) {
        std::cout << "获取资源：分配了 " << sz << " 个 int 内存" << std::endl;
    }

    // 析构函数：释放资源（回收内存）
    ~IntArray() {
        delete[] data;
        std::cout << "释放资源：回收了 " << size << " 个 int 内存" << std::endl;
    }

    void setValue(size_t index, int value) {
        if (index < size) data[index] = value;
    }
    int getValue(size_t index) const {
        return (index < size) ? data[index] : -1;
    }
};

int main() {
    IntArray arr(5); // 构造：自动分配内存
    arr.setValue(0, 100);
    std::cout << "arr[0] = " << arr.getValue(0) << std::endl;
    // 离开这个作用域时，arr 的析构函数被自动调用！
}
```

输出：  

    获取资源：分配了 5 个 int 内存
    arr[0] = 100
    释放资源：回收了 5 个 int 内存

## unique_ptr
`std::unique_ptr` 用于管理动态分配对象的生命周期，其实例拥有所指向对象的**独占所有权 exclusive ownership**，不允许拷贝构造或拷贝赋值，但支持移动语义，即所有权可以通过 `std::move` 转移。当实例被销毁，即离开作用域或被显式重置时，它会调用**删除器 deleter**（默认使用 delete）释放所管理的对象，允许用户提供自定义删除器。`unique_ptr` 是首选智能指针，常用于替代裸指针，内部也通常只存储一个裸指针，并持有一个删除器实例（默认删除器无状态，不占额外空间）。

### 创建 unique_ptr
当我们定义一个 `unique_ptr` 时，我们可以将其绑定到一个 `new` 返回的指针上。但 C++ 14 起，提供了一种更安全、更推荐的构造方式，即 `std::make_unique<T>()`。`unique_ptr` 的用法与普通指针几乎一致，当它离开作用域被销毁时，会自动释放所管理的对象，程序员无需也不应再手动调用 `delete`。同时为数组提供了特化 `std::unique_ptr<T[]>`，调用 `delete[]`，但该特化不提供 `*` 和 `->` 操作符，只提供 `[]` 索引，建议直接使用 `std::array`。实例如下：  

``` C++
std::unique_ptr<int> p1(new int(42)); // 直接接管 new 出来的裸指针
std::unique_ptr<int[]> arr1(new int[10]); // 指向 int 数组
auto p2 = std::make_unique<int>(42); // C++ 14 起
auto arr2 = std::make_unique<int[]>(10); // 指向 int 数组

arr1[0] = 5; // 支持下标访问
std::cout << *p2 << std::endl; // 输出 42
```

由于一个 `unique_ptr` 拥有它指向的对象，因此不支持普通的拷贝或赋值操作。如果允许拷贝，两个 `unique_ptr` 会同时以为自己独占同一个对象，销毁时就会对同一块内存重复执行 `delete`，即二次释放。因此拷贝会直接导致编译错误，所有权只能通过移动来转移，借助 `std::move` 把对象的所有权从一个 `unique_ptr` 完整交给另一个，转移后原指针自动变为空，例如：  

``` C++
std::unique_ptr<int> p1 = std::make_unique<int>(42);
// std::unique_ptr<int> p2 = p1;         // 错误！unique_ptr 不可拷贝（编译期报错）
std::unique_ptr<int> p3 = std::move(p1); // 移动：所有权转移给 p3，p1 变为空
std::cout << !p1 << std::endl; // 输出 1

std::unique_ptr<int> createNumber(int v) { // 从函数返回 unique_ptr 时会自动移动
    return std::make_unique<int>(v);
}
auto q = createNumber(7); // q 接管函数内部创建的对象
std::cout << *q << std::endl; // 输出 7
```

### 常用成员函数
`unique_ptr` 常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`get()`</font> | <font size=2>返回所管理的裸指针，所有权仍归该 `unique_ptr`</font> |
| <font size=2>`release()`</font> | <font size=2>放弃所有权但不释放资源：返回裸指针并把自身置空，之后必须由调用者负责释放资源，手动 delete</font> |
| <font size=2>`reset(q)`</font> | <font size=2>释放当前管理的对象，并可选地改而接管新指针 `q`（无参调用时仅释放并置空）</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个 `unique_ptr` 交换各自管理的对象</font> |

``` C++
auto p = std::make_unique<int>(10);
int* raw = p.get(); // get：取出裸指针查看，p 仍是唯一所有者
*raw = 20; // 通过解引用正常读写
std::cout << *p << std::endl; // 输出 20

p.reset(new int(30)); // reset：释放 20，改而接管新的 30
std::cout << *p << std::endl; // 输出 30
p.reset(); // reset()：释放 30，p 变为空
std::cout << !p << std::endl; // 输出 1

int* r = new int(40);
std::unique_ptr<int> q(r); // q 接管裸指针 r
int* taken = q.release(); // release：q 放弃所有权并置空，返回 r
std::cout << !q << std::endl; // 输出 1
delete taken; // 此后必须手动 delete，否则会造成内存泄漏
```

### 自定义删除器
`unique_ptr` 的第二个模板参数是删除器类型，默认使用 `std::default_delete<T>`，即对它管理的指针调用 `delete`。当对象需要特殊的释放方式时，可以传入自定义删除器，例如：  

``` C++
// 自定义删除器：接收一个 T*，负责释放该资源
auto loggingDeleter = [](int* p) {
    std::cout << "正在释放 int" << std::endl;
    delete p;
};
std::unique_ptr<int, decltype(loggingDeleter)> p(new int(42), loggingDeleter);
// p 销毁时会调用 loggingDeleter，而不是默认的 delete
```

## shared_ptr
`std::shared_ptr` 与 `unique_ptr` 的独占模型不同，多个实例可以共同拥有并管理同一个对象，即**共享所有权 shared ownership**。其实现依赖**引用计数 reference counting**，即每个被管理的对象都关联着一个计数，记录当前有多少个 `shared_ptr` 指向它，每通过拷贝或赋值新增一个共享该对象的 `shared_ptr`，引用计数加一；每销毁或重置一个，计数减一；当计数归零，即不再有任何 `shared_ptr` 指向该对象时，对象才会被自动释放。

引用计数存放在一块单独分配的**控制块 control block** 中，因此 `shared_ptr` 内部通常保存两个指针，一个指向所管理的对象，一个指向控制块。控制块由第一个接管对象的 `shared_ptr` 创建，其中一般包括：  
1. **强引用计数 strong reference count**：记录当前有多少个 `shared_ptr` 共享该对象，归零时销毁对象，但控制块本身未必随之释放；  
2. **弱引用计数 weak reference count**：记录指向该对象的 `weak_ptr` 数量，强计数与弱计数都归零时控制块才会被真正释放（详见后文 `weak_ptr` 一节）；  
3. **删除器 deleter**：销毁对象时使用的可调用对象，默认是 `delete`，允许用户自定义；  
4. **分配器 allocator**：若用户提供了自定义分配器，也一并保存在控制块中；  
5. **指向所管理对象的指针**（或对象本身）：从裸指针构造时，控制块只存指向对象的指针。使用 `make_shared` 创建时，对象与控制块位于同一次分配中，此时控制块内直接包含对象本身。

### 创建 shared_ptr
创建 `shared_ptr` 的方式跟 `unique_ptr` 类似，可以直接接管 `new` 返回的指针，也可以使用 `std::make_shared<T>()`，更建议使用该函数，因为它把对象本身与控制块合并到同一次内存分配中完成，既减少了一次堆分配，也提升了缓存局部性。若希望对象的内存来自自定义分配器，可以使用 `std::allocate_shared<T>(alloc, args...)`，`make_shared` 可视作传入默认分配器的特例。创建之后，`shared_ptr` 的用法与普通指针几乎一致，并且支持拷贝：  

``` C++
std::shared_ptr<int> p1; // 默认构造，创建一个空的 shared_ptr
std::shared_ptr<int> p2(new int(10)); // 指针构造，从原始指针获取所有权，不推荐
std::shared_ptr<int> p3(p2); // 拷贝构造，共享所有权，引用计数 +1
std::shared_ptr<int> p4(std::move(p3)); // 移动构造，转移所有权，p3 变为空
auto p5 = std::make_shared<int>(42); // 最推荐的方式
```

> C++ 17 起，`shared_ptr` 也提供了数组特化 `std::shared_ptr<T[]>`，其析构时调用 `delete[]`（C++ 17 之前需借助自定义删除器实现）。

`shared_ptr` 支持拷贝构造与拷贝赋值，也支持移动语义，移动不增减引用计数，只是把所有权从一个 `shared_ptr` 转给另一个。此外，`unique_ptr` 可以通过移动单向转换为 `shared_ptr`，反之则不行：  

``` C++
auto up = std::make_unique<int>(42);
std::shared_ptr<int> sp = std::move(up); // 独占所有权 -> 共享所有权，up 变为空
```

### 常用成员函数
`shared_ptr` 常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`get()`</font> | <font size=2>返回所管理的裸指针，所有权仍归各 `shared_ptr` 共享</font> |
| <font size=2>`reset(q)`</font> | <font size=2>放弃当前所有权（计数减一），并可选地改而接管新指针 `q`（无参调用时仅放弃并置空）</font> |
| <font size=2>`use_count()`</font> | <font size=2>返回共享当前对象的 `shared_ptr` 数量</font> |
| <font size=2>`unique()`</font> | <font size=2>判断当前是否为唯一拥有者，等价于 `use_count() == 1`，C++ 20 起被标记为弃用，C++ 23 中已移除</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个 `shared_ptr` 交换各自管理的对象</font> |

``` C++
auto p1 = std::make_shared<int>(42); // 创建：p1 是唯一拥有者
int* raw = p1.get(); // get：取出裸指针查看，所有权仍归 p1
*raw = 20; // 通过解引用正常读写
std::cout << *p1 << std::endl; // 输出 20

auto p2 = p1; // 拷贝：引用计数加一
std::cout << p1.use_count() << std::endl; // 输出 2（p1、p2 共享同一份计数）

p2.reset(); // reset()：p2 放弃所有权并置空，计数减一
std::cout << (p1.use_count() == 1) << std::endl; // 输出 1（p1 重新成为唯一拥有者）

auto p3 = std::make_shared<int>(7);
p1.swap(p3); // swap：与 p3 交换各自管理的对象
std::cout << *p1 << std::endl; // 输出 7
std::cout << *p3 << std::endl; // 输出 20
```

### 注意事项
①不要用同一个裸指针构造多个 `shared_ptr`：  
每个由裸指针独立构造的 `shared_ptr` 都会创建各自独立的控制块，彼此不知道对方的存在，析构时会对同一块内存重复 `delete`。正确做法是拷贝已有的 `shared_ptr` 来共享所有权，或者直接使用 `make_shared`：  

``` C++
int* raw = new int(42);
std::shared_ptr<int> p1(raw);
std::shared_ptr<int> p2(raw); // 错误！p1、p2 各有独立的控制块，析构时二次释放
```

②**循环引用 circular reference** 问题：  
引用计数无法处理循环引用，若两个对象各自持有指向对方的 `shared_ptr`，它们的引用计数永远无法归零，即使外部已没有任何指针可达，这两个对象也不会被释放，从而造成内存泄漏。解决办法是把其中一环换成不增加引用计数的 `weak_ptr`，这正是下一小节要介绍的内容。

③线程安全性：  
`shared_ptr` 的线程安全是有条件的，主要保证的是控制块内部的引用计数操作。引用计数的增减是原子的，即多个线程分别持有指向同一对象的 `shared_ptr`，各自独立地进行拷贝、析构或 `reset()` 时是安全的，计数不会出错，对象也只会被释放一次。但被管理的对象本身并不是线程安全的，多个线程同时通过 `shared_ptr` 读写同一个对象仍需加锁或使用其他同步手段。此外，同一个 `shared_ptr` 实例被多个线程同时读写是不安全的，需要借助互斥锁等保证同步，正确做法是各线程先拷贝出属于自己的那份 `shared_ptr` 再使用。

## weak_ptr
`std::weak_ptr` 是一种不控制对象生命周期的智能指针，表示对某个由 `shared_ptr` 管理的对象的弱引用，但不增加其强引用计数，常用于打破 `shared_ptr` 之间的循环引用。其内部同样保存指向控制块的指针，但它只增加控制块中的弱引用计数。由于对象可能已被销毁，`weak_ptr` 不提供 `*` 和 `->` 访问对象，必须通过成员函数 `lock()` 尝试提升为 `shared_ptr`，成功时返回非空 `shared_ptr` 并可安全访问，强引用计数 + 1，失败时返回空 `shared_ptr`。

### 创建 weak_ptr
`weak_ptr` 通常由 `shared_ptr` 或另一个 `weak_ptr` 构造或赋值而来，例如：  

``` C++
std::weak_ptr<int> wp1; // 默认构造，创建一个空的 weak_ptr
auto sp = std::make_shared<int>(42);
std::weak_ptr<int> wp2(sp); // 从 shared_ptr 构造，观察 sp 但不增加强引用计数
std::weak_ptr<int> wp3(wp2); // 拷贝构造，与 wp2 观察同一对象
std::weak_ptr<int> wp4(std::move(wp3)); // 移动构造，wp3 变为空
```

注意，不能直接从 `weak_ptr` 构造 `shared_ptr`，唯一正规途径是调用 `lock()` 显式提升，让编译器强制你在使用前检查对象是否仍然存活。

### 常用成员函数
`weak_ptr` 常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`expired()`</font> | <font size=2>判断所观察的对象是否已被销毁</font> |
| <font size=2>`lock()`</font> | <font size=2>返回指向该对象的 `shared_ptr`；若对象已销毁，则返回空的 `shared_ptr`</font> |
| <font size=2>`use_count()`</font> | <font size=2>返回与当前 `weak_ptr` 共享所有权的 `shared_ptr` 数量</font> |
| <font size=2>`reset()`</font> | <font size=2>将 `weak_ptr` 置空</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个 `weak_ptr` 交换各自观察的对象</font> |

核心操作是 `lock()`：若对象仍存在，`lock()` 返回一个共享所有权的 `shared_ptr`；若对象已被释放，`lock()` 返回一个空的 `shared_ptr`。在访问前，可以通过 `expired()` 成员函数判断对象是否已销毁（等价于 `use_count() == 0`）。  

``` C++
auto sp = std::make_shared<int>(42);
std::weak_ptr<int> wp(sp); // 构造，wp 观察 sp 但不增加强引用计数
std::cout << wp.use_count() << std::endl; // 输出 1（use_count 返回强引用计数，weak_ptr 不影响它）

if (auto spt = wp.lock()) { // lock：尝试获取 shared_ptr
    std::cout << *spt << std::endl; // 输出 42
    std::cout << wp.use_count() << std::endl; // 输出 2（提升成功，强引用计数 +1）
} // spt 离开作用域被销毁，强引用计数回落为 1
std::cout << wp.use_count() << std::endl; // 输出 1

sp.reset(); // 释放 sp 后，对象被销毁，wp 过期
std::cout << wp.use_count() << std::endl; // 输出 0
std::cout << wp.expired() << std::endl; // 输出 1
```

### 解决循环引用
循环引用是指两个对象通过 `shared_ptr` 互相持有，导致引用计数永远不归零，即使外部没有任何指针指向它们，内存也无法释放。将其中一个成员改为 `weak_ptr` 即可打破这种死锁：  

``` C++
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;  // 反向使用 weak_ptr，避免循环

    ~Node() {
        std::cout << "Node destroyed\n";
    }
};

int main() {
    auto a = std::make_shared<Node>();
    auto b = std::make_shared<Node>();

    a->next = b;   // b 强计数 +1
    b->prev = a;   // a 强计数不变，只增加弱计数

    // 离开作用域后，a、b 都能正常销毁
}
```

在上例中，若 prev 也使用 `shared_ptr<Node>`，则引用计数永远至少为 1，析构函数将永远不会被调用，从而导致内存泄漏。

## new / delete
在之前的笔记中已经介绍过 `new` / `delete` 的基本用法，这里再深入到它们背后的机制。一个 `new` 表达式实际上完成了两件事：①调用名为 `operator new` 的函数，向系统申请一块足够大的**原始内存 raw memory**；②在这块内存上调用对象的构造函数完成初始化。与之对应，一个 `delete` 表达式同样分为两步：①先调用对象的析构函数完成清理；②再调用名为 `operator delete` 的函数把内存归还给系统。

因此需要区分两组概念：`new` / `delete` 是 C++ 的关键字，由它们构成的 new 表达式与 delete 表达式属于运算符，负责把分配与构造、析构与释放组合在一起。而 `operator new` / `operator delete` 是函数，标准中分别称为**分配函数 allocation function** 与**释放函数 deallocation function**，它们按作用域分为两类：①**全局版本**，写作 `::operator new` / `::operator delete`，标准库为它们提供了一份默认实现，同时标准也允许用户把它替换掉；②**类内重载的版本**，作为该类的静态成员函数，只作用于这个类的 new / delete 表达式。真正向系统申请和归还内存的始终是这两个函数，new / delete 表达式不过是它们与构造函数、析构函数调用的组合。

> 分配释放函数虽然在 `<new>` 头文件中，但常规形式不需要包含 `<new>` 也能使用，因为标准规定普通版本、数组版本以及 C++ 17 起的对齐版本（即不带 `nothrow` / `placement` 额外参数的几种）会在每个翻译单元中被隐式声明。

### operator new / delete
`operator new` / `operator delete` 只负责分配和释放原始内存，既不构造也不析构对象，只保证分配或释放一块大小与对齐都符合要求的、未初始化的内存。其常见形式如下表所示：  

| <font size=2>函数形式</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`void* operator new(std::size_t n)`</font> | <font size=2>分配 `n` 字节原始内存，失败时抛出 `std::bad_alloc`</font> |
| <font size=2>`void operator delete(void* p) noexcept`</font> | <font size=2>释放 `p` 指向的内存，不调用析构函数</font> |
| <font size=2>`void operator delete(void* p, std::size_t n) noexcept`</font> | <font size=2>sized deallocation，C++ 14 起</font> |
| <font size=2>`void* operator new[](std::size_t n)`</font> | <font size=2>供 `new T[]` 使用的数组版本</font> |
| <font size=2>`void operator delete[](void* p) noexcept`</font> | <font size=2>供 `delete[]` 使用的数组版本</font> |
| <font size=2>`void* operator new(std::size_t n, const std::nothrow_t&) noexcept`</font> | <font size=2>配合 `new (std::nothrow) T` 使用，失败时返回 `nullptr`</font> |
| <font size=2>`void operator delete(void* p, const std::nothrow_t&) noexcept`</font> | <font size=2>与上面对应的释放函数</font> |
| <font size=2>`void* operator new(std::size_t n, std::align_val_t al)`</font> | <font size=2>C++ 17 起的对齐版本，分配对齐到 `al` 的内存</font> |
| <font size=2>`void operator delete(void* p, std::align_val_t al) noexcept`</font> | <font size=2>C++ 17 起的对齐版本释放函数</font> |

> new / delete 表达式中调用哪一个由编译器决定的：过对齐 over-aligned 类型会自动改用对齐版本，`new (std::nothrow) T` 会选出带 `nothrow` 的版本，带大小的释放函数是否被采用也依编译器与编译选项而定。使用 new / delete 表达式时不需要关心选中的是哪一个，只有自己手动调用这些函数时，才要保证分配与释放的形式相互匹配。

``` C++
void* raw = ::operator new(sizeof(std::string)); // 只申请 sizeof(std::string) 字节的原始内存
::operator delete(raw); // 直接调用释放函数，不调用析构函数

std::string* ps = new std::string("hello"); // new 表达式：先 operator new 分配，再调用构造函数
delete ps; // 先调用析构函数，再 operator delete 释放
```

#### 类内重载
可以在类内定义 `operator new` / `operator delete` 函数，同时它们隐含为静态成员函数，`static` 关键字可写可不写。类内定义之后，`new T` 会先在类作用域中查找，找不到才使用全局版本，并且按照名字查找规则，类内查找到的版本会<u>隐藏</u>掉所有全局版本。下面用一个简单的例子来演示：  

``` C++
class Widget {
public:
    static void* operator new(std::size_t size) { // 隐含为 static，不能是虚函数
        std::cout << "分配 " << size << " 字节\n";
        return ::operator new(size); // 具体分配仍转交给全局版本
    }
    static void operator delete(void* p) noexcept {
        std::cout << "释放内存\n";
        ::operator delete(p);
    }
    // ... 其他成员
};

Widget* w = new Widget(); // 输出：分配 1 字节，随后调用构造函数
delete w; // 输出：释放内存
```

#### 全局替换
如果在全局作用域中按规定的签名定义一份 `operator new` / `operator delete`，就会<u>替换</u>掉标准库的默认实现，整个程序中所有 new / delete 表达式都会改用这份实现，它们因此被称为**可替换的全局分配/释放函数 replaceable global allocation/deallocation function**。由于默认分配器 `std::allocator`（分配器下一小节讲）的 `allocate()` 成员函数正是调用 `::operator new`，替换之后连 STL 容器的内存来源也会一并改变，这正是实现内存池、分配统计与泄漏检测最方便的切入点。

替换时需要遵守几条规则：必须定义在全局作用域，不能放进命名空间或类中，也不能声明为 `inline`，各版本（普通、数组、`nothrow`、`sized` 乃至对齐版本）最好成套替换，以免分配用一种、释放却用另一种。一个简单的示例如下：  

``` C++
void* operator new(std::size_t sz) {
    if (void* p = std::malloc(sz)) return p;
    throw std::bad_alloc();
}

void operator delete(void* p) noexcept {
    std::free(p);
}
```

另外，可以在 new 表达式里用 `::` 显式指定使用全局版本：  

``` C++
Widget* w1 = new Widget();   // 使用 Widget 类内重载的 operator new
Widget* w2 = ::new Widget(); // 强制使用全局 ::operator new
::delete w2;                 // 强制使用全局 ::operator delete
```

### placement new
**placement new** 是 new 表达式的一种形式，它不在堆上申请新内存，而是在调用者提供的已有内存上直接构造对象。写法是在 `new` 之后紧跟一对括号，括号中给出额外参数，例如 `new (buf) T(args)`，其中 `buf` 就是预先准备好的内存地址。标准库在 `<new>` 中为此专门提供了相关的分配函数：

``` C++
void* operator new(std::size_t, void* p) noexcept { return p; } // 原样返回传入的地址
```

正因为这个重载版本什么都不做，只是把地址原封不动地交回来，所以 `new (buf) T` 最终只完成了调用构造函数这一步，而准备内存这一步完全由调用者自己负责。placement new 的典型用途包括：STL 容器在自己的缓冲区中构造元素、内存池避免频繁向系统申请内存、为对象预留一块长期存在且地址稳定的内存等。示例如下：  

``` C++
#include <new>
#include <string>

// ① 准备一块足够大且对齐正确的原始内存（这里放在栈上）
alignas(std::string) unsigned char buf[sizeof(std::string)];

// ② 在这块内存上调用构造函数构造对象
std::string* ps = new (buf) std::string("hello");
std::cout << *ps << std::endl; // 输出 hello

// ③ 用完必须手动调用析构函数，但不能对 ps 使用 delete，属于未定义行为
ps-> std::string::~string(); // C++ 17 起也可写成 std::destroy_at(ps);
```

> 由于 placement new 的在已有内存上构造对象这一语义与分配器分配与构造分离的目标完全一致，C++ 20 之前 `std::allocator::construct` 内部就是借助 placement new 实现的，C++ 20 之后则由 `std::construct_at` 取代。`std::uninitialized_copy`、`std::uninitialized_fill` 等未初始化内存算法也都建立在它之上。

### nothrow new
默认的分配函数在申请内存失败时会抛出 `std::bad_alloc` 异常，这会打断正常的控制流。若希望像 C 语言的 `malloc` 那样，在失败时<u>返回空指针</u>而不是抛出异常，就可以使用 **nothrow new**。写法是在 `new` 之后紧跟 `(std::nothrow)`，此时编译器会选用带 `const std::nothrow_t&` 参数的分配函数：  

``` C++
#include <new>

int* p = new (std::nothrow) int(42); // 失败时返回空指针，不会抛出异常
if (p) {
    std::cout << *p << std::endl; // 输出 42
    delete p;
}

int* arr = new (std::nothrow) int[1'000'000'000'000]; // 申请一个超大的数组，失败时得到空指针
std::cout << !arr << std::endl; // 很可能输出 1，表示分配失败
delete[] arr; // 对空指针执行 delete 是安全的，什么也不做
```

## 分配器
`std::allocator<T>` 是 C++ 标准库中的默认内存**分配器 allocator**，定义在 `<memory>` 头文件中。它将内存分配与对象构造两个步骤分离：先分配原始内存，再在其上调用构造函数；销毁时先调用析构函数，再释放内存。而 `new` 将内存分配和对象构造组合在了一起，`delete` 将对象析构和内存释放组合在了一起。STL 容器（如 `vector`、`list`）默认使用该分配器，但也允许用户传入自定义分配器，以满足特定的内存管理需求，例如使用内存池、共享内存或跟踪内存分配统计等。

> C++ 17 引入 `std::pmr::polymorphic_allocator`（位于 `<memory_resource>`），允许在运行时指定内存资源，适合构建内存池等复杂系统，属于更高级的内存管理技术。

### 核心成员函数
`std::allocator` 是最简单的分配器，其成员函数 `allocate()` 和 `deallocate()` 封装了全局 `::operator new` 和 `::operator delete` 的调用。日常编程中很少直接使用它，因为它主要服务于标准库容器的内部实现，但了解其接口有助于理解容器的工作原理。其核心成员函数如下表所示：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`allocate(n)`</font> | <font size=2>分配能容纳 `n` 个 `T` 对象的原始内存，返回 `T*`，不构造对象</font> |
| <font size=2>`deallocate(p, n)`</font> | <font size=2>释放由 `allocate` 分配的内存，`p` 必须指向之前分配的内存首地址</font> |
| <font size=2>`construct(p, args)`</font> | <font size=2>在已分配的内存 `p` 处用 `args` 构造对象（C++ 20 已移除）</font> |
| <font size=2>`destroy(p)`</font> | <font size=2>销毁 `p` 指向的对象但不释放内存（C++ 20 已移除）</font> |
| <font size=2>`max_size()`</font> | <font size=2>返回理论上最多能分配的元素个数（C++ 20 已移除）</font> |

> C++ 20 起，`construct` 和 `destroy` 成员被移除，可以使用 `std::construct_at` 和 `std::destroy_at` 自由函数。

``` C++
std::allocator<int> alloc; // 定义一个 int 类型的分配器

int* p = alloc.allocate(5); // 分配能容纳 5 个 int 的原始内存（未构造）
alloc.construct(p, 42); // 在 p 处构造一个 int，值为 42（C++ 20 起移除，改用 std::construct_at）
alloc.destroy(p); // 调用析构函数销毁对象（C++ 20 起移除，改用 std::destroy_at）
alloc.deallocate(p, 5); // 释放内存
```

> 按照 C++ 11 以来的约定，应当通过 `std::allocator_traits` 与分配器交互，而不是直接调用分配器自身的成员，它统一了分配器接口，当分配器未提供 `pointer`、`size_type`、`construct`、`destroy` 等可选成员时，会由它提供默认实现。这也是 C++ 20 移除 std::allocator 的 construct、destroy、max_size 之后仍可继续使用的入口。


# 第十八章 字符串与 I/O 流
## 字符串
C++ 中的字符串处理主要依靠标准库提供的专门类型，而不是 **C 风格字符串**（已在第二章类型、变量与声明的[字面量](https://ybniaobu.github.io/2026/05/10/2026-05-10-C++%E5%AD%A6%E4%B9%A0%E7%AC%94%E8%AE%B01/#%E5%AD%97%E7%AC%A6%E4%B8%B2%E5%AD%97%E9%9D%A2%E9%87%8F)小节中详细讨论过）。后者需要手动管理内存，容易出现忘记结尾空字符 `'\0'`、缓冲区溢出、越界访问等问题。为此，标准库在头文件 `<string>` 中定义了一个通用的字符串模板 `std::basic_string`，并为常用的字符类型分别准备了别名，如下表：  

| <font size=2>别名</font> | <font size=2>实际类型</font> | <font size=2>字符类型</font> |
| :---- | :---- | :---- |
| <font size=2>`std::string`</font> | <font size=2>`std::basic_string<char>`</font> | <font size=2>`char`</font> |
| <font size=2>`std::wstring`</font> | <font size=2>`std::basic_string<wchar_t>`</font> | <font size=2>`wchar_t`</font> |
| <font size=2>`std::u16string`</font> | <font size=2>`std::basic_string<char16_t>`</font> | <font size=2>`char16_t`</font> |
| <font size=2>`std::u32string`</font> | <font size=2>`std::basic_string<char32_t>`</font> | <font size=2>`char32_t`</font> |
| <font size=2>`std::u8string`</font> | <font size=2>`std::basic_string<char8_t>`</font> | <font size=2>`char8_t`（C++ 20 起）</font> |

``` C++
std::string str = "普通字符";
std::wstring wstr = L"宽字符";
std::u16string u16 = u"UTF-16";
std::u32string u32 = U"UTF-32";
std::u8string  u8  = u8"UTF-8"; 
```

由于在绝大多数场景中，使用的都是 `std::string`，它和 C 风格字符串兼容，也可以存储 UTF-8，故下面主要介绍 `std::string` 以及用于高效访问字符串数据的字符串视图 `std::string_view`。

### string
`std::string` 是 `std::basic_string<char>` 的类型别名，表示由 `char` 组成的动态字符序列，它的字符在内存中连续存储（C++ 11 起由标准保证），内存由对象自动管理、按需扩容，因此可以将其理解为字符向量 `vector<char>`，只是说它保证在序列末尾额外存放一个 `'\0'`，并提供了大量字符串专有的操作。与 vector 一样，在发生扩容或插入、删除后，原有的迭代器、指针与引用都可能失效。此外，`std::string` 内部通常还实现了**短字符串优化 short string optimization (SSO)**，当字符串很短时，字符直接存放在对象自身的内部缓冲区中，不进行堆分配，从而避免小字符串频繁申请内存，只在字符串较长时才把字符转移到堆上。

#### 构造与初始化
`std::string` 提供了很多构造函数，常用构造函数如下：  

``` C++
std::string s1;                             // 默认构造，空字符串
std::string s2("hello");                    // 从 C 风格字符串构造
std::string s3 = "hello";                   // 拷贝初始化，等价于上一种
std::string s4(s2);                         // 拷贝构造
std::string s5(5, 'a');                     // 填充构造，即 "aaaaa"
std::string s6(s2, 1, 3);                   // 子串构造，从下标 1 开始取 3 个字符，即 "ell"
std::string s7("hello", 3);                 // 长度构造，从 C 字符串取前 3 个字符，即 "hel"
std::string s8(s2.begin(), s2.begin() + 3); // 迭代器区间构造，即 "hel"
std::string s9(std::move(s2));              // 移动构造
std::string s10{'h', 'e', 'l', 'l', 'o'};   // 初始化列表构造
```

#### 容量与访问
`std::string` 很多成员函数的作用与 `std::vector` 一样：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`empty()`</font> | <font size=2>判断字符串是否为空</font> |
| <font size=2>`size()` / `length()`</font> | <font size=2>返回字符数（不包括结尾的 `\0`），两者完全等价</font> |
| <font size=2>`max_size()`</font> | <font size=2>返回字符数的最大值</font> |
| <font size=2>`reserve(n)`</font> | <font size=2>预分配至少能容纳 `n` 个字符的容量，避免多次扩容</font> |
| <font size=2>`capacity()`</font> | <font size=2>返回当前已分配、无需重新分配即可存放的字符数</font> |
| <font size=2>`shrink_to_fit()`</font> | <font size=2>请求把容量缩减到与大小匹配</font> |
| <font size=2>`at(pos)` / `operator[]`</font> | <font size=2>访问下标 `i` 处的字符，`at` 越界时抛出 `std::out_of_range`，`operator[]` 不做越界检查，越界属于未定义行为</font> |
| <font size=2>`front()` / `back()`</font> | <font size=2>返回首字符 / 尾字符的引用，在空字符串上调用属于未定义行为</font> |
| <font size=2>`data()` / `c_str()`</font> | <font size=2>返回指向底层字符数组首元素的指针，`c_str` 始终返回 `const char*`，`data` 在 C++ 17 起于非 const 对象上返回 `char*`</font> |
| <font size=2>`begin()` / `cbegin()`</font> | <font size=2>返回指向首字符的迭代器 / 只读迭代器</font> |
| <font size=2>`end()` / `cend()`</font> | <font size=2>返回指向尾后位置的迭代器 / 只读迭代器</font> |
| <font size=2>`rbegin()` / `crbegin()`</font> | <font size=2>返回指向尾字符的反向迭代器 / 只读反向迭代器，用于逆序遍历</font> |
| <font size=2>`rend()` / `crend()`</font> | <font size=2>返回指向首字符前一位置的反向迭代器 / 只读反向迭代器，标记逆序遍历的终点</font> |

``` C++
std::string s = "hello";
std::cout << s.empty() << std::endl;      // 输出 0（字符串非空）
std::cout << s.size() << std::endl;       // 输出 5
std::cout << s.length() << std::endl;     // 输出 5，与 size() 完全等价
std::cout << s.capacity() << std::endl;   // 输出当前容量，通常 >= size()（具体值依实现而定）
s.reserve(100);                           // 预留容量，避免后续追加时反复扩容
std::cout << s.capacity() << std::endl;   // 输出 >= 100
s.shrink_to_fit();                        // 请求把容量缩减到与大小匹配（非强制）
std::cout << s.capacity() << std::endl;   // 容量可能缩回与 size() 相近的值

std::cout << s[0] << std::endl;           // 输出 h
std::cout << s.at(1) << std::endl;        // 输出 e
s[0] = 'H';                               // 通过下标修改，得到 "Hello"
std::cout << s.front() << std::endl;      // 输出 H
std::cout << s.back() << std::endl;       // 输出 o
printf("%s\n", s.c_str());                // 输出 Hello，可直接传给 C 风格接口

for (auto it = s.rbegin(); it != s.rend(); ++it) { // rbegin / rend：反向遍历
    std::cout << *it;
}
std::cout << std::endl;                   // 输出 olleH
```

#### 修改操作
`std::string` 提供了很多用于修改内容的成员函数：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`clear()`</font> | <font size=2>从字符串中移除所有字符</font> |
| <font size=2>`insert(pos, s)`</font> | <font size=2>在下标 `pos` 处插入字符串</font> |
| <font size=2>`erase(pos, n)`</font> | <font size=2>删除从 `pos` 开始的 `n` 个字符（省略 `n` 时删到末尾）</font> |
| <font size=2>`push_back(c)` / `pop_back()`</font> | <font size=2>在末尾追加 / 删除一个字符</font> |
| <font size=2>`operator+=` / `append(s)`</font> | <font size=2>在末尾追加内容，`+=` 是最常用的拼接方式</font> |
| <font size=2>`replace(pos, n, s)`</font> | <font size=2>用字符串 `s` 替换从 `pos` 开始的 `n` 个字符</font> |
| <font size=2>`copy(dest, n, pos)`</font> | <font size=2>把从 `pos` 开始的 `n` 个字符复制到外部缓冲区 `dest`，不追加结尾的 `'\0'`，返回复制的字符数</font> |
| <font size=2>`resize(n, c)`</font> | <font size=2>把长度调整为 `n`，不足的部分用字符 `c`（省略时填 `'\0'`）填充</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个字符串高效交换内容</font> |

``` C++
std::string s = "hello";
s += " world";                   // "hello world"
s.append("!");                   // "hello world!"
s.push_back('?');                // "hello world!?"
s.pop_back();                    // "hello world!"
s.insert(5, ",");                // 在下标 5 处插入，"hello, world!"
s.erase(5, 1);                   // 删除下标 5 处的 1 个字符，"hello world!"
s.replace(0, 5, "HELLO");        // 把前 5 个字符替换为 "HELLO"，得到 "HELLO world!"

char buf[6] = {};                // copy()：把字符复制到外部缓冲区，不会自动补上 '\0'
size_t n = s.copy(buf, 5, 0);    // 从下标 0 开始复制 5 个字符到 buf，返回实际复制的字符数
buf[n] = '\0';                   // 因此需要自己补上结尾空字符
std::cout << buf << std::endl;   // 输出 HELLO

s.resize(14, '!');               // 长度不足时用 '!' 补足，得到 "HELLO world!!!"
s.resize(5);                     // 长度超出时直接截断，得到 "HELLO"
```

> `operator+` 与 `+=` 都会按需扩容，但 `operator+` 每次都会生成一个新的字符串对象，在循环中反复拼接时应改用 `+=` 或 `append`，必要时先用 `reserve` 预留容量，以减少不必要的内存分配与拷贝。

#### 查找与子串
`std::string` 提供了很多用于查找和截取的成员函数：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`find(s, pos)`</font> | <font size=2>从 `pos` 起向后查找首个子串 `s`，返回首次出现的下标，失败返回 `npos`</font> |
| <font size=2>`rfind(s, pos)`</font> | <font size=2>从 `pos` 起向前查找首个子串 `s`，返回最后一次出现的下标</font> |
| <font size=2>`find_first_of(s, pos)`</font> | <font size=2>从 `pos` 起向后查找 `s` 中任意一个字符首次出现的位置</font> |
| <font size=2>`find_last_of(s, pos)`</font> | <font size=2>从 `pos` 起向前查找 `s` 中任意一个字符最后一次出现的位置</font> |
| <font size=2>`find_first_not_of(s)`</font> | <font size=2>从 `pos` 起向后查找第一个不在 `s` 中的字符的位置</font> |
| <font size=2>`find_last_not_of(s)`</font> | <font size=2>从 `pos` 起向前查找最后一个不在 `s` 中的字符的位置</font> |
| <font size=2>`substr(pos, n)`</font> | <font size=2>返回从 `pos` 开始、长度为 `n` 的子串（省略 `n` 时取到末尾）</font> |
| <font size=2>`compare(s)`</font> | <font size=2>按字典序比较，小于返回负数，相等返回 0，大于返回正数</font> |
| <font size=2>`starts_with(s)` / `ends_with(s)`</font> | <font size=2>判断是否以 `s` 为前缀 / 后缀（C++ 20 起）</font> |

> `std::string::npos` 是一个静态常量，用于表示没有位置，其值通常是 `size_t` 的最大值。

``` C++
std::string s = "hello world";
std::cout << s.find("world") << std::endl;      // 输出 6
std::cout << s.rfind('o') << std::endl;         // 输出 7（从后往前找，最后一个 'o' 的下标）
std::cout << s.find("xyz") << std::endl;        // 输出 npos（一个极大的数）

std::cout << s.find_first_of("aeiou") << std::endl;    // 输出 1（第一个元音 'e' 的下标）
std::cout << s.find_last_of("aeiou") << std::endl;     // 输出 7（最后一个元音 'o' 的下标）
std::cout << s.find_first_not_of("hel") << std::endl;  // 输出 4（第一个不属于 "hel" 的字符 'o'）
std::cout << s.find_last_not_of("dl") << std::endl;    // 输出 8（最后一个不属于 "dl" 的字符 'r'）

std::cout << s.substr(6, 5) << std::endl;              // 输出 world
std::cout << s.compare("hello world") << std::endl;    // 输出 0（两者相等）
std::cout << s.compare("z") << std::endl;              // 输出负数（'h' 的字典序在 'z' 之前）
std::cout << s.starts_with("hello") << std::endl;      // 输出 1（C++ 20）
std::cout << s.ends_with("world") << std::endl;        // 输出 1（C++ 20）
```

#### 输入输出
`std::string` 可以直接配合标准输入输出流使用：输出用 `std::cout << s`，输入则有两种方式，`std::cin >> s` 以空白为分隔读取，`std::getline` 则读取一整行。它们的行为如下表所示：  

| <font size=2>方式</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::cin >> s`</font> | <font size=2>先跳过前导空白，再读到下一处空白为止，因此无法读入含空格的整行</font> |
| <font size=2>`std::getline(std::cin, s)`</font> | <font size=2>读取从当前位置到换行符 `\n` 为止的整行文本，换行符从 cin 中删除但不存入 `s`</font> |
| <font size=2>`std::getline(std::cin, s, delim)`</font> | <font size=2>指定分隔符 `delim`，读到该字符为止</font> |

``` C++
std::string word, line;
std::cin >> word;               // 第 1 次输入：hello
std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); // 清除换行
std::cout << word << std::endl; // 输出 hello

std::getline(std::cin, line);   // 第 2 次输入：hello world
std::cout << line << std::endl; // 输出 hello world

std::string word2, line2;
std::cin >> word2;              // 第 3 次输入：hello world，word2 得到 hello
std::getline(std::cin, line2);  // 直接读缓冲区剩余的 " world"
std::cout << word2 << line2 << std::endl; // 输出 hello world
```

> `std::cin` 和 `std::getline` 二者混用时要注意：`std::cin` 会把换行符留在输入缓冲区，紧接着调用 `getline` 会立刻读到这个换行符并返回空字符串，可先用 `std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n')` 丢弃该行剩余内容。另外，`std::getline` 是定义在 `<string>` 中的自由函数，不要与 `<istream>` 中读取 C 风格字符数组的成员函数 `istream::getline` 混淆。

#### 数值转换
字符串与数值之间的转换可以借助 `<string>` 中的一组函数完成：  

| <font size=2>函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::stoi(s)` / `std::stol(s)` / `std::stoll(s)`</font> | <font size=2>转换字符串为有符号整数，依次为 int、long、long long</font> |
| <font size=2>`std::stoul(s)` / `std::stoull(s)`</font> | <font size=2>转换字符串为无符号整数，依次为 unsigned long、unsigned long long</font> |
| <font size=2>`std::stof` / `stod` / `stold`</font> | <font size=2>转换字符串为浮点数，依次为 float / double / long double</font> |
| <font size=2>`std::to_string(v)`</font> | <font size=2>把数值转为字符串，支持各整数类型与浮点类型</font> |
| <font size=2>`std::to_wstring(v)`</font> | <font size=2>把数值转为宽字符串 `std::wstring`，接受与 `to_string` 相同的数值类型</font> |

``` C++
int i = std::stoi("42");                     // 42
long l = std::stol("2026");                  // 2026L
long long ll = std::stoll("9000000000");     // 9000000000LL
unsigned long ul = std::stoul("42");         // 42UL
unsigned long long ull = std::stoull("42");  // 42ULL
float f = std::stof("3.14");                 // 3.14f
double d = std::stod("3.14");                // 3.14
long double ld = std::stold("3.14");         // 3.14L

std::string s1 = std::to_string(2026);       // "2026"
std::string s2 = std::to_string(3.14);       // "3.140000"（浮点默认保留 6 位小数）
std::wstring ws = std::to_wstring(2026);     // L"2026"

// 指定进制：stoi 家族的第三个参数是进制，默认为 10
int bin = std::stoi("1010", nullptr, 2);     // 二进制 "1010" → 10
int hex = std::stoi("ff", nullptr, 16);      // 十六进制 "ff" → 255

// 反向（整数 -> 二进制字符串）没有对应的函数，可借助 std::bitset
std::string b = std::bitset<8>(10).to_string(); // "00001010"
```

> 从 C++ 17 起，`<charconv>` 提供了基于 `std::from_chars` / `std::to_chars` 的无异常、零分配转换接口，在高性能场景下比 `std::stoi` / `std::to_string` 更合适。

### string_view
`std::string_view` 是 C++ 17 引入的<u>只读</u>字符串视图，定义在 `<string_view>` 头文件中。它是对一段已存在字符序列的只读引用，本质上只保存一个指向字符数据的指针和一个长度，即可以理解为 `(const char*, size_t)`。<u>它不负责管理底层字符数据的内存，不能通过它修改底层字符</u>。跟 `std::string` 类似，它本质上是 `std::basic_string_view<T>` 的类型别名：  

    std::string_view      // std::basic_string_view<char>
    std::wstring_view     // std::basic_string_view<wchar_t>
    std::u16string_view   // std::basic_string_view<char16_t>
    std::u32string_view   // std::basic_string_view<char32_t>
    std::u8string_view    // std::basic_string_view<char8_t>，C++ 20

#### 常见构造方式
`std::string_view` 的构造方式很灵活，可以从字符串字面量、`std::string`、迭代器区间等来源创建，且都不复制底层数据：  

``` C++
std::string_view sv1;                         // 默认构造，空视图
std::string_view sv2 = "hello";               // 从字符串字面量构造（不复制）
std::string_view sv3("hello", 3);             // 指针 + 长度
std::string_view sv4 = sv2;                   // 拷贝构造，开销极小

std::string str = "hello";
std::string_view sv5 = str;                   // 从 std::string 构造（隐式转换）
std::string_view sv6(str.begin(), str.end()); // C++ 20 迭代器范围
std::string_view sv7 = sv2.substr(1, 3);      // 子视图，"ell"

std::string_view sv8 = "hello"sv;             // C++17 字面量，需 using namespace std::string_view_literals;
```

#### 成员函数
`string_view` 的大部分成员函数与 `std::string` 类似，用法完全一致，不再重复说明，下表只列出它特有或行为不同的成员函数：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`substr(pos, n)`</font> | <font size=2>返回子视图（不复制数据），与 `string` 的 `substr` 返回新字符串不同</font> |
| <font size=2>`remove_prefix(n)`</font> | <font size=2>把视图起点后移 `n` 个字符（视图独有）</font> |
| <font size=2>`remove_suffix(n)`</font> | <font size=2>把视图长度缩短 `n` 个字符（视图独有）</font> |

``` C++
std::string_view sv = "hello world";
std::string_view sub = sv.substr(6, 5); // substr：返回子视图（不复制数据）
std::cout << sub << std::endl;          // 输出 world
sv.remove_prefix(6);                    // remove_prefix：丢弃前 6 个字符
std::cout << sv << std::endl;           // 输出 world
sv.remove_suffix(1);                    // remove_suffix：丢弃末尾 1 个字符
std::cout << sv << std::endl;           // 输出 worl
```

#### 其它事项
①`string_view` 最典型的用途是作为函数参数类型。若参数写成 `const std::string&`，那么当调用方传入字符串字面量或 `const char*` 时，会隐式构造出一个临时 `std::string`，产生一次内存分配与拷贝，而使用 `string_view` 则可以完全避免这次开销：  

``` C++
bool startsWithHello(std::string_view sv) { // 无论传入 string、const char* 还是字符串字面量，都不会发生拷贝
    return sv.starts_with("hello");
}

std::string s = "hello world";
std::cout << startsWithHello(s) << std::endl;        // 传入 std::string
std::cout << startsWithHello("hello there") << std::endl; // 传入字面量
```

②生命周期问题：`string_view` 不延长所观察数据的生命期，若底层字符串先被销毁或数据被重新分配，视图就会变成**悬空视图 dangling view**，此时访问属于未定义行为：  

``` C++
std::string_view bad = std::string("temp"); // 错误！临时 string 当场销毁，bad 立即悬空

std::string s = "hello";
std::string_view sv = s.substr(0, 2); // 悬空：s.substr 返回临时 std::string

std::string_view sv = s;
s += " world!!!"; // 若触发扩容，字符数据搬家，sv 失效
```

因此<u>不要把 `string_view` 作为返回值返回临时数据，也不要长期保存指向局部字符串的视图</u>。作为函数参数使用时是安全的，因为此时被观察的数据在整个调用期间都活着。

## I/O 流
**流 stream** 是 C++ 对**输入输出 input/output (I/O)** 的抽象，表示数据按顺序、有方向地在程序与数据源/目的地之间传输。这个源/目的地可以是键盘、屏幕、文件、网络、内存等。对程序来说，它就是一串有序的字符序列，通过统一接口读写。C++ 标准库提供了一套以 `basic_*stream` 为模板的流类体系，如下表：  

| <font size=2>类别</font> | <font size=2>头文件</font> | <font size=2>说明</font> |
| :---- | :---- | :---- |
| <font size=2>标准流</font> | <font size=2>`<iostream>`</font> | <font size=2>与标准输入输出设备（键盘、屏幕）绑定的全局流对象，如 `std::cin` / `std::cout` / `std::cerr` / `std::clog`</font> |
| <font size=2>文件流</font> | <font size=2>`<fstream>`</font> | <font size=2>读写磁盘文件，如 `std::ifstream` / `std::ofstream` / `std::fstream`</font> |
| <font size=2>字符串流</font> | <font size=2>`<sstream>`</font> | <font size=2>在内存中的 `std::string` 上读写，如 `std::istringstream` / `std::ostringstream` / `std::stringstream`</font> |
| <font size=2>同步流</font> | <font size=2>`<syncstream>`（C++ 20）</font> | <font size=2>多线程环境下保证各线程输出不交错的流缓冲包装，如 `std::osyncstream`</font> |
| <font size=2>内存流</font> | <font size=2>`<spanstream>`（C++ 23）</font> | <font size=2>在已有的固定内存块 `std::span` 上读写，如 `std::ispanstream` / `std::ospanstream` / `std::spanstream`</font> |
| <font size=2>C 风格流</font> | <font size=2>`<cstdio>`</font> | <font size=2>C 标准库遗留的输入输出接口，以 `std::FILE*` 表示流</font> |

流这一块，其实细究起来有很多内容，

### 标准流
标准库在头文件 `<iostream>` 中包含了 `<istream>` 和 `<ostream>`，分别定义了两个类模板：输入流 `std::basic_istream` 与输出流 `std::basic_ostream`，并为常用的字符类型提供了别名，如 `std::istream` / `std::ostream`（对应 `char`）以及 `std::wistream` / `std::wostream`（对应 `wchar_t`）。向流中写数据使用 `<<` **插入运算符 insertion operator**，从流中读数据使用 `>>` **提取运算符 extraction operator**，二者都返回流对象自身，因此可以连续串联，例如 `std::cout << a << b;`。同时，在 `<iostream>` 中预先定义好了若干个与标准输入输出设备绑定的全局流对象，如下表：  

| <font size=2>流对象</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::cin`</font> | <font size=2>标准输入，通常绑定键盘，类型为 `std::istream`</font> |
| <font size=2>`std::cout`</font> | <font size=2>标准输出，通常绑定屏幕，带缓冲，类型为 `std::ostream`</font> |
| <font size=2>`std::cerr`</font> | <font size=2>标准错误，不带缓冲，立即刷新，类型为 `std::ostream`</font> |
| <font size=2>`std::clog`</font> | <font size=2>标准错误日志，带缓冲，类型为 `std::ostream`</font> |

> 宽字符对应 `std::wcin`、`std::wcout`、`std::wcerr`、`std::wclog`。

``` C++
int age;
std::cout << "请输入年龄："; // 提示信息，不换行
std::cin >> age;             // 从标准输入读取一个整数
std::cout << "你的年龄是 " << age << std::endl;

std::clog << "这是一条日志信息" << std::endl; // 带缓冲，缓冲区满或程序结束时才输出
std::cerr << "这是一条错误信息"; // 不带缓冲，立即输出
```

> `std::endl` 会写入换行符 `'\n'` 并**刷新缓冲区**，而直接写 `'\n'` 只换行、不刷新。频繁刷新会拖慢输出，因此大量输出时更推荐用 `'\n'`，只在确需立即看到结果时才用 `std::endl`。

### 缓冲区
【书签】

流内部维护着一块称为**缓冲区 buffer** 的内存区域：输出时，写入流的数据并不会立刻送达设备，而是先暂存进缓冲区，等缓冲区被填满、被显式刷新或程序正常结束时，才一次性交给操作系统真正写入设备；输入时则相反，一次从设备读入一大块数据塞进缓冲区，之后的读取操作直接从缓冲区中取用，取空后再去读下一块。之所以这样做，是因为设备访问（磁盘、终端、网络等）远比内存操作慢，把大量零散的小块读写合并成整块的读写，可以显著减少昂贵的系统调用次数，从而大幅提升效率。

按照刷新时机的不同，标准库把流大致分为三种缓冲方式：

| <font size=2>缓冲方式</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>全缓冲 full buffering</font> | <font size=2>缓冲区满、被显式刷新或程序结束时才真正写入设备，文件等块设备通常是这种方式</font> |
| <font size=2>行缓冲 line buffering</font> | <font size=2>遇到换行符 `'\n'` 即刷新，与终端交互时常见</font> |
| <font size=2>无缓冲 unbuffered</font> | <font size=2>不做缓冲，每次操作都立即传递到设备，效率较低但能保证即时可见</font> |

> 具体采用哪一种由实现决定：`std::cerr` 默认无缓冲（相当于开启了 `std::unitbuf`），以保证错误信息第一时间出现；`std::cout` 与终端关联时通常是行缓冲，重定向到文件时往往变成全缓冲，这也是同一程序在终端里输出正常、重定向到文件后却“看不到”中间过程的原因。

与刷新有关的操纵符和成员函数如下表：  

| <font size=2>操纵符 / 成员</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::flush`</font> | <font size=2>立即刷新缓冲区</font> |
| <font size=2>`std::endl`</font> | <font size=2>写入换行符 `'\n'` 后刷新，等价于 `'\n' << std::flush`</font> |
| <font size=2>`std::unitbuf` / `nounitbuf`</font> | <font size=2>开启 / 关闭“每次输出后都刷新”的模式</font> |
| <font size=2>`tie(stream)`</font> | <font size=2>把输出流与某个输入流绑定，使该输入流每次读取前自动刷新这个输出流</font> |

其中 **tie** 是交互式程序最常用的机制：`std::cin` 默认就与 `std::cout` 绑定了（`std::cin.tie()` 返回 `&std::cout`），因此每次从 `std::cin` 读取之前，`std::cout` 的缓冲区都会被自动刷新，这正是“先输出一句提示、再等待输入”时提示文字能够及时出现的原因。

``` C++
std::cout << "请输入一个数字："; // 没有换行，可能仍留在缓冲区里
int n;
std::cin >> n;                   // 读取前 cin 会自动刷新 cout，提示信息这才显示出来

std::cout << "处理中" << std::flush; // 手动刷新，立即输出而不必等到缓冲区满
std::cout << "完成" << std::endl;    // 写入换行符并刷新
```

> 缓冲区最容易踩的坑是程序<u>异常终止</u>时未刷新的内容会丢失：若程序因 `std::abort()`、崩溃或 `_exit()` 而结束，标准流的缓冲区不会被刷新，此前“打印过”的内容可能根本没有写出去（而在 `return` 或 `std::exit()` 正常结束时，标准库会自动刷新）。因此调试时若发现日志缺失，除了检查逻辑，也要考虑缓冲区尚未刷新这一可能。

> 顺带一提：缓冲区本身并不由流对象直接管理，而是交给独立的**流缓冲区 streambuf**（`std::basic_streambuf`）负责，`std::istream` / `std::ostream` 内部只保存一个指向它的指针；文件流底层用的是 `std::basic_filebuf`，字符串流底层用的是 `std::basic_stringbuf`，通过成员函数 `rdbuf()` 可以取得当前流关联的 `streambuf`。

### 输入输出的格式化
流会按照数据的类型自动选择默认格式，若需要控制宽度、精度、进制等，可以借助 `<iomanip>` 中的**操纵符 manipulator**，常用的如下表：  

| <font size=2>操纵符</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::endl`</font> | <font size=2>写入换行符 `'\n'` 并刷新缓冲区</font> |
| <font size=2>`std::dec` / `hex` / `oct`</font> | <font size=2>整数按十进制 / 十六进制 / 八进制输出（默认为十进制）</font> |
| <font size=2>`std::showbase`</font> | <font size=2>显示进制前缀，如十六进制的 `0x`</font> |
| <font size=2>`std::setw(n)`</font> | <font size=2>设置下一个输出项的最小宽度为 `n`，<u>只影响其后一项</u>，内容超出时不会被截断</font> |
| <font size=2>`std::setfill(c)`</font> | <font size=2>设置填充字符，默认为空格</font> |
| <font size=2>`std::left` / `right`</font> | <font size=2>设置左对齐 / 右对齐（默认为右对齐）</font> |
| <font size=2>`std::setprecision(n)`</font> | <font size=2>设置浮点数的有效位数，与 `fixed` 搭配时表示小数位数</font> |
| <font size=2>`std::fixed` / `scientific`</font> | <font size=2>浮点数按定点 / 科学计数法输出</font> |
| <font size=2>`std::boolalpha`</font> | <font size=2>`bool` 输出为 `true` / `false`，而非 1 / 0</font> |
| <font size=2>`std::flush`</font> | <font size=2>立即刷新缓冲区</font> |

``` C++
#include <iomanip>
#include <iostream>

std::cout << std::hex << 255 << std::endl;                                // 输出 ff
std::cout << std::setw(8) << std::setfill('0') << 42 << std::endl;        // 输出 00000042
std::cout << std::fixed << std::setprecision(2) << 3.14159 << std::endl;  // 输出 3.14
std::cout << std::left << std::setw(6) << "abc" << '|' << std::endl;      // 输出 abc   |
std::cout << std::boolalpha << (1 < 2) << std::endl;                      // 输出 true
```

> 大多数操纵符会<u>持续生效</u>（如 `std::hex`、`std::fixed`），只有 `std::setw` 仅作用于紧随其后的一个输出项。要恢复默认，可以使用对应的重置操纵符，如 `std::dec`、`std::defaultfloat`、`std::noboolalpha`。

### 流的状态与错误处理
每个流对象内部都维护着一组状态标志，用于记录最近一次操作的结果。当读写失败或到达末尾时，流会进入相应的状态，此时继续使用该流将不再生效，必须先清除状态。常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`good()`</font> | <font size=2>一切正常，没有任何错误标志</font> |
| <font size=2>`eof()`</font> | <font size=2>已到达文件末尾 eof（end of file）</font> |
| <font size=2>`fail()`</font> | <font size=2>发生了逻辑错误（如类型不匹配），或已到达文件末尾</font> |
| <font size=2>`bad()`</font> | <font size=2>发生了严重的读写错误（如设备故障、数据损坏）</font> |
| <font size=2>`clear()`</font> | <font size=2>清除所有状态标志，使流恢复可用</font> |
| <font size=2>`ignore(n, delim)`</font> | <font size=2>丢弃至多 `n` 个字符，直到遇到分隔符 `delim` 为止</font> |

流对象可以隐式转换为 `bool`，相当于判断 `!fail()`，因此最常见的写法是把读取操作直接放进条件中。

``` C++
int x;
std::cin >> x;              // 若输入 "abc"
if (!std::cin) {            // 等价于 std::cin.fail()
    std::cout << "输入失败" << std::endl;
    std::cin.clear();       // 清除错误标志，使流恢复可用
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); // 丢弃本行剩余内容
}

int n;
while (std::cin >> n) {     // 读取成功则继续，失败或到达末尾时自动退出
    std::cout << n << ' ';
}
```

> 用 `while (!std::cin.eof()) { ... }` 判断输入结束是一种常见的<u>错误</u>写法：只有当读操作读到末尾之后，`eof` 标志才会被置上，因此循环体会多执行一次，最后一条数据被重复处理。正确做法是把读取操作本身放进条件，如 `while (std::cin >> n)` 或 `while (std::getline(std::cin, line))`。

### 文件流
文件的输入输出由 `<fstream>` 中的三个类提供，它们与 `std::cin` / `std::cout` 的用法几乎一致，只是需要先用文件名打开文件，用完后可以显式关闭（对象析构时也会自动关闭）：  

| <font size=2>类</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::ifstream`</font> | <font size=2>输入文件流，用于读取文件</font> |
| <font size=2>`std::ofstream`</font> | <font size=2>输出文件流，用于写入文件</font> |
| <font size=2>`std::fstream`</font> | <font size=2>输入输出文件流，既可读也可写</font> |

打开文件时可以通过第二个参数指定**打开模式 open mode**，多个模式用按位或 `|` 组合，常用的如下表：  

| <font size=2>打开模式</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::ios::in`</font> | <font size=2>以读方式打开</font> |
| <font size=2>`std::ios::out`</font> | <font size=2>以写方式打开（默认会截断已有内容）</font> |
| <font size=2>`std::ios::app`</font> | <font size=2>追加：所有写入都发生在文件末尾</font> |
| <font size=2>`std::ios::trunc`</font> | <font size=2>若文件已存在则清空其内容</font> |
| <font size=2>`std::ios::ate`</font> | <font size=2>打开后立即定位到文件末尾</font> |
| <font size=2>`std::ios::binary`</font> | <font size=2>以二进制方式打开，不做文本转换</font> |

``` C++
#include <fstream>
#include <iostream>
#include <string>

std::ofstream out("test.txt");   // 写文件：默认 out | trunc，会清空原内容
if (!out) std::cerr << "打开文件失败" << std::endl;
out << "第一行" << std::endl;
out << "第二行" << std::endl;
out.close();                     // 用完及时关闭

std::ifstream in("test.txt");    // 读文件
std::string line;
while (std::getline(in, line)) { // 逐行读取，直到文件末尾
    std::cout << line << std::endl;
}
in.close();
```

> 打开文件后应当用 `is_open()`（或直接判断流对象）检查是否成功。`std::ofstream` 默认以 `out | trunc` 打开，若想在文件末尾追加内容，需要显式指定 `std::ios::app`。另外，关闭后流的状态标志不会自动清除，若要复用同一个流对象继续打开其它文件，应先调用 `clear()`。

### 字符串流
`std::istringstream`、`std::ostringstream` 与 `std::stringstream`（位于 `<sstream>`）把流的概念用在了字符串上：它们不读写外部设备，而是在内存中的字符串上进行输入输出，常用于拼接复杂文本或解析按字段分隔的数据。  

| <font size=2>类</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::istringstream`</font> | <font size=2>从一个字符串中读取数据</font> |
| <font size=2>`std::ostringstream`</font> | <font size=2>把数据写入其中，最终得到一个字符串</font> |
| <font size=2>`std::stringstream`</font> | <font size=2>既可读也可写</font> |

``` C++
#include <sstream>
#include <string>

std::ostringstream oss;                  // 拼接字符串
oss << "坐标：(" << 1 << ", " << 2 << ")，名称：" << "玩家";
std::string text = oss.str();            // str() 取出内部的字符串
std::cout << text << std::endl;          // 输出 坐标：(1, 2)，名称：玩家

std::istringstream iss("42 3.14 hello"); // 按空白切分字段
int i; double d; std::string s;
iss >> i >> d >> s;
std::cout << i << ' ' << d << ' ' << s << std::endl; // 输出 42 3.14 hello
```

> `>>` 默认以空白为分隔，若要解析形如 `a,b,c` 的数据，可以改用 `std::getline(iss, field, ',')` 按逗号逐个取出。同一个 `std::stringstream` 对象可以重复使用：先用 `str("")` 清空内容，再调用 `clear()` 清除状态标志，即可重新读写。
