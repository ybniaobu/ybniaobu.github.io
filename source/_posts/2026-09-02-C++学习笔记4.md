# 第十七章 智能指针与内存管理
之前的例子中，对动态内存的管理都是通过 `new` 和 `delete` 来手动管理的。然而，手动管理动态内存很容易出问题，因为确保在正确的时间释放内存是相对困难的：如果忘记调用 `delete`，被分配的内存就无法归还给系统，从而产生**内存泄漏 memory leak**；如果释放得过早，指针就会变成指向已销毁对象的**悬空指针 dangling pointer**；如果对同一块内存释放两次，还会发生**二次释放 double free**。而悬空指针与二次释放都属于**未定义行为 undefined behavior**，轻则导致程序崩溃，重则破坏数据、引发难以排查的安全漏洞。此外，若在 `new` 之后、对应的 `delete` 之前抛出异常，释放内存的语句将永远无法执行，同样会造成内存泄漏。可见，仅仅依靠 `new`/`delete` 来手动管理内存，既不安全，也不省心。  

为此，C++ 11 标准库引入了**智能指针 smart pointer**。智能指针在行为上类似内置指针，但它的核心价值在于可以自动管理所指向对象的生命周期：借助后面将要介绍的 **RAII** 思想，当智能指针对象被销毁时，它会自动释放所管理的内存，使程序员无需（也不应）再手动调用 `delete`。C++ 11 一共提供了三种智能指针（位于头文件 `<memory>` 中）：独占对象所有权的 `unique_ptr`、可共享对象所有权的 `shared_ptr`，以及配合 `shared_ptr` 使用、不增加引用计数的 `weak_ptr`，它们分别适用于不同的所有权模型。

## RAII 思想
**资源获取即初始化 resource acquisition is initialization (RAII)** 是一种借助对象的生命周期来管理资源的编程思想，简单来说就是一句话：<u>在构造函数中获取资源，在析构函数中释放资源</u>。只要把某份资源的生命周期绑定到一个局部对象的生命周期上，那么无论该对象是正常离开作用域，还是因异常触发栈展开而被销毁，其析构函数都一定会被执行，资源也就一定能得到释放，程序员无需手动触发。其中的**资源 resource** 是一个相当宽泛的概念，包括：动态内存、文件句柄、互斥锁、数据库连接、网络套接字等。下面用一个简单的例子来演示 RAII 的工作方式：  

``` C++
class IntArray {
private:
    int* data; // 原始资源（动态数组）
    size_t size;

public:
    // 构造函数：获取资源（分配内存）
    IntArray(size_t sz) : size(sz), data(new int[sz]) {
        std::cout << "获取资源：分配了 " << sz << " 个 int 内存" << std::endl;
    }

    // 析构函数：释放资源（回收内存）
    ~IntArray() {
        delete[] data;
        std::cout << "释放资源：回收了 " << size << " 个 int 内存" << std::endl;
    }

    void setValue(size_t index, int value) {
        if (index < size) data[index] = value;
    }
    int getValue(size_t index) const {
        return (index < size) ? data[index] : -1;
    }
};

int main() {
    IntArray arr(5); // 构造：自动分配内存
    arr.setValue(0, 100);
    std::cout << "arr[0] = " << arr.getValue(0) << std::endl;
    // 离开这个作用域时，arr 的析构函数被自动调用！
}
```

输出：  

    获取资源：分配了 5 个 int 内存
    arr[0] = 100
    释放资源：回收了 5 个 int 内存

## unique_ptr
`std::unique_ptr` 用于管理动态分配对象的生命周期，其实例拥有所指向对象的**独占所有权 exclusive ownership**，不允许拷贝构造或拷贝赋值，但支持移动语义，即所有权可以通过 `std::move` 转移。当实例被销毁，即离开作用域或被显式重置时，它会调用**删除器 deleter**（默认使用 delete）释放所管理的对象，允许用户提供自定义删除器。`unique_ptr` 是首选智能指针，常用于替代裸指针，内部也通常只存储一个裸指针，并持有一个删除器实例（默认删除器无状态，不占额外空间）。

### 创建 unique_ptr
当我们定义一个 `unique_ptr` 时，我们可以将其绑定到一个 `new` 返回的指针上。但 C++ 14 起，提供了一种更安全、更推荐的构造方式，即 `std::make_unique<T>()`。`unique_ptr` 的用法与普通指针几乎一致，当它离开作用域被销毁时，会自动释放所管理的对象，程序员无需也不应再手动调用 `delete`。同时为数组提供了特化 `std::unique_ptr<T[]>`，调用 `delete[]`，但该特化不提供 `*` 和 `->` 操作符，只提供 `[]` 索引，建议直接使用 `std::array`。实例如下：  

``` C++
std::unique_ptr<int> p1(new int(42)); // 直接接管 new 出来的裸指针
std::unique_ptr<int[]> arr1(new int[10]); // 指向 int 数组
auto p2 = std::make_unique<int>(42); // C++ 14 起
auto arr2 = std::make_unique<int[]>(10); // 指向 int 数组

arr1[0] = 5; // 支持下标访问
std::cout << *p2 << std::endl; // 输出 42
```

由于一个 `unique_ptr` 拥有它指向的对象，因此不支持普通的拷贝或赋值操作。如果允许拷贝，两个 `unique_ptr` 会同时以为自己独占同一个对象，销毁时就会对同一块内存重复执行 `delete`，即二次释放。因此拷贝会直接导致编译错误，所有权只能通过移动来转移，借助 `std::move` 把对象的所有权从一个 `unique_ptr` 完整交给另一个，转移后原指针自动变为空，例如：  

``` C++
std::unique_ptr<int> p1 = std::make_unique<int>(42);
// std::unique_ptr<int> p2 = p1;         // 错误！unique_ptr 不可拷贝（编译期报错）
std::unique_ptr<int> p3 = std::move(p1); // 移动：所有权转移给 p3，p1 变为空
std::cout << !p1 << std::endl; // 输出 1

std::unique_ptr<int> createNumber(int v) { // 从函数返回 unique_ptr 时会自动移动
    return std::make_unique<int>(v);
}
auto q = createNumber(7); // q 接管函数内部创建的对象
std::cout << *q << std::endl; // 输出 7
```

### 常用成员函数
`unique_ptr` 常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`get()`</font> | <font size=2>返回所管理的裸指针，所有权仍归该 `unique_ptr`</font> |
| <font size=2>`release()`</font> | <font size=2>放弃所有权但不释放资源：返回裸指针并把自身置空，之后必须由调用者负责释放资源，手动 delete</font> |
| <font size=2>`reset(q)`</font> | <font size=2>释放当前管理的对象，并可选地改而接管新指针 `q`（无参调用时仅释放并置空）</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个 `unique_ptr` 交换各自管理的对象</font> |

``` C++
auto p = std::make_unique<int>(10);
int* raw = p.get(); // get：取出裸指针查看，p 仍是唯一所有者
*raw = 20; // 通过解引用正常读写
std::cout << *p << std::endl; // 输出 20

p.reset(new int(30)); // reset：释放 20，改而接管新的 30
std::cout << *p << std::endl; // 输出 30
p.reset(); // reset()：释放 30，p 变为空
std::cout << !p << std::endl; // 输出 1

int* r = new int(40);
std::unique_ptr<int> q(r); // q 接管裸指针 r
int* taken = q.release(); // release：q 放弃所有权并置空，返回 r
std::cout << !q << std::endl; // 输出 1
delete taken; // 此后必须手动 delete，否则会造成内存泄漏
```

### 自定义删除器
`unique_ptr` 的第二个模板参数是删除器类型，默认使用 `std::default_delete<T>`，即对它管理的指针调用 `delete`。当对象需要特殊的释放方式时，可以传入自定义删除器，例如：  

``` C++
// 自定义删除器：接收一个 T*，负责释放该资源
auto loggingDeleter = [](int* p) {
    std::cout << "正在释放 int" << std::endl;
    delete p;
};
std::unique_ptr<int, decltype(loggingDeleter)> p(new int(42), loggingDeleter);
// p 销毁时会调用 loggingDeleter，而不是默认的 delete
```

## shared_ptr
`std::shared_ptr` 与 `unique_ptr` 的独占模型不同，多个实例可以共同拥有并管理同一个对象，即**共享所有权 shared ownership**。其实现依赖**引用计数 reference counting**，即每个被管理的对象都关联着一个计数，记录当前有多少个 `shared_ptr` 指向它，每通过拷贝或赋值新增一个共享该对象的 `shared_ptr`，引用计数加一；每销毁或重置一个，计数减一；当计数归零，即不再有任何 `shared_ptr` 指向该对象时，对象才会被自动释放。

引用计数存放在一块单独分配的**控制块 control block** 中，因此 `shared_ptr` 内部通常保存两个指针，一个指向所管理的对象，一个指向控制块。控制块由第一个接管对象的 `shared_ptr` 创建，其中一般包括：  
1. **强引用计数 strong reference count**：记录当前有多少个 `shared_ptr` 共享该对象，归零时销毁对象，但控制块本身未必随之释放；  
2. **弱引用计数 weak reference count**：记录指向该对象的 `weak_ptr` 数量，强计数与弱计数都归零时控制块才会被真正释放（详见后文 `weak_ptr` 一节）；  
3. **删除器 deleter**：销毁对象时使用的可调用对象，默认是 `delete`，允许用户自定义；  
4. **分配器 allocator**：若用户提供了自定义分配器，也一并保存在控制块中；  
5. **指向所管理对象的指针**（或对象本身）：从裸指针构造时，控制块只存指向对象的指针。使用 `make_shared` 创建时，对象与控制块位于同一次分配中，此时控制块内直接包含对象本身。

### 创建 shared_ptr
创建 `shared_ptr` 的方式跟 `unique_ptr` 类似，可以直接接管 `new` 返回的指针，也可以使用 `std::make_shared<T>()`，更建议使用该函数，因为它把对象本身与控制块合并到同一次内存分配中完成，既减少了一次堆分配，也提升了缓存局部性。若希望对象的内存来自自定义分配器，可以使用 `std::allocate_shared<T>(alloc, args...)`，`make_shared` 可视作传入默认分配器的特例。创建之后，`shared_ptr` 的用法与普通指针几乎一致，并且支持拷贝：  

``` C++
std::shared_ptr<int> p1; // 默认构造，创建一个空的 shared_ptr
std::shared_ptr<int> p2(new int(10)); // 指针构造，从原始指针获取所有权，不推荐
std::shared_ptr<int> p3(p2); // 拷贝构造，共享所有权，引用计数 +1
std::shared_ptr<int> p4(std::move(p3)); // 移动构造，转移所有权，p3 变为空
auto p5 = std::make_shared<int>(42); // 最推荐的方式
```

> C++ 17 起，`shared_ptr` 也提供了数组特化 `std::shared_ptr<T[]>`，其析构时调用 `delete[]`（C++ 17 之前需借助自定义删除器实现）。

`shared_ptr` 支持拷贝构造与拷贝赋值，也支持移动语义，移动不增减引用计数，只是把所有权从一个 `shared_ptr` 转给另一个。此外，`unique_ptr` 可以通过移动单向转换为 `shared_ptr`，反之则不行：  

``` C++
auto up = std::make_unique<int>(42);
std::shared_ptr<int> sp = std::move(up); // 独占所有权 -> 共享所有权，up 变为空
```

### 常用成员函数
`shared_ptr` 常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`get()`</font> | <font size=2>返回所管理的裸指针，所有权仍归各 `shared_ptr` 共享</font> |
| <font size=2>`reset(q)`</font> | <font size=2>放弃当前所有权（计数减一），并可选地改而接管新指针 `q`（无参调用时仅放弃并置空）</font> |
| <font size=2>`use_count()`</font> | <font size=2>返回共享当前对象的 `shared_ptr` 数量</font> |
| <font size=2>`unique()`</font> | <font size=2>判断当前是否为唯一拥有者，等价于 `use_count() == 1`，C++ 20 起被标记为弃用，C++ 23 中已移除</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个 `shared_ptr` 交换各自管理的对象</font> |

``` C++
auto p1 = std::make_shared<int>(42); // 创建：p1 是唯一拥有者
int* raw = p1.get(); // get：取出裸指针查看，所有权仍归 p1
*raw = 20; // 通过解引用正常读写
std::cout << *p1 << std::endl; // 输出 20

auto p2 = p1; // 拷贝：引用计数加一
std::cout << p1.use_count() << std::endl; // 输出 2（p1、p2 共享同一份计数）

p2.reset(); // reset()：p2 放弃所有权并置空，计数减一
std::cout << (p1.use_count() == 1) << std::endl; // 输出 1（p1 重新成为唯一拥有者）

auto p3 = std::make_shared<int>(7);
p1.swap(p3); // swap：与 p3 交换各自管理的对象
std::cout << *p1 << std::endl; // 输出 7
std::cout << *p3 << std::endl; // 输出 20
```

### 注意事项
①不要用同一个裸指针构造多个 `shared_ptr`：  
每个由裸指针独立构造的 `shared_ptr` 都会创建各自独立的控制块，彼此不知道对方的存在，析构时会对同一块内存重复 `delete`。正确做法是拷贝已有的 `shared_ptr` 来共享所有权，或者直接使用 `make_shared`：  

``` C++
int* raw = new int(42);
std::shared_ptr<int> p1(raw);
std::shared_ptr<int> p2(raw); // 错误！p1、p2 各有独立的控制块，析构时二次释放
```

②**循环引用 circular reference** 问题：  
引用计数无法处理循环引用，若两个对象各自持有指向对方的 `shared_ptr`，它们的引用计数永远无法归零，即使外部已没有任何指针可达，这两个对象也不会被释放，从而造成内存泄漏。解决办法是把其中一环换成不增加引用计数的 `weak_ptr`，这正是下一小节要介绍的内容。

③线程安全性：  
`shared_ptr` 的线程安全是有条件的，主要保证的是控制块内部的引用计数操作。引用计数的增减是原子的，即多个线程分别持有指向同一对象的 `shared_ptr`，各自独立地进行拷贝、析构或 `reset()` 时是安全的，计数不会出错，对象也只会被释放一次。但被管理的对象本身并不是线程安全的，多个线程同时通过 `shared_ptr` 读写同一个对象仍需加锁或使用其他同步手段。此外，同一个 `shared_ptr` 实例被多个线程同时读写是不安全的，需要借助互斥锁等保证同步，正确做法是各线程先拷贝出属于自己的那份 `shared_ptr` 再使用。

## weak_ptr
`std::weak_ptr` 是一种不控制对象生命周期的智能指针，表示对某个由 `shared_ptr` 管理的对象的弱引用，但不增加其强引用计数，常用于打破 `shared_ptr` 之间的循环引用。其内部同样保存指向控制块的指针，但它只增加控制块中的弱引用计数。由于对象可能已被销毁，`weak_ptr` 不提供 `*` 和 `->` 访问对象，必须通过成员函数 `lock()` 尝试提升为 `shared_ptr`，成功时返回非空 `shared_ptr` 并可安全访问，强引用计数 + 1，失败时返回空 `shared_ptr`。

### 创建 weak_ptr
`weak_ptr` 通常由 `shared_ptr` 或另一个 `weak_ptr` 构造或赋值而来，例如：  

``` C++
std::weak_ptr<int> wp1; // 默认构造，创建一个空的 weak_ptr
auto sp = std::make_shared<int>(42);
std::weak_ptr<int> wp2(sp); // 从 shared_ptr 构造，观察 sp 但不增加强引用计数
std::weak_ptr<int> wp3(wp2); // 拷贝构造，与 wp2 观察同一对象
std::weak_ptr<int> wp4(std::move(wp3)); // 移动构造，wp3 变为空
```

注意，不能直接从 `weak_ptr` 构造 `shared_ptr`，唯一正规途径是调用 `lock()` 显式提升，让编译器强制你在使用前检查对象是否仍然存活。

### 常用成员函数
`weak_ptr` 常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`expired()`</font> | <font size=2>判断所观察的对象是否已被销毁</font> |
| <font size=2>`lock()`</font> | <font size=2>返回指向该对象的 `shared_ptr`；若对象已销毁，则返回空的 `shared_ptr`</font> |
| <font size=2>`use_count()`</font> | <font size=2>返回与当前 `weak_ptr` 共享所有权的 `shared_ptr` 数量</font> |
| <font size=2>`reset()`</font> | <font size=2>将 `weak_ptr` 置空</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个 `weak_ptr` 交换各自观察的对象</font> |

核心操作是 `lock()`：若对象仍存在，`lock()` 返回一个共享所有权的 `shared_ptr`；若对象已被释放，`lock()` 返回一个空的 `shared_ptr`。在访问前，可以通过 `expired()` 成员函数判断对象是否已销毁（等价于 `use_count() == 0`）。  

``` C++
auto sp = std::make_shared<int>(42);
std::weak_ptr<int> wp(sp); // 构造，wp 观察 sp 但不增加强引用计数
std::cout << wp.use_count() << std::endl; // 输出 1（use_count 返回强引用计数，weak_ptr 不影响它）

if (auto spt = wp.lock()) { // lock：尝试获取 shared_ptr
    std::cout << *spt << std::endl; // 输出 42
    std::cout << wp.use_count() << std::endl; // 输出 2（提升成功，强引用计数 +1）
} // spt 离开作用域被销毁，强引用计数回落为 1
std::cout << wp.use_count() << std::endl; // 输出 1

sp.reset(); // 释放 sp 后，对象被销毁，wp 过期
std::cout << wp.use_count() << std::endl; // 输出 0
std::cout << wp.expired() << std::endl; // 输出 1
```

### 解决循环引用
循环引用是指两个对象通过 `shared_ptr` 互相持有，导致引用计数永远不归零，即使外部没有任何指针指向它们，内存也无法释放。将其中一个成员改为 `weak_ptr` 即可打破这种死锁：  

``` C++
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;  // 反向使用 weak_ptr，避免循环

    ~Node() {
        std::cout << "Node destroyed\n";
    }
};

int main() {
    auto a = std::make_shared<Node>();
    auto b = std::make_shared<Node>();

    a->next = b;   // b 强计数 +1
    b->prev = a;   // a 强计数不变，只增加弱计数

    // 离开作用域后，a、b 都能正常销毁
}
```

在上例中，若 prev 也使用 `shared_ptr<Node>`，则引用计数永远至少为 1，析构函数将永远不会被调用，从而导致内存泄漏。

## new / delete
在之前的笔记中已经介绍过 `new` / `delete` 的基本用法，这里再深入到它们背后的机制。一个 `new` 表达式实际上完成了两件事：①调用名为 `operator new` 的函数，向系统申请一块足够大的**原始内存 raw memory**；②在这块内存上调用对象的构造函数完成初始化。与之对应，一个 `delete` 表达式同样分为两步：①先调用对象的析构函数完成清理；②再调用名为 `operator delete` 的函数把内存归还给系统。

因此需要区分两组概念：`new` / `delete` 是 C++ 的关键字，由它们构成的 new 表达式与 delete 表达式属于运算符，负责把分配与构造、析构与释放组合在一起。而 `operator new` / `operator delete` 是函数，标准中分别称为**分配函数 allocation function** 与**释放函数 deallocation function**，它们按作用域分为两类：①**全局版本**，写作 `::operator new` / `::operator delete`，标准库为它们提供了一份默认实现，同时标准也允许用户把它替换掉；②**类内重载的版本**，作为该类的静态成员函数，只作用于这个类的 new / delete 表达式。真正向系统申请和归还内存的始终是这两个函数，new / delete 表达式不过是它们与构造函数、析构函数调用的组合。

> 分配释放函数虽然在 `<new>` 头文件中，但常规形式不需要包含 `<new>` 也能使用，因为标准规定普通版本、数组版本以及 C++ 17 起的对齐版本（即不带 `nothrow` / `placement` 额外参数的几种）会在每个翻译单元中被隐式声明。

### operator new / delete
`operator new` / `operator delete` 只负责分配和释放原始内存，既不构造也不析构对象，只保证分配或释放一块大小与对齐都符合要求的、未初始化的内存。其常见形式如下表所示：  

| <font size=2>函数形式</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`void* operator new(std::size_t n)`</font> | <font size=2>分配 `n` 字节原始内存，失败时抛出 `std::bad_alloc`</font> |
| <font size=2>`void operator delete(void* p) noexcept`</font> | <font size=2>释放 `p` 指向的内存，不调用析构函数</font> |
| <font size=2>`void operator delete(void* p, std::size_t n) noexcept`</font> | <font size=2>sized deallocation，C++ 14 起</font> |
| <font size=2>`void* operator new[](std::size_t n)`</font> | <font size=2>供 `new T[]` 使用的数组版本</font> |
| <font size=2>`void operator delete[](void* p) noexcept`</font> | <font size=2>供 `delete[]` 使用的数组版本</font> |
| <font size=2>`void* operator new(std::size_t n, const std::nothrow_t&) noexcept`</font> | <font size=2>配合 `new (std::nothrow) T` 使用，失败时返回 `nullptr`</font> |
| <font size=2>`void operator delete(void* p, const std::nothrow_t&) noexcept`</font> | <font size=2>与上面对应的释放函数</font> |
| <font size=2>`void* operator new(std::size_t n, std::align_val_t al)`</font> | <font size=2>C++ 17 起的对齐版本，分配对齐到 `al` 的内存</font> |
| <font size=2>`void operator delete(void* p, std::align_val_t al) noexcept`</font> | <font size=2>C++ 17 起的对齐版本释放函数</font> |

> new / delete 表达式中调用哪一个由编译器决定的：过对齐 over-aligned 类型会自动改用对齐版本，`new (std::nothrow) T` 会选出带 `nothrow` 的版本，带大小的释放函数是否被采用也依编译器与编译选项而定。使用 new / delete 表达式时不需要关心选中的是哪一个，只有自己手动调用这些函数时，才要保证分配与释放的形式相互匹配。

``` C++
void* raw = ::operator new(sizeof(std::string)); // 只申请 sizeof(std::string) 字节的原始内存
::operator delete(raw); // 直接调用释放函数，不调用析构函数

std::string* ps = new std::string("hello"); // new 表达式：先 operator new 分配，再调用构造函数
delete ps; // 先调用析构函数，再 operator delete 释放
```

#### 类内重载
可以在类内定义 `operator new` / `operator delete` 函数，同时它们隐含为静态成员函数，`static` 关键字可写可不写。类内定义之后，`new T` 会先在类作用域中查找，找不到才使用全局版本，并且按照名字查找规则，类内查找到的版本会<u>隐藏</u>掉所有全局版本。下面用一个简单的例子来演示：  

``` C++
class Widget {
public:
    static void* operator new(std::size_t size) { // 隐含为 static，不能是虚函数
        std::cout << "分配 " << size << " 字节\n";
        return ::operator new(size); // 具体分配仍转交给全局版本
    }
    static void operator delete(void* p) noexcept {
        std::cout << "释放内存\n";
        ::operator delete(p);
    }
    // ... 其他成员
};

Widget* w = new Widget(); // 输出：分配 1 字节，随后调用构造函数
delete w; // 输出：释放内存
```

#### 全局替换
如果在全局作用域中按规定的签名定义一份 `operator new` / `operator delete`，就会<u>替换</u>掉标准库的默认实现，整个程序中所有 new / delete 表达式都会改用这份实现，它们因此被称为**可替换的全局分配/释放函数 replaceable global allocation/deallocation function**。由于默认分配器 `std::allocator`（分配器下一小节讲）的 `allocate()` 成员函数正是调用 `::operator new`，替换之后连 STL 容器的内存来源也会一并改变，这正是实现内存池、分配统计与泄漏检测最方便的切入点。

替换时需要遵守几条规则：必须定义在全局作用域，不能放进命名空间或类中，也不能声明为 `inline`，各版本（普通、数组、`nothrow`、`sized` 乃至对齐版本）最好成套替换，以免分配用一种、释放却用另一种。一个简单的示例如下：  

``` C++
void* operator new(std::size_t sz) {
    if (void* p = std::malloc(sz)) return p;
    throw std::bad_alloc();
}

void operator delete(void* p) noexcept {
    std::free(p);
}
```

另外，可以在 new 表达式里用 `::` 显式指定使用全局版本：  

``` C++
Widget* w1 = new Widget();   // 使用 Widget 类内重载的 operator new
Widget* w2 = ::new Widget(); // 强制使用全局 ::operator new
::delete w2;                 // 强制使用全局 ::operator delete
```

### placement new
**placement new** 是 new 表达式的一种形式，它不在堆上申请新内存，而是在调用者提供的已有内存上直接构造对象。写法是在 `new` 之后紧跟一对括号，括号中给出额外参数，例如 `new (buf) T(args)`，其中 `buf` 就是预先准备好的内存地址。标准库在 `<new>` 中为此专门提供了相关的分配函数：

``` C++
void* operator new(std::size_t, void* p) noexcept { return p; } // 原样返回传入的地址
```

正因为这个重载版本什么都不做，只是把地址原封不动地交回来，所以 `new (buf) T` 最终只完成了调用构造函数这一步，而准备内存这一步完全由调用者自己负责。placement new 的典型用途包括：STL 容器在自己的缓冲区中构造元素、内存池避免频繁向系统申请内存、为对象预留一块长期存在且地址稳定的内存等。示例如下：  

``` C++
#include <new>
#include <string>

// ① 准备一块足够大且对齐正确的原始内存（这里放在栈上）
alignas(std::string) unsigned char buf[sizeof(std::string)];

// ② 在这块内存上调用构造函数构造对象
std::string* ps = new (buf) std::string("hello");
std::cout << *ps << std::endl; // 输出 hello

// ③ 用完必须手动调用析构函数，但不能对 ps 使用 delete，属于未定义行为
ps-> std::string::~string(); // C++ 17 起也可写成 std::destroy_at(ps);
```

> 由于 placement new 的在已有内存上构造对象这一语义与分配器分配与构造分离的目标完全一致，C++ 20 之前 `std::allocator::construct` 内部就是借助 placement new 实现的，C++ 20 之后则由 `std::construct_at` 取代。`std::uninitialized_copy`、`std::uninitialized_fill` 等未初始化内存算法也都建立在它之上。

### nothrow new
默认的分配函数在申请内存失败时会抛出 `std::bad_alloc` 异常，这会打断正常的控制流。若希望像 C 语言的 `malloc` 那样，在失败时<u>返回空指针</u>而不是抛出异常，就可以使用 **nothrow new**。写法是在 `new` 之后紧跟 `(std::nothrow)`，此时编译器会选用带 `const std::nothrow_t&` 参数的分配函数：  

``` C++
#include <new>

int* p = new (std::nothrow) int(42); // 失败时返回空指针，不会抛出异常
if (p) {
    std::cout << *p << std::endl; // 输出 42
    delete p;
}

int* arr = new (std::nothrow) int[1'000'000'000'000]; // 申请一个超大的数组，失败时得到空指针
std::cout << !arr << std::endl; // 很可能输出 1，表示分配失败
delete[] arr; // 对空指针执行 delete 是安全的，什么也不做
```

## 分配器
`std::allocator<T>` 是 C++ 标准库中的默认内存**分配器 allocator**，定义在 `<memory>` 头文件中。它将内存分配与对象构造两个步骤分离：先分配原始内存，再在其上调用构造函数；销毁时先调用析构函数，再释放内存。而 `new` 将内存分配和对象构造组合在了一起，`delete` 将对象析构和内存释放组合在了一起。STL 容器（如 `vector`、`list`）默认使用该分配器，但也允许用户传入自定义分配器，以满足特定的内存管理需求，例如使用内存池、共享内存或跟踪内存分配统计等。

> C++ 17 引入 `std::pmr::polymorphic_allocator`（位于 `<memory_resource>`），允许在运行时指定内存资源，适合构建内存池等复杂系统，属于更高级的内存管理技术。

### 核心成员函数
`std::allocator` 是最简单的分配器，其成员函数 `allocate()` 和 `deallocate()` 封装了全局 `::operator new` 和 `::operator delete` 的调用。日常编程中很少直接使用它，因为它主要服务于标准库容器的内部实现，但了解其接口有助于理解容器的工作原理。其核心成员函数如下表所示：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`allocate(n)`</font> | <font size=2>分配能容纳 `n` 个 `T` 对象的原始内存，返回 `T*`，不构造对象</font> |
| <font size=2>`deallocate(p, n)`</font> | <font size=2>释放由 `allocate` 分配的内存，`p` 必须指向之前分配的内存首地址</font> |
| <font size=2>`construct(p, args)`</font> | <font size=2>在已分配的内存 `p` 处用 `args` 构造对象（C++ 20 已移除）</font> |
| <font size=2>`destroy(p)`</font> | <font size=2>销毁 `p` 指向的对象但不释放内存（C++ 20 已移除）</font> |
| <font size=2>`max_size()`</font> | <font size=2>返回理论上最多能分配的元素个数（C++ 20 已移除）</font> |

> C++ 20 起，`construct` 和 `destroy` 成员被移除，可以使用 `std::construct_at` 和 `std::destroy_at` 自由函数。

``` C++
std::allocator<int> alloc; // 定义一个 int 类型的分配器

int* p = alloc.allocate(5); // 分配能容纳 5 个 int 的原始内存（未构造）
alloc.construct(p, 42); // 在 p 处构造一个 int，值为 42（C++ 20 起移除，改用 std::construct_at）
alloc.destroy(p); // 调用析构函数销毁对象（C++ 20 起移除，改用 std::destroy_at）
alloc.deallocate(p, 5); // 释放内存
```

> 按照 C++ 11 以来的约定，应当通过 `std::allocator_traits` 与分配器交互，而不是直接调用分配器自身的成员，它统一了分配器接口，当分配器未提供 `pointer`、`size_type`、`construct`、`destroy` 等可选成员时，会由它提供默认实现。这也是 C++ 20 移除 std::allocator 的 construct、destroy、max_size 之后仍可继续使用的入口。


# 第十八章 字符串与 I/O 流
## 字符串
C++ 中的字符串处理主要依靠标准库提供的专门类型，而不是 **C 风格字符串**（已在第二章类型、变量与声明的[字面量](https://ybniaobu.github.io/2026/05/10/2026-05-10-C++%E5%AD%A6%E4%B9%A0%E7%AC%94%E8%AE%B01/#%E5%AD%97%E7%AC%A6%E4%B8%B2%E5%AD%97%E9%9D%A2%E9%87%8F)小节中详细讨论过）。后者需要手动管理内存，容易出现忘记结尾空字符 `'\0'`、缓冲区溢出、越界访问等问题。为此，标准库在头文件 `<string>` 中定义了一个通用的字符串模板 `std::basic_string`，并为常用的字符类型分别准备了别名，如下表：  

| <font size=2>别名</font> | <font size=2>实际类型</font> | <font size=2>字符类型</font> |
| :---- | :---- | :---- |
| <font size=2>`std::string`</font> | <font size=2>`std::basic_string<char>`</font> | <font size=2>`char`</font> |
| <font size=2>`std::wstring`</font> | <font size=2>`std::basic_string<wchar_t>`</font> | <font size=2>`wchar_t`</font> |
| <font size=2>`std::u16string`</font> | <font size=2>`std::basic_string<char16_t>`</font> | <font size=2>`char16_t`</font> |
| <font size=2>`std::u32string`</font> | <font size=2>`std::basic_string<char32_t>`</font> | <font size=2>`char32_t`</font> |
| <font size=2>`std::u8string`</font> | <font size=2>`std::basic_string<char8_t>`</font> | <font size=2>`char8_t`（C++ 20 起）</font> |

``` C++
std::string str = "普通字符";
std::wstring wstr = L"宽字符";
std::u16string u16 = u"UTF-16";
std::u32string u32 = U"UTF-32";
std::u8string  u8  = u8"UTF-8"; 
```

由于在绝大多数场景中，使用的都是 `std::string`，它和 C 风格字符串兼容，也可以存储 UTF-8，故下面主要介绍 `std::string` 以及用于高效访问字符串数据的字符串视图 `std::string_view`。

### string
`std::string` 是 `std::basic_string<char>` 的类型别名，表示由 `char` 组成的动态字符序列，它的字符在内存中连续存储（C++ 11 起由标准保证），内存由对象自动管理、按需扩容，因此可以将其理解为字符向量 `vector<char>`，只是说它保证在序列末尾额外存放一个 `'\0'`，并提供了大量字符串专有的操作。与 vector 一样，在发生扩容或插入、删除后，原有的迭代器、指针与引用都可能失效。此外，`std::string` 内部通常还实现了**短字符串优化 short string optimization (SSO)**，当字符串很短时，字符直接存放在对象自身的内部缓冲区中，不进行堆分配，从而避免小字符串频繁申请内存，只在字符串较长时才把字符转移到堆上。

#### 构造与初始化
`std::string` 提供了很多构造函数，常用构造函数如下：  

``` C++
std::string s1;                             // 默认构造，空字符串
std::string s2("hello");                    // 从 C 风格字符串构造
std::string s3 = "hello";                   // 拷贝初始化，等价于上一种
std::string s4(s2);                         // 拷贝构造
std::string s5(5, 'a');                     // 填充构造，即 "aaaaa"
std::string s6(s2, 1, 3);                   // 子串构造，从下标 1 开始取 3 个字符，即 "ell"
std::string s7("hello", 3);                 // 长度构造，从 C 字符串取前 3 个字符，即 "hel"
std::string s8(s2.begin(), s2.begin() + 3); // 迭代器区间构造，即 "hel"
std::string s9(std::move(s2));              // 移动构造
std::string s10{'h', 'e', 'l', 'l', 'o'};   // 初始化列表构造
```

#### 容量与访问
`std::string` 很多成员函数的作用与 `std::vector` 一样：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`empty()`</font> | <font size=2>判断字符串是否为空</font> |
| <font size=2>`size()` / `length()`</font> | <font size=2>返回字符数（不包括结尾的 `\0`），两者完全等价</font> |
| <font size=2>`max_size()`</font> | <font size=2>返回字符数的最大值</font> |
| <font size=2>`reserve(n)`</font> | <font size=2>预分配至少能容纳 `n` 个字符的容量，避免多次扩容</font> |
| <font size=2>`capacity()`</font> | <font size=2>返回当前已分配、无需重新分配即可存放的字符数</font> |
| <font size=2>`shrink_to_fit()`</font> | <font size=2>请求把容量缩减到与大小匹配</font> |
| <font size=2>`at(pos)` / `operator[]`</font> | <font size=2>访问下标 `i` 处的字符，`at` 越界时抛出 `std::out_of_range`，`operator[]` 不做越界检查，越界属于未定义行为</font> |
| <font size=2>`front()` / `back()`</font> | <font size=2>返回首字符 / 尾字符的引用，在空字符串上调用属于未定义行为</font> |
| <font size=2>`data()` / `c_str()`</font> | <font size=2>返回指向底层字符数组首元素的指针，`c_str` 始终返回 `const char*`，`data` 在 C++ 17 起于非 const 对象上返回 `char*`</font> |
| <font size=2>`begin()` / `cbegin()`</font> | <font size=2>返回指向首字符的迭代器 / 只读迭代器</font> |
| <font size=2>`end()` / `cend()`</font> | <font size=2>返回指向尾后位置的迭代器 / 只读迭代器</font> |
| <font size=2>`rbegin()` / `crbegin()`</font> | <font size=2>返回指向尾字符的反向迭代器 / 只读反向迭代器，用于逆序遍历</font> |
| <font size=2>`rend()` / `crend()`</font> | <font size=2>返回指向首字符前一位置的反向迭代器 / 只读反向迭代器，标记逆序遍历的终点</font> |

``` C++
std::string s = "hello";
std::cout << s.empty() << std::endl;      // 输出 0（字符串非空）
std::cout << s.size() << std::endl;       // 输出 5
std::cout << s.length() << std::endl;     // 输出 5，与 size() 完全等价
std::cout << s.capacity() << std::endl;   // 输出当前容量，通常 >= size()（具体值依实现而定）
s.reserve(100);                           // 预留容量，避免后续追加时反复扩容
std::cout << s.capacity() << std::endl;   // 输出 >= 100
s.shrink_to_fit();                        // 请求把容量缩减到与大小匹配（非强制）
std::cout << s.capacity() << std::endl;   // 容量可能缩回与 size() 相近的值

std::cout << s[0] << std::endl;           // 输出 h
std::cout << s.at(1) << std::endl;        // 输出 e
s[0] = 'H';                               // 通过下标修改，得到 "Hello"
std::cout << s.front() << std::endl;      // 输出 H
std::cout << s.back() << std::endl;       // 输出 o
printf("%s\n", s.c_str());                // 输出 Hello，可直接传给 C 风格接口

for (auto it = s.rbegin(); it != s.rend(); ++it) { // rbegin / rend：反向遍历
    std::cout << *it;
}
std::cout << std::endl;                   // 输出 olleH
```

#### 修改操作
`std::string` 提供了很多用于修改内容的成员函数：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`clear()`</font> | <font size=2>从字符串中移除所有字符</font> |
| <font size=2>`insert(pos, s)`</font> | <font size=2>在下标 `pos` 处插入字符串</font> |
| <font size=2>`erase(pos, n)`</font> | <font size=2>删除从 `pos` 开始的 `n` 个字符（省略 `n` 时删到末尾）</font> |
| <font size=2>`push_back(c)` / `pop_back()`</font> | <font size=2>在末尾追加 / 删除一个字符</font> |
| <font size=2>`operator+=` / `append(s)`</font> | <font size=2>在末尾追加内容，`+=` 是最常用的拼接方式</font> |
| <font size=2>`replace(pos, n, s)`</font> | <font size=2>用字符串 `s` 替换从 `pos` 开始的 `n` 个字符</font> |
| <font size=2>`copy(dest, n, pos)`</font> | <font size=2>把从 `pos` 开始的 `n` 个字符复制到外部缓冲区 `dest`，不追加结尾的 `'\0'`，返回复制的字符数</font> |
| <font size=2>`resize(n, c)`</font> | <font size=2>把长度调整为 `n`，不足的部分用字符 `c`（省略时填 `'\0'`）填充</font> |
| <font size=2>`swap(other)`</font> | <font size=2>与另一个字符串高效交换内容</font> |

``` C++
std::string s = "hello";
s += " world";                   // "hello world"
s.append("!");                   // "hello world!"
s.push_back('?');                // "hello world!?"
s.pop_back();                    // "hello world!"
s.insert(5, ",");                // 在下标 5 处插入，"hello, world!"
s.erase(5, 1);                   // 删除下标 5 处的 1 个字符，"hello world!"
s.replace(0, 5, "HELLO");        // 把前 5 个字符替换为 "HELLO"，得到 "HELLO world!"

char buf[6] = {};                // copy()：把字符复制到外部缓冲区，不会自动补上 '\0'
size_t n = s.copy(buf, 5, 0);    // 从下标 0 开始复制 5 个字符到 buf，返回实际复制的字符数
buf[n] = '\0';                   // 因此需要自己补上结尾空字符
std::cout << buf << std::endl;   // 输出 HELLO

s.resize(14, '!');               // 长度不足时用 '!' 补足，得到 "HELLO world!!!"
s.resize(5);                     // 长度超出时直接截断，得到 "HELLO"
```

> `operator+` 与 `+=` 都会按需扩容，但 `operator+` 每次都会生成一个新的字符串对象，在循环中反复拼接时应改用 `+=` 或 `append`，必要时先用 `reserve` 预留容量，以减少不必要的内存分配与拷贝。

#### 查找与子串
`std::string` 提供了很多用于查找和截取的成员函数：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`find(s, pos)`</font> | <font size=2>从 `pos` 起向后查找首个子串 `s`，返回首次出现的下标，失败返回 `npos`</font> |
| <font size=2>`rfind(s, pos)`</font> | <font size=2>从 `pos` 起向前查找首个子串 `s`，返回最后一次出现的下标</font> |
| <font size=2>`find_first_of(s, pos)`</font> | <font size=2>从 `pos` 起向后查找 `s` 中任意一个字符首次出现的位置</font> |
| <font size=2>`find_last_of(s, pos)`</font> | <font size=2>从 `pos` 起向前查找 `s` 中任意一个字符最后一次出现的位置</font> |
| <font size=2>`find_first_not_of(s)`</font> | <font size=2>从 `pos` 起向后查找第一个不在 `s` 中的字符的位置</font> |
| <font size=2>`find_last_not_of(s)`</font> | <font size=2>从 `pos` 起向前查找最后一个不在 `s` 中的字符的位置</font> |
| <font size=2>`substr(pos, n)`</font> | <font size=2>返回从 `pos` 开始、长度为 `n` 的子串（省略 `n` 时取到末尾）</font> |
| <font size=2>`compare(s)`</font> | <font size=2>按字典序比较，小于返回负数，相等返回 0，大于返回正数</font> |
| <font size=2>`starts_with(s)` / `ends_with(s)`</font> | <font size=2>判断是否以 `s` 为前缀 / 后缀（C++ 20 起）</font> |

> `std::string::npos` 是一个静态常量，用于表示没有位置，其值通常是 `size_t` 的最大值。

``` C++
std::string s = "hello world";
std::cout << s.find("world") << std::endl;      // 输出 6
std::cout << s.rfind('o') << std::endl;         // 输出 7（从后往前找，最后一个 'o' 的下标）
std::cout << s.find("xyz") << std::endl;        // 输出 npos（一个极大的数）

std::cout << s.find_first_of("aeiou") << std::endl;    // 输出 1（第一个元音 'e' 的下标）
std::cout << s.find_last_of("aeiou") << std::endl;     // 输出 7（最后一个元音 'o' 的下标）
std::cout << s.find_first_not_of("hel") << std::endl;  // 输出 4（第一个不属于 "hel" 的字符 'o'）
std::cout << s.find_last_not_of("dl") << std::endl;    // 输出 8（最后一个不属于 "dl" 的字符 'r'）

std::cout << s.substr(6, 5) << std::endl;              // 输出 world
std::cout << s.compare("hello world") << std::endl;    // 输出 0（两者相等）
std::cout << s.compare("z") << std::endl;              // 输出负数（'h' 的字典序在 'z' 之前）
std::cout << s.starts_with("hello") << std::endl;      // 输出 1（C++ 20）
std::cout << s.ends_with("world") << std::endl;        // 输出 1（C++ 20）
```

#### 输入输出
`std::string` 可以直接配合标准输入输出流使用：输出用 `std::cout << s`，输入则有两种方式，`std::cin >> s` 以空白为分隔读取，`std::getline` 则读取一整行。它们的行为如下表所示：  

| <font size=2>方式</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::cin >> s`</font> | <font size=2>先跳过前导空白，再读到下一处空白为止，因此无法读入含空格的整行</font> |
| <font size=2>`std::getline(std::cin, s)`</font> | <font size=2>读取从当前位置到换行符 `\n` 为止的整行文本，换行符从 cin 中删除但不存入 `s`</font> |
| <font size=2>`std::getline(std::cin, s, delim)`</font> | <font size=2>指定分隔符 `delim`，读到该字符为止</font> |

``` C++
std::string word, line;
std::cin >> word;               // 第 1 次输入：hello
std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); // 清除换行
std::cout << word << std::endl; // 输出 hello

std::getline(std::cin, line);   // 第 2 次输入：hello world
std::cout << line << std::endl; // 输出 hello world

std::string word2, line2;
std::cin >> word2;              // 第 3 次输入：hello world，word2 得到 hello
std::getline(std::cin, line2);  // 直接读缓冲区剩余的 " world"
std::cout << word2 << line2 << std::endl; // 输出 hello world
```

> `std::cin` 和 `std::getline` 二者混用时要注意：`std::cin` 会把换行符留在输入缓冲区，紧接着调用 `getline` 会立刻读到这个换行符并返回空字符串，可先用 `std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n')` 丢弃该行剩余内容。另外，`std::getline` 是定义在 `<string>` 中的自由函数，不要与 `<istream>` 中读取 C 风格字符数组的成员函数 `istream::getline` 混淆。

#### 数值转换
字符串与数值之间的转换可以借助 `<string>` 中的一组函数完成：  

| <font size=2>函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::stoi(s)` / `std::stol(s)` / `std::stoll(s)`</font> | <font size=2>转换字符串为有符号整数，依次为 int、long、long long</font> |
| <font size=2>`std::stoul(s)` / `std::stoull(s)`</font> | <font size=2>转换字符串为无符号整数，依次为 unsigned long、unsigned long long</font> |
| <font size=2>`std::stof` / `stod` / `stold`</font> | <font size=2>转换字符串为浮点数，依次为 float / double / long double</font> |
| <font size=2>`std::to_string(v)`</font> | <font size=2>把数值转为字符串，支持各整数类型与浮点类型</font> |
| <font size=2>`std::to_wstring(v)`</font> | <font size=2>把数值转为宽字符串 `std::wstring`，接受与 `to_string` 相同的数值类型</font> |

``` C++
int i = std::stoi("42");                     // 42
long l = std::stol("2026");                  // 2026L
long long ll = std::stoll("9000000000");     // 9000000000LL
unsigned long ul = std::stoul("42");         // 42UL
unsigned long long ull = std::stoull("42");  // 42ULL
float f = std::stof("3.14");                 // 3.14f
double d = std::stod("3.14");                // 3.14
long double ld = std::stold("3.14");         // 3.14L

std::string s1 = std::to_string(2026);       // "2026"
std::string s2 = std::to_string(3.14);       // "3.140000"（浮点默认保留 6 位小数）
std::wstring ws = std::to_wstring(2026);     // L"2026"

// 指定进制：stoi 家族的第三个参数是进制，默认为 10
int bin = std::stoi("1010", nullptr, 2);     // 二进制 "1010" → 10
int hex = std::stoi("ff", nullptr, 16);      // 十六进制 "ff" → 255

// 反向（整数 -> 二进制字符串）没有对应的函数，可借助 std::bitset
std::string b = std::bitset<8>(10).to_string(); // "00001010"
```

> 从 C++ 17 起，`<charconv>` 提供了基于 `std::from_chars` / `std::to_chars` 的无异常、零分配转换接口，在高性能场景下比 `std::stoi` / `std::to_string` 更合适。

### string_view
`std::string_view` 是 C++ 17 引入的<u>只读</u>字符串视图，定义在 `<string_view>` 头文件中。它是对一段已存在字符序列的只读引用，本质上只保存一个指向字符数据的指针和一个长度，即可以理解为 `(const char*, size_t)`。<u>它不负责管理底层字符数据的内存，不能通过它修改底层字符</u>。跟 `std::string` 类似，它本质上是 `std::basic_string_view<T>` 的类型别名：  

    std::string_view      // std::basic_string_view<char>
    std::wstring_view     // std::basic_string_view<wchar_t>
    std::u16string_view   // std::basic_string_view<char16_t>
    std::u32string_view   // std::basic_string_view<char32_t>
    std::u8string_view    // std::basic_string_view<char8_t>，C++ 20

#### 常见构造方式
`std::string_view` 的构造方式很灵活，可以从字符串字面量、`std::string`、迭代器区间等来源创建，且都不复制底层数据：  

``` C++
std::string_view sv1;                         // 默认构造，空视图
std::string_view sv2 = "hello";               // 从字符串字面量构造（不复制）
std::string_view sv3("hello", 3);             // 指针 + 长度
std::string_view sv4 = sv2;                   // 拷贝构造，开销极小

std::string str = "hello";
std::string_view sv5 = str;                   // 从 std::string 构造（隐式转换）
std::string_view sv6(str.begin(), str.end()); // C++ 20 迭代器范围
std::string_view sv7 = sv2.substr(1, 3);      // 子视图，"ell"

std::string_view sv8 = "hello"sv;             // C++17 字面量，需 using namespace std::string_view_literals;
```

#### 成员函数
`string_view` 的大部分成员函数与 `std::string` 类似，用法完全一致，不再重复说明，下表只列出它特有或行为不同的成员函数：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`substr(pos, n)`</font> | <font size=2>返回子视图（不复制数据），与 `string` 的 `substr` 返回新字符串不同</font> |
| <font size=2>`remove_prefix(n)`</font> | <font size=2>把视图起点后移 `n` 个字符（视图独有）</font> |
| <font size=2>`remove_suffix(n)`</font> | <font size=2>把视图长度缩短 `n` 个字符（视图独有）</font> |

``` C++
std::string_view sv = "hello world";
std::string_view sub = sv.substr(6, 5); // substr：返回子视图（不复制数据）
std::cout << sub << std::endl;          // 输出 world
sv.remove_prefix(6);                    // remove_prefix：丢弃前 6 个字符
std::cout << sv << std::endl;           // 输出 world
sv.remove_suffix(1);                    // remove_suffix：丢弃末尾 1 个字符
std::cout << sv << std::endl;           // 输出 worl
```

#### 其它事项
①`string_view` 典型的用途之一是作为函数参数类型。若参数写成 `const std::string&`，那么当调用方传入字符串字面量或 `const char*` 时，会隐式构造出一个临时 `std::string`，产生一次内存分配与拷贝，而使用 `string_view` 则可以完全避免这次开销：  

``` C++
bool startsWithHello(std::string_view sv) { // 无论传入 string、const char* 还是字符串字面量，都不会发生拷贝
    return sv.starts_with("hello");
}

std::string s = "hello world";
std::cout << startsWithHello(s) << std::endl; // 传入 std::string
std::cout << startsWithHello("hello there") << std::endl; // 传入字面量
```

②生命周期问题：`string_view` 不延长所观察数据的生命期，若底层字符串先被销毁或数据被重新分配，视图就会变成**悬空视图 dangling view**，此时访问属于未定义行为：  

``` C++
std::string_view bad = std::string("temp"); // 错误！临时 string 当场销毁，bad 立即悬空

std::string s = "hello";
std::string_view sv = s.substr(0, 2); // 悬空：s.substr 返回临时 std::string

std::string_view sv = s;
s += " world!!!"; // 若触发扩容，字符数据搬家，sv 失效
```

因此<u>不要把 `string_view` 作为返回值返回临时数据，也不要长期保存指向局部字符串的视图</u>。作为函数参数使用时是安全的，因为此时被观察的数据在整个调用期间都活着。

## I/O 流
**流 stream** 是 C++ 对**输入输出 input/output (I/O)** 的抽象，表示数据按顺序、有方向地在程序与数据源/目的地之间传输。这个源/目的地可以是键盘、屏幕、文件、网络、内存等。对程序来说，它就是一串有序的字符序列，通过统一接口读写。C++ 标准库提供了一套以 `basic_*stream` 为模板的流类体系，如下表：  

| <font size=2>类别</font> | <font size=2>头文件</font> | <font size=2>说明</font> |
| :---- | :---- | :---- |
| <font size=2>标准流</font> | <font size=2>`<iostream>`</font> | <font size=2>与标准输入输出设备（键盘、屏幕）绑定的全局流对象，如 `std::cin` / `std::cout` / `std::cerr` / `std::clog`</font> |
| <font size=2>文件流</font> | <font size=2>`<fstream>`</font> | <font size=2>读写磁盘文件，如 `std::ifstream` / `std::ofstream` / `std::fstream`</font> |
| <font size=2>字符串流</font> | <font size=2>`<sstream>`</font> | <font size=2>在内存中的 `std::string` 上读写，如 `std::istringstream` / `std::ostringstream` / `std::stringstream`</font> |
| <font size=2>同步流</font> | <font size=2>`<syncstream>`（C++ 20）</font> | <font size=2>多线程环境下保证各线程输出不交错的流缓冲包装，如 `std::osyncstream`</font> |
| <font size=2>内存流</font> | <font size=2>`<spanstream>`（C++ 23）</font> | <font size=2>在已有的固定内存块 `std::span` 上读写，如 `std::ispanstream` / `std::ospanstream` / `std::spanstream`</font> |
| <font size=2>C 风格流</font> | <font size=2>`<cstdio>`</font> | <font size=2>C 标准库遗留的输入输出接口，以 `std::FILE*` 表示流</font> |

流的内容细究起来颇为庞杂，限于篇幅，下面只讨论最常用的标准流、文件流与字符串流，其余几种不再展开，对于一些内在机制也只点到为止。

### 标准流
标准库在头文件 `<iostream>` 中包含了 `<istream>` 和 `<ostream>`，分别定义了两个类模板：输入流 `std::basic_istream` 与输出流 `std::basic_ostream`，并为常用的字符类型提供了别名，如 `std::istream` / `std::ostream`（对应 `char`）以及 `std::wistream` / `std::wostream`（对应 `wchar_t`）。向流中写数据使用 `<<` **插入运算符 insertion operator**，从流中读数据使用 `>>` **提取运算符 extraction operator**，二者都返回流对象自身，因此可以连续串联，例如 `std::cout << a << b;`。同时，在 `<iostream>` 中预先定义好了若干个与标准输入输出设备绑定的全局流对象，如下表：  

| <font size=2>流对象</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::cin`</font> | <font size=2>标准输入，通常绑定键盘，类型为 `std::istream`</font> |
| <font size=2>`std::cout`</font> | <font size=2>标准输出，通常绑定屏幕，带缓冲，类型为 `std::ostream`</font> |
| <font size=2>`std::cerr`</font> | <font size=2>标准错误，不带缓冲，立即刷新，类型为 `std::ostream`</font> |
| <font size=2>`std::clog`</font> | <font size=2>标准错误日志，带缓冲，类型为 `std::ostream`</font> |

> 宽字符对应 `std::wcin`、`std::wcout`、`std::wcerr`、`std::wclog`。

这些标准流对象是 **RAII** 的典型例子：它们都是定义在 `<iostream>` 中的全局对象（在 `main` 开始之前就已完成构造），构造时取得设备与缓冲区等资源，析构时释放资源，即刷新缓冲区、把尚未真正写出的数据交给操作系统并回收缓冲区内存。它们的析构发生在程序正常结束、全局对象被销毁之时，因此只要程序正常退出，缓冲区中残留的数据都会被自动写出。反之，若程序通过 `std::abort()` 等非正常方式终止，这些全局对象不会析构，缓冲区也就不会被刷新。

``` C++
int age;
std::cout << "请输入年龄："; // 提示信息，不换行
std::cin >> age; // 从标准输入读取一个整数
std::cout << "你的年龄是 " << age << std::endl;

std::clog << "这是一条日志信息" << std::endl; // 带缓冲，缓冲区满或程序结束时才输出
std::cerr << "这是一条错误信息"; // 不带缓冲，立即输出
```

> `std::endl` 会写入换行符 `'\n'` 并**刷新缓冲区**，而直接写 `'\n'` 只换行、不刷新。频繁刷新会拖慢输出，因此大量输出时更推荐用 `'\n'`，只在确需立即看到结果时才用 `std::endl`。

#### 缓冲区
流内部维护着一块称为**缓冲区 buffer** 的内存区域：输出时，写入流的数据并不会立刻送达设备，而是先暂存进缓冲区，等缓冲区被填满、被显式刷新或程序正常结束时，才一次性交给操作系统真正写入设备。输入时则相反，一次从设备读入一大块数据塞进缓冲区，之后的读取操作直接从缓冲区中取用，取空后再去读下一块。之所以这样做，是因为设备访问（磁盘、终端、网络等）远比内存操作慢，把大量零散的小块读写合并成整块的读写，可以减少系统调用次数，从而提升效率。

缓冲区本身并不由流对象直接管理，而是交给独立的**流缓冲区 streambuf**（`std::basic_streambuf`）负责，流对象内部只保存一个指向它的指针，文件流底层用的是 `std::basic_filebuf`，字符串流底层用的是 `std::basic_stringbuf`。流对象通过成员函数 `rdbuf()` 可以取得当前流关联的 `streambuf`。

与刷新有关的操纵符和成员函数如下表：  

| <font size=2>操纵符 / 成员</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::flush`</font> | <font size=2>立即刷新缓冲区</font> |
| <font size=2>`std::endl`</font> | <font size=2>写入换行符 `'\n'` 后刷新，等价于 `'\n' << std::flush`</font> |
| <font size=2>`std::ends`</font> | <font size=2>写入一个空字符 `'\0'`，不换行也不刷新</font> |
| <font size=2>`std::unitbuf` / `nounitbuf`</font> | <font size=2>开启 / 关闭每次输出后都刷新的模式</font> |
| <font size=2>`tie(stream)`</font> | <font size=2>把输出流与某个输入流绑定，使该输入流每次读取前自动刷新这个输出流</font> |

其中 **tie** 是交互式程序最常用的机制：`std::cin` 默认就与 `std::cout` 绑定了（`std::cin.tie()` 返回 `&std::cout`），因此每次从 `std::cin` 读取之前，`std::cout` 的缓冲区都会被自动刷新，如下：  

``` C++
std::cout << "请输入一个数字："; // 留在缓冲区里
int n;
std::cin >> n; // 读取前 cin 会自动刷新 cout，提示信息这才显示出来

std::cout << "处理中" << std::flush; // 手动刷新，立即输出而不必等到缓冲区满
std::cout << "完成" << std::endl; // 写入换行符并刷新

std::cout << std::unitbuf; // 开启：此后每次输出后都自动刷新
std::cout << "第一条日志"; // 没有换行，也没有 flush，仍然立即显示
std::cout << "第二条日志"; // 同样立即显示

std::cout << std::nounitbuf; // 关闭，恢复默认的缓冲行为
std::cout << "第三条日志"; // 留在缓冲区里，遇到程序结束才写出
```

#### 标准操纵符
流会按照数据的类型自动选择默认格式，若需要控制进制、精度、字段宽度与对齐等，可以使用**格式化状态 formatting state** 或**操纵符 manipulator**，格式化状态这里就不介绍了，下面简单说明一下几个常用的操纵符。标准操纵符主要定义在 `<ios>`、`<istream>`、`<ostream>` 和 `<iomanip>` 中。 

| <font size=2>操纵符</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::dec` / `hex` / `oct`</font> | <font size=2>整数按十进制 / 十六进制 / 八进制输出（默认为十进制）</font> |
| <font size=2>`std::showbase` / `noshowbase`</font> | <font size=2>显示 / 隐藏进制前缀，如十六进制的 `0x`、八进制的 `0`（默认为不显示）</font> |
| <font size=2>`std::fixed` / `scientific`</font> | <font size=2>浮点数按定点 / 科学计数法输出，此后 `setprecision` 表示小数位数</font> |
| <font size=2>`std::setprecision(n)`</font> | <font size=2>设置浮点数的有效位数（默认格式下），与 `fixed` / `scientific` 搭配时表示小数位数</font> |
| <font size=2>`std::boolalpha` / `noboolalpha`</font> | <font size=2>`bool` 输出为 `true` / `false`，而非 1 / 0（默认为 1 / 0）</font> |
| <font size=2>`std::setw(n)`</font> | <font size=2>设置下一个输出项的最小字段宽度为 `n`，内容超出时不会被截断</font> |
| <font size=2>`std::setfill(c)`</font> | <font size=2>设置填充字符，默认为空格</font> |

``` C++
std::cout << std::hex << 255 << std::endl << std::dec;                    // 输出 ff
std::cout << std::setw(8) << std::setfill('0') << 42 << std::endl;        // 输出 00000042
std::cout << std::fixed << std::setprecision(2) << 3.14159 << std::endl;  // 输出 3.14
std::cout << std::boolalpha << (1 < 2) << std::endl;                      // 输出 true
```

> 大多数操纵符会持续生效，如 `std::hex`、`std::fixed`，要恢复默认可以使用对应的重置操纵符，如 `std::dec`、`std::defaultfloat`。

#### 流状态
每个流对象内部都维护着一组状态标志，用于记录最近一次操作的结果，其类型为 `std::ios_base::iostate`，它是一个**位掩码 bitmask**，由下面四个状态位构成：  

| <font size=2>状态标志</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::ios_base::goodbit`</font> | <font size=2>不置位任何标志（值通常为 0），表示当前状态一切正常</font> |
| <font size=2>`std::ios_base::eofbit`</font> | <font size=2>已到达输入序列末尾 eof（end of file）</font> |
| <font size=2>`std::ios_base::failbit`</font> | <font size=2>发生了逻辑错误，如格式化的读取无法把字符解析成目标类型</font> |
| <font size=2>`std::ios_base::badbit`</font> | <font size=2>发生了严重的底层错误，如缓冲区读写失败或数据损坏</font> |

当读写失败或到达末尾时，流会进入相应的状态，此时继续使用该流将不再生效，必须先清除状态。流对象跟流状态相关的常用成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`good()`</font> | <font size=2>一切正常，没有任何错误标志，等价于 `rdstate() == goodbit`</font> |
| <font size=2>`eof()`</font> | <font size=2>已到达文件末尾 eof（end of file），等价于 `rdstate()` 中 `eofbit` 置位</font> |
| <font size=2>`fail()`</font> | <font size=2>发生了逻辑错误（如类型不匹配），或已到达文件末尾，等价于 `rdstate()` 中 `failbit` 或 `badbit` 置位</font> |
| <font size=2>`bad()`</font> | <font size=2>发生了严重的读写错误（如设备故障、数据损坏），等价于 `rdstate()` 中 `badbit` 置位</font> |
| <font size=2>`rdstate()`</font> | <font size=2>返回当前的状态位掩码，类型为 `std::ios_base::iostate`</font> |
| <font size=2>`setstate(state)`</font> | <font size=2>把参数中的位叠加到当前状态上（相当于按位或），常用于模拟某种错误</font> |
| <font size=2>`clear(state)`</font> | <font size=2>清除所有状态标志，使流恢复可用；若传入 `iostate` 参数，则改为该参数指定的状态（默认参数为 `goodbit`）</font> |
| <font size=2>`ignore(n, delim)`</font> | <font size=2>丢弃至多 `n` 个字符，直到遇到分隔符 `delim` 为止</font> |

由于状态本身就是个位掩码，借助 `rdstate()` 可以精确判断究竟置位了哪些标志，也可以只清除其中某一位：  

``` C++
int x;
std::cin >> x; // 假设输入 "abc"，解析失败
std::ios_base::iostate st = std::cin.rdstate(); // 取出状态位掩码
std::cout << std::boolalpha
          << bool(st & std::ios_base::eofbit) << ' '  // 输出 false，未到末尾
          << bool(st & std::ios_base::failbit) << ' ' // 输出 true，发生了逻辑错误
          << bool(st & std::ios_base::badbit) << std::endl; // 输出 false，没有严重错误

std::cout << std::cin.eof() << std::endl; // 输出 false
std::cout << std::cin.fail() << std::endl; // 输出 true
std::cout << std::cin.bad() << std::endl; // 输出 false
```

另外，流对象可以隐式转换为 `bool`，相当于判断 `!fail()`，因此最常见的写法是把读取操作直接放进条件中。

``` C++
int n;
while (std::cin >> n) { // 读取成功则继续，失败或到达末尾时自动退出
    std::cout << n << ' ';
}
```

### 文件流
文件的输入输出由 `<fstream>` 中的三个类提供，只是需要先用文件名打开文件，用完后可以显式关闭（对象析构时也会自动关闭）：  

| <font size=2>类</font> | <font size=2>默认打开模式</font> | <font size=2>说明</font> |
| :---- | :---- | :---- |
| <font size=2>`std::ifstream`</font> | <font size=2>`std::ios::in`</font> | <font size=2>输入文件流，用于读取文件</font> |
| <font size=2>`std::ofstream`</font> | <font size=2>`std::ios::out`</font> | <font size=2>输出文件流，用于写入文件</font> |
| <font size=2>`std::fstream`</font> | <font size=2>`std::ios::in` &#124; `std::ios::out`</font> | <font size=2>输入输出文件流，既可读也可写</font> |

> `std::ofstream` 的默认模式 `out` 对文件隐含 `trunc`，因此会清空或新建文件；而 `std::fstream` 默认为 `in | out`，`in` 又要求文件必须已存在，所以它既不会新建文件也不会清空已有内容，若想把它当纯读或纯写使用，需要显式指定 `std::ios::in` 或 `std::ios::out`。

打开文件时可以通过第二个参数指定**打开模式 open mode**，多个模式用按位或 `|` 组合，常用的如下表：  

| <font size=2>打开模式</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::ios::in`</font> | <font size=2>以读方式打开</font> |
| <font size=2>`std::ios::out`</font> | <font size=2>以写方式打开（默认会截断已有内容）</font> |
| <font size=2>`std::ios::app`</font> | <font size=2>追加：所有写入都发生在文件末尾</font> |
| <font size=2>`std::ios::trunc`</font> | <font size=2>若文件已存在则清空其内容</font> |
| <font size=2>`std::ios::ate`</font> | <font size=2>打开后立即定位到文件末尾（at end）</font> |
| <font size=2>`std::ios::binary`</font> | <font size=2>以二进制方式打开，不做文本转换</font> |

``` C++
std::ofstream out("test.txt");   // 写文件：默认 out | trunc，会清空原内容
if (!out) std::cerr << "打开文件失败" << std::endl;
out << "第一行" << std::endl;
out << "第二行" << std::endl;
out.close();                     // 用完及时关闭

std::ifstream in("test.txt");    // 读文件
std::string line;
while (std::getline(in, line)) { // 逐行读取，直到文件末尾
    std::cout << line << std::endl;
}
in.close();
```

> 打开文件后应当用 `is_open()` 或直接判断流对象检查是否成功。`std::ofstream` 默认以 `out | trunc` 打开，若想在文件末尾追加内容，需要显式指定 `std::ios::app`。另外，关闭后流的状态标志不会自动清除，若要复用同一个流对象继续打开其它文件，应先调用 `clear()`。

### 字符串流
字符串流是标准库 `<sstream>` 提供的一组类，即 `std::istringstream`、`std::ostringstream` 与 `std::stringstream`，它们把流的概念用在了字符串上：它们不读写外部设备，而是在内存中的字符串上进行输入输出，常用于拼接复杂文本或解析按字段分隔的数据。  

| <font size=2>类</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::istringstream`</font> | <font size=2>从一个字符串中读取数据</font> |
| <font size=2>`std::ostringstream`</font> | <font size=2>把数据写入其中，最终得到一个字符串</font> |
| <font size=2>`std::stringstream`</font> | <font size=2>既可读也可写</font> |

``` C++
std::ostringstream oss; // 拼接字符串
oss << "坐标：(" << 1 << ", " << 2 << ")，名称：" << "玩家";
std::string text = oss.str(); // str() 取出内部的字符串
std::cout << text << std::endl; // 输出 坐标：(1, 2)，名称：玩家

std::istringstream iss("42 3.14 hello"); // 按空白切分字段
int i; double d; std::string s;
iss >> i >> d >> s;
std::cout << i << ' ' << d << ' ' << s << std::endl; // 输出 42 3.14 hello
```

> `>>` 默认以空白为分隔，若要解析形如 `a,b,c` 的数据，可以改用 `std::getline(iss, field, ',')` 按逗号逐个取出。


# 第十九章 视图与范围
本章主要补充 C++ 20 引入的两组常用标准库设施：**视图 span** 与**范围 range**。**`std::span`** 表示对一段连续内存或序列的视图，之前介绍的 `std::string_view` 就属于这一范畴。**`std::ranges`** 则使用范围替代传统迭代器来表达一段可以迭代的序列。这两组设施在现代 C++ 项目中比较常用，值得掌握。

## span
`std::span` 定义在头文件 `<span>` 中，它本质上只保存一个指向数据的指针与一个长度，用来引用一段已存在的连续内存。它有两个模板参数，元素类型与长度，长度默认为 `std::dynamic_extent` 表示运行时确定，也可指定编译期固定长度，如下表：  

| <font size=2>写法</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::span<T>`</font> | <font size=2>动态长度，等价于 `std::span<T, std::dynamic_extent>`</font> |
| <font size=2>`std::span<T, N>`</font> | <font size=2>静态长度，元素个数 `N` 在编译期就已知</font> |
| <font size=2>`std::span<const T>`</font> | <font size=2>只读视图，不能通过它修改元素</font> |

> 可以把 span 看作 `std::string_view` 的一般化，`std::string_view` 相当于只读的 `span<const char>`，只不过还额外提供了字符串专有的成员函数。

### 构造与初始化
`std::span` 可以从 C 数组、`std::array`、`std::vector`、`std::string` 等任何连续序列直接构造，也可以显式给出指针、迭代器与长度：  

``` C++
int carr[5] = {1, 2, 3, 4, 5};
std::array<int, 3> arr = {6, 7, 8};
std::vector<int> vec = {9, 10, 11, 12};

std::span<int> s0;          // 默认构造，空视图，size() 为 0
std::span<int> s1(carr);    // 从 C 数组构造，长度 5
std::span<int> s2(arr);     // 从 std::array 构造，长度 3
std::span<int> s3(vec);     // 从 std::vector 构造，长度 4
std::span<int> s4(carr, 3); // 指针 + 长度，只看前 3 个元素
std::span<int, 3> s5(arr);  // 静态长度，实参长度必须正好是 3
std::span<int> s6(vec.begin(), vec.end()); // 迭代器区间构造，长度 4
std::span<int> s7(vec.begin(), 2);         // 迭代器 + 长度，只看前 2 个元素
```

### 常用成员
`std::span` 常用的成员如下：  

| <font size=2>成员函数/数据成员</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`extent`</font> | <font size=2>静态成员常量，静态长度为其具体值，动态长度为 `std::dynamic_extent`</font> |
| <font size=2>`front()` / `back()`</font> | <font size=2>返回首元素 / 尾元素的引用，在空 span 上调用属于未定义行为</font> |
| <font size=2>`operator[]`</font> | <font size=2>按下标访问元素，不做越界检查，越界属于未定义行为</font> |
| <font size=2>`data()`</font> | <font size=2>返回指向首元素的指针</font> |
| <font size=2>`size()` / `size_bytes()`</font> | <font size=2>返回元素个数 / 占用的字节数</font> |
| <font size=2>`empty()`</font> | <font size=2>判断视图是否为空</font> |
| <font size=2>`begin()` / `end()`</font> | <font size=2>返回指向首元素 / 尾后位置的迭代器，因此可以范围 for 遍历</font> |
| <font size=2>`rbegin()` / `rend()`</font> | <font size=2>返回反向迭代器，用于逆序遍历</font> |
| <font size=2>`first(n)` / `last(n)`</font> | <font size=2>由前 `n` 个 / 后 `n` 个元素构成的子视图</font> |
| <font size=2>`subspan(offset, count)`</font> | <font size=2>由从 `offset` 开始的 `count` 个元素构成的子视图</font> |

子视图只是调整指针与长度，不复制任何数据，因此代价极低：  

``` C++
std::vector<int> vec = {1, 2, 3, 4, 5, 6};
std::span<int> s(vec);

auto a = s.first(2);      // {1, 2}
auto b = s.last(2);       // {5, 6}
auto c = s.subspan(2, 3); // {3, 4, 5}
```

### 其它事项
①`std::span` 典型的用途之一就是作为函数参数类型，可以统一地接受各种连续序列，诸如 C 数组、`std::array`、`std::vector` 等：  

``` C++
void print(const int* data, std::size_t size); // 只接受 C 数组
void print(const std::vector<int>& v); // 只接受 std::vector

void print(std::span<const int> data) { // 只读视图，可接受任何连续序列
    for (int v : data) std::cout << v << ' ';
    std::cout << std::endl;
}

int arr[3] = {1, 2, 3};
std::vector<int> vec = {4, 5};

print(arr); // 传入 C 数组，长度不会丢失
print(vec); // 传入 vector
```

②生命周期：与 `string_view` 一样，`span` 不拥有数据，也不延长所引用数据的生命期。若底层容器被销毁，或数据因扩容等原因被重新分配，span 就会变成**悬空视图 dangling view**，此时访问属于未定义行为，因此不要用临时对象去构造 span。   

## range
C++ 20 之前，标准库算法只能用一对迭代器来表达一段序列，写法较为啰嗦。C++ 20 引入了**范围 range**，对算法和迭代器库进行了扩展与泛化，提供了更加简洁安全的接口，主要头文件是 `<ranges>`，命名空间为 `std::ranges`。这次扩展建立在 C++ 20 新增的模板**概念 concept** 之上，即用编译期谓词对模板参数提出明确要求。此前的算法都是**无约束算法 unconstrained algorithm**，模板参数只有名字、要求仅写在文档里，一旦传错类型，错误会在算法内部深处爆发，报错冗长难读。C++ 20 据此在 `std::ranges` 中提供了**使用概念约束的算法 constrained algorithm**（如 `std::ranges::sort`），把要求写进签名，不满足时直接在调用处报错，接口也顺带由迭代器对改成了范围。两版算法并存，无约束版本仍保留在 `<algorithm>` 中。

ranges 大致包含以下三部分内容：  
* **范围概念 range concept**：`<ranges>` 头文件中定义了很多范围的概念，用于描述范围的属性（诸如长度、迭代器类型等），算法与视图正是借助这些概念来约束各自所能接受的范围；  
* **视图 view**：视图是查看范围的一种方式，它提供了一种惰性求值、可组合、轻量级的方式来处理序列数据，支持管道操作符 `|` 串联组合；  
* **使用概念约束的算法 constrained algorithm**：前缀为 `std::ranges::` 的算法，仍然位于 `<algorithm>` 头文件中（数值版本位于 `<numeric>`），接口由迭代器对改为范围，并额外支持投影。

### 范围概念
`std::ranges::range` 可以说是范围概念中的基础，它定义了一个类型必须满足的要求：能够通过提供起始迭代器和结束**哨兵 sentinel** 来遍历其元素，即满足 range 概念。哨兵可以是迭代器，也可以不是迭代器，但它需要能与前面的迭代器比较，用于判断遍历是否结束。除了最基础的 range，标准还按能力细分了一批概念，常用的如下表：  

| <font size=2>概念</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::ranges::range`</font> | <font size=2>范围由起始迭代器和结束哨兵组成</font> |
| <font size=2>`std::ranges::sized_range`</font> | <font size=2>范围能在常数时间内获得其长度</font> |
| <font size=2>`std::ranges::common_range`</font> | <font size=2>范围起始迭代器与哨兵类型相同</font> |
| <font size=2>`std::ranges::view`</font> | <font size=2>范围能在常数时间内拷贝、移动、赋值</font> |
| <font size=2>`std::ranges::borrowed_range`</font> | <font size=2>迭代器的生命周期不依赖于范围本身，可以安全返回迭代器而不会悬垂</font> |
| <font size=2>`std::ranges::viewable_range`</font> | <font size=2>可以安全地转换为视图的范围</font> |
| <font size=2>`std::ranges::input_range`</font> | <font size=2>迭代器满足 `input_iterator`，只保证单遍只读遍历</font> |
| <font size=2>`std::ranges::output_range`</font> | <font size=2>迭代器满足 `output_iterator`，只能写入元素</font> |
| <font size=2>`std::ranges::forward_range`</font> | <font size=2>迭代器满足 `forward_iterator`，可以多遍遍历</font> |
| <font size=2>`std::ranges::bidirectional_range`</font> | <font size=2>迭代器满足 `bidirectional_iterator`，可以双向遍历</font> |
| <font size=2>`std::ranges::random_access_range`</font> | <font size=2>迭代器满足 `random_access_iterator`，支持常数时间任意跳转</font> |
| <font size=2>`std::ranges::contiguous_range`</font> | <font size=2>迭代器满足 `contiguous_iterator`，元素在内存中连续存放</font> |

### 定制点对象
上述的概念描述的是范围具备的能力，而我们经常需要对范围调用一些基本操作，例如获取起始迭代器、结束哨兵、长度等等。但是，不同类型提供这些信息的途径并不一致，比如容器通过成员函数，但是 C 数组并没有这些成员函数。为此，标准提供了若干个**定制点对象 customization point object (CPO)** 作为访问范围的统一入口，常用的如下表：  

| <font size=2>定制点对象</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::ranges::begin(r)` / `end(r)`</font> | <font size=2>取得起始迭代器 / 结束哨兵</font> |
| <font size=2>`std::ranges::size(r)`</font> | <font size=2>取得元素个数，仅 `sized_range` 可用</font> |
| <font size=2>`std::ranges::empty(r)`</font> | <font size=2>判断范围是否为空，优先用 `size()`，否则比较 `begin` 与 `end`</font> |
| <font size=2>`std::ranges::data(r)`</font> | <font size=2>取得指向首个元素的指针，仅 `contiguous_range` 可用</font> |
| <font size=2>`std::ranges::rbegin(r)` / `rend(r)`</font> | <font size=2>取得反向迭代器，仅 `bidirectional_range` 可用</font> |
| <font size=2>`std::ranges::cbegin(r)` / `cend(r)`</font> | <font size=2>取得只读迭代器</font> |

``` C++
int carr[3] = {1, 2, 3};
// 支持 C 数组
std::cout << std::ranges::size(carr) << std::endl;   // 输出 3
std::cout << std::ranges::empty(carr) << std::endl;  // 输出 0
std::cout << *std::ranges::begin(carr) << std::endl; // 输出 1
std::cout << *std::ranges::data(carr) << std::endl;  // 输出 1
```

### 视图
**视图 view** 是建立在范围之上的一类轻量对象，它不拥有元素，只是引用或间接表示另一个范围中的元素。视图有两个关键性质：①拷贝、移动、赋值都必须是常数时间（这正是 `std::ranges::view` 概念的约束），通常使用值传递，而不会复制底层数据；②求值是**惰性 lazy** 的，只有在遍历到某个元素时才会真正计算它，不会预先造出一个中间容器。另外，<u>视图本身也是范围</u>，满足 `std::ranges::range`、`std::movable`、`std::ranges::enable_view` 这三个概念。

#### 范围适配器
视图通常通过**范围适配器 range adaptor** 来创建，按调用签名可以分成两种形式：  
1. 接收一个范围和额外参数（若有），并返回视图，例如 `std::views::filter(r, pred)` 返回 `std::ranges::filter_view` 视图类型；  
2. 只接受额外参数（若有），例如 `std::views::filter(pred)`，得到**范围适配器闭包对象 range adaptor closure object**，若将闭包对象作用到某个范围上即可得到视图，后面要提到的管道操作符 `|` 的右侧操作数必须是一个范围适配器闭包对象。

常用的范围适配器如下表：  

| <font size=2>适配器</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::views::filter(pred)`</font> | <font size=2>只保留使谓词 `pred` 为真的元素</font> |
| <font size=2>`std::views::transform(f)`</font> | <font size=2>对每个元素应用变换函数 `f`，把返回值作为视图的元素</font> |
| <font size=2>`std::views::take(n)` / `drop(n)`</font> | <font size=2>取前 `n` 个元素 / 丢弃前 `n` 个元素</font> |
| <font size=2>`std::views::take_while(pred)` / `drop_while(pred)`</font> | <font size=2>取开头连续满足谓词的一段 / 丢弃这一段</font> |
| <font size=2>`std::views::reverse`</font> | <font size=2>反转元素顺序，要求双向范围</font> |
| <font size=2>`std::views::split(delim)` / `lazy_split(delim)`</font> | <font size=2>按分隔符切分成子范围，`split` 要求前向范围</font> |
| <font size=2>`std::views::keys` / `values` / `elements<N>`</font> | <font size=2>从 `pair`、`tuple` 之类的范围中取出第 `N` 个成员，`keys` 即 `elements<0>`</font> |
| <font size=2>`std::views::common`</font> | <font size=2>把哨兵类型不同的范围转成 `common_range`，便于套用经典算法</font> |
| <font size=2>`std::views::counted(it, n)`</font> | <font size=2>从迭代器 `it` 起取 `n` 个元素</font> |

创建视图时，既可以把范围作为第一个参数，也可以生成闭包后再作用到范围上，这两种写法完全等价：  

``` C++
std::vector<int> v = {1, 2, 3, 4, 5, 6};

// 写法一：适配器对象直接接收范围与参数
auto evens = std::views::filter(v, [](int x) { return x % 2 == 0; }); // 视图内容为 2 4 6
auto squares = std::views::transform(evens, [](int x) { return x * x; }); // 视图内容为 4 16 36

// 写法二：先得到闭包，再作用到范围上
auto squareOfEven = std::views::transform([](int x) { return x * x; });
auto squares2 = squareOfEven(evens); // 与上面的 squares 等价

for (int x : squares2) std::cout << x << ' '; // 输出 4 16 36
```

#### 范围工厂
**范围工厂 range factory**（也称**视图工厂 view factory**）无需已有范围作为输入，它凭空生成一个新的视图，工厂则通常作为管道操作符 `|` 左侧的起点。常用的工厂如下表：  

| <font size=2>工厂</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::views::empty<T>`</font> | <font size=2>不含任何元素的空视图</font> |
| <font size=2>`std::views::single(x)`</font> | <font size=2>只含一个元素 `x` 的视图</font> |
| <font size=2>`std::views::iota(a, b)`</font> | <font size=2>从 `a` 开始、步长为 1 的整数序列，不含上界 `b`</font> |
| <font size=2>`std::views::iota(a)`</font> | <font size=2>从 `a` 开始的无限整数序列，必须配合 `take` 等适配器使用</font> |
| <font size=2>`std::views::istream<T>(is)`</font> | <font size=2>把输入流 `is` 按 `T` 逐个读取，形成一系列元素</font> |

``` C++
for (int i : std::views::iota(1, 5)) std::cout << i << ' '; // 输出 1 2 3 4
for (int i : std::views::iota(0) | std::views::take(3)) std::cout << i << ' '; // 输出 0 1 2
for (char c : std::views::single('x')) std::cout << c << ' '; // 输出 x
std::cout << std::views::empty<int>.size() << std::endl; // 输出 0

std::istringstream iss("10 20 30"); // istream 工厂：把输入流当成范围来读
for (int n : std::views::istream<int>(iss)) std::cout << n << ' '; // 输出 10 20 30
```

> `std::views::iota` 的有限版本是 `sized_range` 与 `random_access_range`，可以在其上直接使用 `size()`、下标等操作。无限视图本身无法单独遍历，只有配合 `take` 之类的适配器才能安全使用。

#### 视图管道
把多个适配器套在一起最自然的写法是使用**管道运算符** `|`。对任意范围 `r` 与范围适配器闭包对象 `c`，`r | c` 完全等价于 `c(r)`，即把左侧的范围作为第一个参数传给右侧的适配器：  

``` C++
std::vector<int> v = {1, 2, 3, 4, 5, 6, 7, 8};

auto r = v // 也可以使用视图工厂 std::views::iota(1, 8)
       | std::views::filter([](int x) { return x % 2 == 0; })  // 2 4 6 8
       | std::views::transform([](int x) { return x * x; })    // 4 16 36 64
       | std::views::take(2);                                  // 4 16
for (int x : r) std::cout << x << ' '; // 输出 4 16

// 等价的嵌套写法：从最内层往外读，不直观
auto nested = std::views::take(
    std::views::transform(
        std::views::filter(v, [](int x) { return x % 2 == 0; }),
        [](int x) { return x * x; }),
    2);
for (int y : nested) std::cout << y << ' '; // 输出 4 16
```

闭包之间也可以用 `|` 组合成一个新的闭包，从而把常用的适配器链预先拼好、反复套用到不同范围上：  

``` C++
// 闭包 | 闭包：组合成一个新的闭包，此时还没有绑定任何范围
auto evenSquares = std::views::filter([](int x) { return x % 2 == 0; })
                 | std::views::transform([](int x) { return x * x; });

std::vector<int> a = {1, 2, 3, 4};
std::vector<int> b = {5, 6, 7, 8};
for (int x : a | evenSquares) std::cout << x << ' '; // 输出 4 16
for (int x : b | evenSquares) std::cout << x << ' '; // 输出 36 64
```

#### 惰性求值
视图的第二个关键性质是**惰性求值 lazy evaluation**：构造视图本身不会遍历元素，也不会做任何计算，只有真正遍历视图时，才会逐元素地把这些操作应用上去，遍历到哪个元素才算哪个元素，例如：  

``` C++
std::vector<int> v = {1, 2, 3, 4, 5};

auto r = v | std::views::filter([](int x){
    std::cout << "filtering " << x << "\n";
    return x % 2 == 0;
});

std::cout << "before loop\n";
for (int x : r) std::cout << "got " << x << "\n";
```

输出：  

``` text
before loop
filtering 1
filtering 2
got 2
filtering 3
filtering 4
got 4
filtering 5
```

惰性求值可以带来两个好处：①可以表达**无限序列**，元素是随取随算的，之后由 `take` 之类的适配器提前结束即可；②允许**短路**，若只需要前几个元素，那么昂贵变换也只会对这几个元素执行。但视图不会缓存已经算出的结果，每遍历一次都会从头重新计算一遍中间结果，若遍历次数多、变换代价高，重复计算带来的开销反而可能超过省下中间容器所省下的开销，甚至比直接先把结果放进容器更慢。C++ 23 起，`std::ranges::to` 可以把视图**物化 materialize** 成具体的容器，即一次性遍历视图、把结果依次存入容器，从而把惰性求值固化为实实在在的数据，避免后续的重复计算，例如 `auto v = view | std::ranges::to<std::vector>();`。

### 范围算法
`<algorithm>` 中几乎所有经典算法在 `std::ranges` 命名空间下都有同名版本。它们与经典版本相比主要有三处不同：  
1. 参数由一对迭代器改为一个**范围**，可读性更好；  
2. 许多 `std::ranges` 算法返回的是一个包含迭代器、哨兵或计数的结构体，而不仅仅是单个迭代器，提供了更多有用的信息；  
3. 新增可选的**投影 projection** 参数，允许你在算法执行过程中，指定特定成员应用可调用对象进行比较或操作。

`std::ranges` 中个别算法如下表：  

| <font size=2>算法</font> | <font size=2>要求的范围概念</font> | <font size=2>说明</font> |
| :---- | :---- | :---- |
| <font size=2>`std::ranges::sort(r, comp, proj)`</font> | <font size=2>`random_access_range`</font> | <font size=2>将范围中元素排序</font> |
| <font size=2>`std::ranges::find_if(r, pred, proj)`</font> | <font size=2>`input_range`</font> | <font size=2>查找第一个满足条件的元素，返回其迭代器</font> |
| <font size=2>`std::ranges::count_if(r, pred, proj)`</font> | <font size=2>`input_range`</font> | <font size=2>统计满足条件的元素个数</font> |
| <font size=2>`std::ranges::for_each(r, f, proj)`</font> | <font size=2>`input_range`</font> | <font size=2>对每个元素调用 `f`，返回 `iter_fun_result`</font> |
| <font size=2>`std::ranges::transform(r, out, f, proj)`</font> | <font size=2>`input_range`</font> | <font size=2>对每个元素应用 `f`，把结果写入目标范围</font> |
| <font size=2>`std::ranges::copy_if(r, out, pred, proj)`</font> | <font size=2>`input_range`</font> | <font size=2>把范围内元素复制到目标范围，返回 `in_out_result`</font> |
| <font size=2>`std::ranges::fill(r, value)`</font> | <font size=2>`output_range`</font> | <font size=2>把范围内所有元素赋值为 `value`</font> |
| <font size=2>`std::ranges::remove_if(r, pred, proj)`</font> | <font size=2>`forward_range`</font> | <font size=2>逻辑删除，返回 `subrange`</font> |

投影是范围算法中非常好用的新特性，极大地简化了针对特定成员排序或查找的场景，例如：  

``` C++
struct Person {
    std::string name;
    int age;
};

std::vector<Person> people = {{"Tom", 25}, {"Jerry", 19}, {"Spike", 30}};

// 经典写法：对比 age
std::sort(people.begin(), people.end(), [](const Person& a, const Person& b) { return a.age < b.age; });

// 范围写法：投影直接指出要比较的成员，比较器用默认的 std::less{} 即可
std::ranges::sort(people, {}, &Person::age);               // 按 age 升序
std::ranges::sort(people, std::greater{}, &Person::name);  // 按 name 降序

auto it = std::ranges::find(people, 30, &Person::age); // 按 age 查找
if (it != people.end()) std::cout << it->name << std::endl; // 输出 Spike
```

结果是结构体的算法可以直接用 C++ 17 引入的**结构化绑定 structured binding**（STL 章节有提到过）解包多个变量：  

``` C++
std::vector<int> src = {1, 2, 3, 4};
std::vector<int> dst(src.size());

auto [in, out] = std::ranges::copy(src, dst.begin()); // 结构化绑定取出 in_out_result
std::cout << (out - dst.begin()) << std::endl;        // 输出 4，复制的元素个数
```


# 第二十章 并发与线程
前面各章的程序基本都是单线程的：整段程序只有一条执行流，语句按书写的顺序一条接一条地执行。然而如今的计算机几乎都是多核的，如果程序始终只用一条执行流，就等于让大部分核心闲置。为此，C++ 11 在标准库中引入了一整套**并发 concurrency** 与**多线程 multithreading** 设施，让程序可以同时推进多个任务，从而充分利用多核处理器、提升吞吐量，并让交互式程序在执行耗时操作时仍保持响应。但并发并非免费的午餐，多条执行流若同时访问同一份数据，就可能引发难以复现的错误。由于是基础笔记，本章以梳理概念与常用设施的整体脉络为主，介绍每项设施时也会说明它究竟要解决什么问题，至于底层实现与高级用法则不深入展开。

标准库的并发设施分散在若干头文件中：线程 `<thread>`、互斥量 `<mutex>`、条件变量 `<condition_variable>`、原子类型 `<atomic>`、异步任务 `<future>`，C++ 20 又补充了闩锁 `<latch>`、屏障 `<barrier>`、信号量 `<semaphore>`。

## 并发的基本概念
***①进程与线程***  
**进程 process** 是操作系统进行资源分配的基本单位，每个进程拥有自己独立的地址空间、文件描述符表等资源，进程之间彼此隔离，一个进程崩溃通常不会影响另一个。**线程 thread** 则是 CPU 调度的基本单位，一个进程内可以包含多个线程，它们<u>共享该进程的地址空间与大部分资源</u>，但各自拥有独立的栈、程序计数器与寄存器等执行上下文。

***②并发与并行***  
这两个词经常混用，但含义不同：**并发 concurrency** 强调的是多个任务在**同一时间段**内交替推进，宏观上像同时进行，微观上可能只是快速切换。而**并行 parallelism** 强调的是多个任务在**同一时刻**真正同时执行，必须依赖多核等硬件条件。可以说并行是并发的一个子集，单核 CPU 上也能实现并发（通过分时切换），但无法实现真正的并行。反过来，多核加上多线程只是具备了并行的条件，至于任务是否真的并行，还要看具体的调度与实现。程序可用的并行线程数取决于硬件的并发支持能力，可以通过 `std::thread::hardware_concurrency()` 查询（返回的是提示值，可能为 0 或不够精确），它通常等于逻辑核心数，可作为创建线程数量的参考上界。

***③上下文切换***  
单个 CPU 核心同一时刻只能执行一条指令流，因此要在单核上并发运行多个线程，就必须在它们之间快速切换，保存当前线程的执行上下文并恢复另一个线程的上下文，这一过程称为**上下文切换 context switch**。切换本身有开销，且会打断 CPU 流水线与缓存局部性，所以线程并非越多越好。

***④内存模型***  
**内存模型 memory model** 是硬件或编程语言对内存操作的抽象规范，尤其规定多线程环境下内存读写操作的**可见性 visibility**、**原子性 atomicity** 和**有序性 ordering**。这三条性质都源自现代计算机读写内存的实际过程：数据平时存放在**内存 memory** 中，CPU 需先把它加载到**缓存 cache**，再读入**寄存器 register**，在寄存器中完成运算后写回缓存，最后才由缓存写回内存。其中缓存并非所有 CPU 核心共有，L1、L2 通常每个核心私有，L3 一般多个核心共享，因此同一变量在多个核心中可能各存一份副本。由此带来三个问题：①**可见性**，指一个线程对共享变量的修改，另一个线程能否、何时能看到，由于修改是在某个核心的寄存器中完成后才逐级写回，写回内存的时刻可能被推迟，其它核心的缓存副本也不会自动同步、可能仍是旧值，因此新值未必立刻可见；②**原子性**，指一个操作能否不被打断地完整执行，其它线程观察到的只有"没做"与"做完"两种状态，像 `++counter` 实际上由读取、加一、写回三步组成，其它线程完全可能插入其中，读到尚未写回的结果；③**有序性**，指代码书写顺序与内存操作实际生效的顺序是否一致，出于性能考虑，编译器与 CPU 都可能进行**指令重排 instruction reordering**，这在单线程中通常无害，多线程中却可能导致一个线程读到旧值、默认值，甚至看到未完全初始化的对象状态。

## 线程
### 创建线程
标准库用类 `std::thread`（C++ 11 引入）表示一个线程，它是底层线程的封装，定义在 `<thread>` 中。构造一个 `std::thread` 对象时，就立即启动一个新线程并在其中执行指定的**可调用对象 callable object**。线程创建后，其实际执行时机和与其它线程的相对顺序由实现和操作系统调度决定，C++ 标准不做保证，调用者不能假设它何时运行，也不能假设未同步操作的先后顺序。一个简单的示例如下：  

``` C++
void hello(const std::string& name) {
    std::cout << "来自子线程 " << name << " 的问候" << std::endl;
}

int main() {
    std::thread t(hello, "worker"); // 构造即启动：新线程开始执行 hello("worker")
    t.join(); // 等待子线程执行完毕
    std::cout << "主线程结束" << std::endl;
}
```

另外，`std::thread` 不能拷贝构造或拷贝赋值，但支持移动构造和移动赋值，因此可以放进容器中，也可以从函数中返回。

### join 与 detach
`std::thread` 对象与它管理的线程之间有两种收尾方式，必须选择一个，即必须 `join()` 或 `detach()`，否则 `std::thread` 对象在析构时仍然 `joinable()`，程序就会直接调用 `std::terminate` 终止。

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`join()`</font> | <font size=2>阻塞当前线程，直到目标线程执行完毕，随后该对象不再关联任何线程</font> |
| <font size=2>`detach()`</font> | <font size=2>使目标线程在后台独立运行，此后该对象不再与之关联，也无法再等待它</font> |
| <font size=2>`joinable()`</font> | <font size=2>判断该对象当前是否关联着一个尚未收尾的线程</font> |
| <font size=2>`get_id()`</font> | <font size=2>返回线程标识，可用于输出或比较；未关联线程时返回默认构造的 id</font> |

有一点要注意，分离出去的线程若访问了已经销毁的对象（例如局部变量或 `main` 结束时被回收的资源），就会造成未定义行为，因此使用 `detach()` 时要小心，通常只在确定线程所依赖的资源在整个程序期间都存活时才使用。

``` C++
std::thread t(work);
if (t.joinable()) t.join();   // 收尾前先判断，避免对已收尾的对象重复调用
// t.detach();                // 与 join 二选一：让线程在后台独立运行
```

### 线程传参
`std::thread` 的构造函数会把后续参数按值拷贝/移动到线程内部的存储中，再以右值的形式传给可调用对象。若希望传递引用，必须用 `std::ref` / `std::cref` 显式包装，例如：  

``` C++
void work(int id, std::string name, std::vector<int>& out) {
    out.push_back(id);
}

std::vector<int> results;
std::thread t(work, 1, "worker", std::ref(results)); // 引用需用 std::ref 包装
t.join();
std::cout << results.size() << std::endl; // 输出 1
```

因为参数是先拷贝再传入，所以即使传入的是局部变量的引用，只要该变量在线程执行期间仍然存活就是安全的。反之，若它先被销毁，线程中访问的就是悬空引用。

### this_thread
在命名空间 `std::this_thread` 中的函数可以用于操作<u>当前正在执行</u>的这个线程，与具体的 `std::thread` 对象无关，常见的有：  

| <font size=2>函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`get_id()`</font> | <font size=2>返回当前线程的标识，可用于输出或比较</font> |
| <font size=2>`yield()`</font> | <font size=2>让出当前线程剩余的时间片，给其它线程运行的机会（仅作提示，不保证）</font> |
| <font size=2>`sleep_for(duration)`</font> | <font size=2>睡眠一段时间</font> |
| <font size=2>`sleep_until(time_point)`</font> | <font size=2>睡眠到指定的时间点</font> |

``` C++
void worker(int id) {
    std::cout << "线程 " << id << " 的 id：" << std::this_thread::get_id() << std::endl;
    std::this_thread::yield(); // 让出当前线程剩余的时间片，给其它线程运行的机会（仅作提示，不保证）
    std::this_thread::sleep_for(std::chrono::milliseconds(100)); // 睡眠 100 毫秒
    std::this_thread::sleep_until(std::chrono::system_clock::now() + std::chrono::seconds(1)); // 睡到 1 秒之后
    std::cout << "线程 " << id << " 结束" << std::endl;
}

int main() {
    std::cout << "主线程的 id：" << std::this_thread::get_id() << std::endl;
    std::thread t(worker, 1); // 构造即启动新线程
    t.join(); // 等待子线程执行完毕
}
```

## jthread
【书签】

`std::thread` 需要手动 `join` / `detach`，稍有不慎就会 `std::terminate`。C++ 20 为此引入了 `std::jthread`，它在析构时会**自动请求停止并 join**，即使中途抛出异常也能正确收尾，同时内置了协作式停止机制（通过 `std::stop_token` 通知线程该停下了）。名字中的 j 取自 **joining**，即"会自行收尾的线程"。

### 自动收尾
`std::jthread` 定义在 `<thread>` 中，构造方式与 `std::thread` 完全一致，接口也高度相似，主要差别集中在收尾与停止这两点。`std::jthread` 的析构函数在对象销毁时会自动完成两件事：①若此前尚未请求停止，则先调用 `request_stop()` 发出停止请求；②若仍然 `joinable()`，则调用 `join()` 等待线程结束。因此它不会再像 `std::thread` 那样因忘记收尾而让程序 `std::terminate`，也无需再写 `if (t.joinable()) t.join();` 之类的样板代码。与 `std::thread` 一样，它不可拷贝构造或拷贝赋值，只支持移动。

`std::jthread` 的常用成员函数如下表所示：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`join()` / `detach()`</font> | <font size=2>与 `std::thread` 一致，手动等待线程结束 / 让线程在后台独立运行</font> |
| <font size=2>`joinable()` / `get_id()`</font> | <font size=2>与 `std::thread` 一致，判断是否仍关联线程 / 返回线程标识</font> |
| <font size=2>`request_stop()`</font> | <font size=2>请求停止：若此前尚未请求过则发出请求并返回 `true`，否则返回 `false`</font> |
| <font size=2>`get_stop_source()`</font> | <font size=2>取得关联的 `std::stop_source`，可据此发出停止请求</font> |
| <font size=2>`get_stop_token()`</font> | <font size=2>取得关联的 `std::stop_token`，用于查询停止状态</font> |

``` C++
std::jthread t(work); // 离开作用域时自动请求停止并等待线程结束，无需手动 join
```

> 虽然 `std::jthread` 会自动 `join`，但它也支持手动收尾：若在析构前显式调用了 `detach()`，析构时就不会再等待；若显式调用了 `join()`，析构时同样不会重复等待。注意它的析构函数可能在等待线程结束时阻塞，语义上与"必须等待这个线程结束"是一致的。

### 协作式停止
`std::jthread` 内置的停止机制是**协作式 cooperative** 的：`request_stop()` 只是发出一个"该停下了"的请求，并不会强行杀死线程，线程是否响应、何时响应，完全由线程自己决定。这既符合"线程无法被安全强杀"的事实，也给了线程清理资源、保存状态的机会。停止机制由三个配合使用的类型组成，它们定义在头文件 `<stop_token>` 中：  

| <font size=2>类型</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::stop_source`</font> | <font size=2>拥有停止状态，是停止请求的发起方，通过 `request_stop()` 发出请求</font> |
| <font size=2>`std::stop_token`</font> | <font size=2>停止状态的只读句柄，可拷贝、可传入线程，用于查询是否已被请求停止</font> |
| <font size=2>`std::stop_callback`</font> | <font size=2>绑定在某个 `stop_token` 上的回调，请求停止时自动被调用（若注册时已请求过则立即调用）</font> |

`std::jthread` 内部持有一个 `stop_source`，构造时会判断可调用对象能否接受一个 `std::stop_token` 作为第一个参数，若能，就把内部的 `stop_token` 自动传给它，线程便可通过它感知停止请求。`std::stop_token` 常用的成员函数如下：  

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`stop_requested()`</font> | <font size=2>判断是否已被请求停止</font> |
| <font size=2>`stop_possible()`</font> | <font size=2>判断是否还有可能收到停止请求，即是否仍有 `stop_source` 与之关联</font> |

最常见的用法是在循环条件中定期检查，例如：  

``` C++
void worker(std::stop_token stoken) { // 接受 stop_token，即可感知停止请求
    int i = 0;
    while (!stoken.stop_requested()) { // 每轮循环检查一次停止请求
        std::cout << "工作中 " << i++ << std::endl;
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }
    std::cout << "收到停止请求，正常退出" << std::endl;
    // 此处可安全地释放资源、保存状态等
}

int main() {
    std::jthread t(worker); // 自动把内部的 stop_token 作为第一个参数传给 worker
    std::this_thread::sleep_for(std::chrono::milliseconds(350));
    t.request_stop(); // 发出停止请求；worker 是否停下由它自己决定
    // 离开作用域时，t 的析构函数会再次请求停止（此时是空操作）并 join
}
```

若可调用对象并不接受 `stop_token`，`std::jthread` 依然可以正常构造与自动收尾，只是线程无法感知停止请求，`request_stop()` 也就没有实际作用：  

``` C++
void plain() { /* 不接受 stop_token，仍可正常使用，只是无法响应停止请求 */ }
std::jthread t(plain); // 可以正常构造，析构时自动 join
```

### stop_callback
`std::stop_callback` 允许在停止请求发出时自动执行一段代码，常用于通知某个阻塞中的操作提前结束：  

``` C++
std::jthread t(worker);
std::stop_callback cb(t.get_stop_token(), [] {
    std::cout << "停止请求已发出" << std::endl; // 请求停止时回调被触发
});
t.request_stop(); // 触发上面的回调，随后 worker 也会看到停止请求
```

### 与条件变量配合
普通的 `std::condition_variable` 一旦挂起等待，就只会因被通知而醒来。若一直没人通知，即使发出了停止请求，等待中的线程也无法响应，`join()` 便只能无限期地等下去。为此 `<condition_variable>` 中的 `std::condition_variable_any` 提供了带 `stop_token` 的重载，它在收到停止请求时也会唤醒等待者：  

``` C++
std::mutex mtx;
std::condition_variable_any cv; // 注意用 _any 版本，才能与 stop_token 配合
std::queue<int> q;

void consumer(std::stop_token stoken) {
    while (!stoken.stop_requested()) {
        std::unique_lock<std::mutex> lock(mtx);
        // 被通知、队列非空、或因停止请求而结束；返回 false 表示是停止请求导致本次唤醒
        if (!cv.wait(lock, stoken, [] { return !q.empty(); })) break;
        int v = q.front();
        q.pop();
        lock.unlock();
        std::cout << "取出 " << v << std::endl;
    }
}
```

这里 `wait(lock, stoken, pred)` 返回 `false`，说明这次唤醒并非谓词成立，而是外部请求了停止，于是循环随即退出，线程得以顺利收尾。

> `std::jthread` 可以理解为 `std::thread` 的改进版：默认自动收尾、内置协作式停止，因此新代码中若没有特殊理由，应优先使用它。但停止是协作式的，它并不能"强行终止"一个不理会停止请求的线程；若线程阻塞在一个无法被中断的操作上，`join()` 仍可能一直等下去。

## 数据竞争与临界区
【避免数据竞争，引出 thread_local、互斥量、条件变量、原子类型】

多条线程共享同一份数据时，如果至少有一条线程在写，且没有做任何同步，就会产生**数据竞争 data race**，其后果属于未定义行为。最典型的例子是一个计数器：`++counter` 看似是一条语句，实际上由读取、加一、写回三步组成，两个线程交错执行时，一方的写回可能覆盖另一方的结果，导致最终值小于预期。

``` C++
int counter = 0; // 共享数据，没有做任何保护

void add() {
    for (int i = 0; i < 100000; ++i) ++counter;
}

int main() {
    std::thread a(add), b(add);
    a.join(); b.join();
    std::cout << counter << std::endl; // 通常小于 200000（具体结果依运行情况而定）
}
```

一块只能被串行访问、不允许并发读写共享数据的代码区域称为**临界区 critical section**。要避免数据竞争，基本思路就是让所有对共享数据的访问都在临界区内串行进行，通常借助**互斥量**或**原子类型**来实现。此外还要注意，编译器和 CPU 都可能对指令重排、把变量缓存在寄存器或缓存中，因此**同步不仅要保证互斥，还要保证可见性**，即一个线程的写入能被其它线程及时看到，这正是后面提到的内存序要处理的问题。

## 互斥量
### mutex
`std::mutex` 是最基本的**互斥量 mutex**（mutual exclusion），它只有两种状态：加锁、解锁。同一时刻只允许一个线程持有它，其它线程若试图加锁就会被阻塞，直到锁被释放。互斥量的成员函数如下：

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`lock()`</font> | <font size=2>加锁，若已被占用则阻塞等待，直到成功</font> |
| <font size=2>`try_lock()`</font> | <font size=2>尝试加锁，成功返回 `true`，已被占用则立即返回 `false`（不阻塞）</font> |
| <font size=2>`unlock()`</font> | <font size=2>解锁，必须由持有该锁的线程调用</font> |

``` C++
std::mutex mtx;
int counter = 0;

void add() {
    for (int i = 0; i < 100000; ++i) {
        mtx.lock();      // 进入临界区
        ++counter;
        mtx.unlock();    // 离开临界区
    }
}
```

> 直接手写 `lock` / `unlock` 很危险：若中途抛出异常或提前返回，`unlock` 就可能被跳过，锁永远不释放，其它线程将一直阻塞。因此实际代码中<u>几乎不应该直接调用它们</u>，而应交给下面介绍的 RAII 包装类自动管理。

### lock_guard 与 unique_lock
标准库提供了几个 RAII 风格的锁管理类，构造时加锁、析构时自动解锁，即使发生异常也能保证锁被释放。

| <font size=2>类</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::lock_guard`</font> | <font size=2>最轻量的 RAII 锁，构造即加锁、析构即解锁，期间不能手动解锁，也不能转移所有权</font> |
| <font size=2>`std::unique_lock`</font> | <font size=2>更灵活的 RAII 锁，可以延迟加锁、手动加解锁、设置超时、转移所有权；开销略大于 `lock_guard`</font> |
| <font size=2>`std::scoped_lock`</font> | <font size=2>C++ 17 引入，可同时锁定一个或多个互斥量，内部按避免死锁的策略进行加锁</font> |
| <font size=2>`std::shared_lock`</font> | <font size=2>C++ 14 引入，用于读写锁中的共享（读）模式加锁</font> |

``` C++
std::mutex mtx;
int counter = 0;

void add() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(mtx); // 构造时加锁，析构时自动解锁
        ++counter;
    } // 每次循环结束时自动解锁，临界区尽量短
}
```

> 通过给 `std::unique_lock` / `std::lock_guard` 传入 `std::adopt_lock` 可以接管一个已经加过的锁；传入 `std::defer_lock` 则只是关联互斥量而不立即加锁。

### 其它互斥量
除了最基本的 `std::mutex`，标准库还按不同需求提供了几种变体：

| <font size=2>类型</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`std::recursive_mutex`</font> | <font size=2>可重入互斥量，同一线程可以重复加锁多次，需解锁同样次数才真正释放</font> |
| <font size=2>`std::timed_mutex`</font> | <font size=2>支持超时加锁，提供 `try_lock_for` / `try_lock_until`</font> |
| <font size=2>`std::recursive_timed_mutex`</font> | <font size=2>上面两者的结合：可重入且支持超时</font> |
| <font size=2>`std::shared_mutex`</font> | <font size=2>C++ 17 引入的读写锁，允许多个读者同时持有，写者则独占</font> |
| <font size=2>`std::shared_timed_mutex`</font> | <font size=2>C++ 14 引入的读写锁，额外支持超时加锁</font> |

**读写锁 read-write lock** 适用读多写少的场景：只读取数据的线程用共享模式加锁（互相不排斥），只有真正要修改时才用独占模式加锁。

``` C++
std::shared_mutex rw; // 读写锁
int value = 0;

void reader() {
    std::shared_lock<std::shared_mutex> lock(rw); // 共享模式：多个读者可同时持有
    std::cout << value << std::endl;
}

void writer() {
    std::unique_lock<std::shared_mutex> lock(rw); // 独占模式：与其它任何持有者互斥
    ++value;
}
```

## 死锁
**死锁 deadlock** 指两个或多个线程各自持有对方所需的锁，又都在等待对方释放，结果谁也无法继续，程序就此永久挂起。最简单的情形如下：

``` C++
std::mutex m1, m2;

void f1() {
    std::lock_guard<std::mutex> a(m1);
    std::lock_guard<std::mutex> b(m2); // 等待 m2
}

void f2() {
    std::lock_guard<std::mutex> a(m2);
    std::lock_guard<std::mutex> b(m1); // 与 f1 的加锁顺序相反，可能形成环路等待
}
```

避免死锁的常用策略有：  
1. **统一加锁顺序**：所有线程都按相同的全局顺序获取多个锁，从根源上消除环路等待；  
2. **一次性锁定全部**：用 `std::scoped_lock`（或 C++ 17 之前的 `std::lock` + `adopt_lock`）同时锁定多个互斥量，标准库内部会用避免死锁的算法来加锁；  
3. **缩短临界区**：尽量不在持有锁时调用可能阻塞或耗时很久的操作（如 I/O、等待另一个线程），也不要在持锁时回调用户代码；  
4. **使用超时加锁**：改用 `timed_mutex` 的 `try_lock_for`，超时后放弃并回退重试，避免无限等待。

``` C++
void f1() {
    std::scoped_lock lock(m1, m2); // 一次性锁定多个，避免加锁顺序不一致导致的死锁
    // ...
}

void f2() {
    std::scoped_lock lock(m2, m1); // 顺序不同也没关系，内部会处理
    // ...
}
```

## 条件变量
互斥量只解决了"同一时刻只有一个线程访问"的问题，但很多场景还需要线程之间**相互等待并通知**，例如消费者线程要等队列里有数据了再取，生产者线程要等队列有空位了再放。这类等待不能靠反复加解锁轮询（既浪费 CPU，又难以保证及时性），标准库为此提供了**条件变量 condition variable**，配合互斥量组成经典的"等待-唤醒"模型。

`std::condition_variable` 需要与 `std::unique_lock<std::mutex>` 配合使用（因为等待期间需要暂时释放锁），其常用成员如下：

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`wait(lock)`</font> | <font size=2>释放 `lock` 并阻塞，直到被唤醒；唤醒后会重新加锁再返回</font> |
| <font size=2>`wait(lock, pred)`</font> | <font size=2>带谓词的版本，等价于 `while (!pred()) wait(lock);`，可有效应对虚假唤醒</font> |
| <font size=2>`wait_for` / `wait_until`</font> | <font size=2>带超时的等待，超时或被唤醒都会返回</font> |
| <font size=2>`notify_one()`</font> | <font size=2>唤醒一个正在等待的线程</font> |
| <font size=2>`notify_all()`</font> | <font size=2>唤醒所有正在等待的线程</font> |

**虚假唤醒 spurious wakeup** 指等待的线程在没有任何人调用 `notify` 的情况下也可能自行醒来，这是底层实现允许的行为，因此唤醒后必须重新检查条件是否真的成立，这正是带谓词的 `wait` 所做的事。

``` C++
std::mutex mtx;
std::condition_variable cv;
std::queue<int> q; // 共享队列，由 mtx 保护

void producer() {
    for (int i = 0; i < 5; ++i) {
        {
            std::lock_guard<std::mutex> lock(mtx); // 临界区尽量短，先放数据再通知
            q.push(i);
        }
        cv.notify_one(); // 通知一个等待中的消费者
    }
}

void consumer() {
    for (int i = 0; i < 5; ++i) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, [] { return !q.empty(); }); // 条件不满足则释放锁并休眠，且自动处理虚假唤醒
        int v = q.front();
        q.pop();
        lock.unlock();                // 先解锁，再做与共享数据无关的处理
        std::cout << "取出 " << v << std::endl;
    }
}

int main() {
    std::thread p(producer), c(consumer);
    p.join();
    c.join();
}
```

> 使用条件变量时要留意：通知方应尽量在临界区内修改完共享状态、离开临界区后再通知；等待方必须用循环或带谓词的 `wait` 复查条件；`std::condition_variable` 只能与 `std::unique_lock<std::mutex>` 搭配，若需要与其它类型的锁搭配，可使用 `std::condition_variable_any`。

## 原子类型
### atomic
比起用互斥量锁住整段临界区，若共享数据只是一个简单的变量，有时只需保证单个读写操作本身不可分割即可，这时就可以使用**原子类型 atomic type**。头文件 `<atomic>` 提供了模板 `std::atomic<T>`，对它的操作要么完整执行，要么完全没发生，不会被其它线程观察到中间状态，因此**不需要加锁**就能避免数据竞争。对于常见的整型、指针、布尔等类型，标准库还能利用硬件指令实现无锁操作。

``` C++
std::atomic<int> counter{0}; // 原子计数器，无需互斥量

void add() {
    for (int i = 0; i < 100000; ++i) ++counter; // 自增本身是原子的
}

int main() {
    std::thread a(add), b(add);
    a.join(); b.join();
    std::cout << counter.load() << std::endl; // 输出 200000
}
```

常用的原子操作如下表：

| <font size=2>成员函数</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`load()`</font> | <font size=2>原子地读取当前值</font> |
| <font size=2>`store(v)`</font> | <font size=2>原子地写入新值</font> |
| <font size=2>`exchange(v)`</font> | <font size=2>原子地写入新值并返回旧值</font> |
| <font size=2>`fetch_add(n)` / `fetch_sub(n)`</font> | <font size=2>原子地加减，返回运算前的旧值</font> |
| <font size=2>`compare_exchange_weak/strong(expected, desired)`</font> | <font size=2>比较并交换：当前值等于 `expected` 时写入 `desired` 并返回 `true`，否则把当前值写回 `expected` 并返回 `false`</font> |

> 简写运算符（`++`、`+=` 等）与对应的 `fetch_*` 等价，只是不返回旧值。`std::atomic_flag` 是最简单的原子类型，保证无锁，常用作自旋锁的基石。注意原子类型只保证<u>单个操作</u>的原子性，若要把多个操作合并成互斥的整体（如"读-改-写"复杂逻辑），仍需要互斥量。

### 内存序
原子操作还有一个**内存序 memory order** 参数，用于指定本次操作周围的指令重排与可见性约束。默认使用最严格的 `std::memory_order_seq_cst`，即所有线程看到的所有原子操作存在一个全局一致的顺序，最容易推理也最不易出错，代价是性能开销最大。只有在深入理解内存模型、并经过性能分析确认瓶颈之后，才应考虑放宽内存序。

| <font size=2>内存序</font> | <font size=2>说明</font> |
| :---- | :---- |
| <font size=2>`memory_order_relaxed`</font> | <font size=2>只保证本操作原子，不提供任何跨线程顺序保证</font> |
| <font size=2>`memory_order_acquire`</font> | <font size=2>读取操作：本操作之后的内存访问不得排到它之前（获取语义）</font> |
| <font size=2>`memory_order_release`</font> | <font size=2>写入操作：本操作之前的内存访问不得排到它之后（释放语义）</font> |
| <font size=2>`memory_order_acq_rel`</font> | <font size=2>兼具获取与释放语义，用于读-改-写操作</font> |
| <font size=2>`memory_order_seq_cst`</font> | <font size=2>顺序一致（默认），最严格，全局单一定序</font> |

## 异步任务与 future
### async
直接使用 `std::thread` 时，要手动把返回值传出来、手动处理异常、手动收尾，比较繁琐。标准库在 `<future>` 中提供了更高层的抽象：**异步任务 asynchronous task**。`std::async` 会启动一个任务（可能在新线程中执行，也可能延迟到取值时执行），并立即返回一个 `std::future` 对象；`future` 表示一个**尚未就绪的结果**，可以先用它继续做其它事情，需要结果时再调用 `get()` 取值。

``` C++
#include <future>

int compute() {
    // 假设这里是一段耗时的计算
    return 42;
}

int main() {
    std::future<int> f = std::async(compute); // 启动异步任务，立即返回 future
    // ... 在这里做其它不依赖结果的工作
    int v = f.get(); // 阻塞直到结果就绪，并取回它（只能取一次）
    std::cout << v << std::endl; // 输出 42
}
```

> `std::async` 的启动策略参数可选 `std::launch::async`（强制在新线程中执行）或 `std::launch::deferred`（延迟到调用 `get()` / `wait()` 时才在当前线程执行）；不指定时由实现自行选择，可能既不并发也不延迟。若确实需要并发，建议显式指定 `std::launch::async`。`f.get()` 只能调用一次，之后 `future` 变为无效；另外 `future` 的析构函数可能阻塞等待任务完成，若不想等待，需要显式接收其结果。

### promise 与 packaged_task
`std::async` 把"启动任务"与"获取结果"打包在一起，而若需要更精细地控制结果何时产生，可以分别使用 `std::promise` 与 `std::packaged_task`：前者是一个可写入结果的通道，后者把一个可调用对象包装成可以异步执行的"任务"，两者都能通过 `get_future()` 取得配套的 `future`。

``` C++
// promise：在某个线程中显式设置结果
std::promise<int> p;
std::future<int> f = p.get_future();
std::thread t([&p] { p.set_value(42); }); // 结果可以由任意线程设置
std::cout << f.get() << std::endl;        // 输出 42
t.join();

// packaged_task：把可调用对象包装成任务，交给线程或线程池执行
std::packaged_task<int(int)> task([](int x) { return x * 2; });
std::future<int> f2 = task.get_future();
std::thread t2(std::move(task), 21);
std::cout << f2.get() << std::endl; // 输出 42
t2.join();
```

### shared_future
`std::future` 不可拷贝，因此一个结果默认只能被一个线程取走。若需要让多个线程都能读取同一个结果，可以用 `share()` 把它转成可拷贝的 `std::shared_future`，多个线程各自持有一份副本，都能调用 `get()` 取到相同的值。

``` C++
std::shared_future<int> sf = std::async(compute).share(); // 可拷贝，可被多个线程共享
// std::thread t1([sf] { std::cout << sf.get() << std::endl; });
// std::thread t2([sf] { std::cout << sf.get() << std::endl; });
```

> 异常也可以经由 `future` 传递：若异步任务内部抛出异常，异常会被保存起来，直到调用 `get()` 时在调用线程中重新抛出，这是 `future` 相比裸线程的一个明显优势。

## 其它并发设施
### thread_local
**线程局部存储 thread local storage** 用关键字 `thread_local` 声明，表示该变量在<u>每个线程中各有一份独立实例</u>，线程首次使用时初始化，线程结束时销毁。它可以把原本需要共享的数据变成"每个线程各自一份"，从而避免加锁。

``` C++
thread_local int counter = 0; // 每个线程都有自己独立的 counter

void add() {
    for (int i = 0; i < 5; ++i) ++counter; // 无需同步，各线程互不影响
    std::cout << counter << std::endl;     // 每个线程都输出 5
}
```

### call_once
若某段初始化代码在多线程下只能执行一次（如只加载一次配置、只建立一次连接），可以使用 `std::once_flag` 与 `std::call_once`，它保证即使多个线程同时调用，也只会有一个线程真正执行该函数，其余线程会等待其完成。

``` C++
std::once_flag flag;

void init() { std::cout << "只执行一次" << std::endl; }

void worker() {
    std::call_once(flag, init); // 多线程同时调用也只会执行一次
    // ... 后续工作
}
```

### 信号量、闩锁与屏障
C++ 20 新增了三种更轻量的线程协调设施，它们都不需要互斥量配合，使用起来比条件变量更直观：

| <font size=2>类型</font> | <font size=2>头文件</font> | <font size=2>说明</font> |
| :---- | :---- | :---- |
| <font size=2>`std::counting_semaphore` / `binary_semaphore`</font> | <font size=2>`<semaphore>`</font> | <font size=2>信号量，内部维护一个计数器，`acquire` 使其减一（为 0 时阻塞），`release` 使其加一，可用于限制并发数量或实现资源池</font> |
| <font size=2>`std::latch`</font> | <font size=2>`<latch>`</font> | <font size=2>一次性闩锁，计数减到 0 后所有等待者同时放行，且不能重置，适合"等所有线程都到达某点再一起开始"</font> |
| <font size=2>`std::barrier`</font> | <font size=2>`<barrier>`</font> | <font size=2>可循环使用的屏障，每轮等到所有参与者都到达后放行并重置计数，适合分阶段迭代计算</font> |

### 并行算法
C++ 17 起，`<algorithm>` 中的许多经典算法增加了接受**执行策略 execution policy** 的重载，可以把原本串行执行的算法改为并行执行，例如 `std::execution::seq`（串行）、`par`（并行）、`par_unseq`（并行且可向量化）、`unseq`（仅向量化）。

``` C++
#include <algorithm>
#include <execution>
#include <vector>

std::vector<int> v(1000000);
std::sort(std::execution::par, v.begin(), v.end()); // 请求并行排序
```

> 并行算法的实际并行化需要标准库后端的支持（如 Intel TBB），若编译器未提供相应后端，策略可能被静默忽略而退化为串行。另外，传入的用户函数必须是**线程安全**的，不能有数据竞争。

## 并发编程的注意事项
最后把本章的要点集中梳理一遍，作为初学者的实践清单：  
1. **能用更高层抽象就不用裸线程**：优先考虑 `std::async` / `std::future`、并行算法，只有当确实需要精细控制线程生命周期、线程池或长期驻留的工作线程时，才直接使用 `std::thread`；  
2. **共享数据必须同步**：只要存在"至少一个线程写"的共享数据，就必须用互斥量或原子类型保护，单靠"看起来没问题"的设计是靠不住的；  
3. **锁交给 RAII 管理**：始终使用 `lock_guard` / `unique_lock` / `scoped_lock`，不要手写 `lock` / `unlock`；临界区尽量短，不要在持锁时做 I/O、等待另一个线程或回调用户代码；  
4. **统一加锁顺序**：需要多个锁时尽量用 `std::scoped_lock` 一次性锁定，从设计上避免环路等待；  
5. **等待条件用谓词**：条件变量的等待一律使用带谓词的 `wait`，以正确处理虚假唤醒；  
6. **优先使用默认内存序**：原子操作默认的 `seq_cst` 最易推理，放宽内存序属于高级优化，需谨慎且有实测依据；  
7. **注意传递引用与生命周期**：线程参数默认拷贝，需要引用要用 `std::ref`；同时确保线程访问的所有对象在其执行期间都保持存活，`detach()` 尤其要小心；  
8. **利用工具排查问题**：数据竞争往往偶发且难以复现，可以借助 **ThreadSanitizer (TSan)** 等工具检测，也可以用调试器观察线程状态来排查死锁；  
9. **性能不是想当然的**：线程创建、上下文切换、锁竞争、伪共享（**伪共享 false sharing**，指不同线程修改同一缓存行上的不同变量，导致缓存行反复失效）都有开销，线程数量与划分方式应当以实测为准。
